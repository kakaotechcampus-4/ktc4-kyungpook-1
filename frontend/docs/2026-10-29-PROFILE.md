# 인적사항 — 학력·경력·어학·자격증 (계약은 BE #552 를 따른다)

계약(경로·칸·열거값·개수·길이·오류)은 백엔드 PR #552 「인적사항 (#516, 구현됨)」이 정했고, 화면은 그대로 따른다. **이 문서는 계약을 다시 적지 않는다** — 같은 계약이 두 곳에 있으면 어긋나기 때문이다. 계약 전문은 #552 가 머지되면 [BACKEND_CONTRACT.md](BACKEND_CONTRACT.md) 의 「인적사항 (#516, 구현됨)」 절에 있고, 이 문서는 **화면 규칙·문구·결정과 BE 에 요청할 것**만 적는다.

- 이 PR 의 처음 FE 제안(`education`·`career`·`certificates`·`updatedAt`, 학력 상태 `LEAVE`·`DROPOUT`·`COMPLETED`, 어학 시험 이름 자유 글, 400 의 칸별 `path`·`code` …)은 #552 와 칸이 많이 달랐다. 매칭 1차 필터(#532)가 '학사 이상'·고용 형태를 보려면 칸은 BE 쪽이 맞다는 리뷰에 따라 **칸은 모두 BE 를 따르도록 바꿨다.** 그때 `BACKEND_CONTRACT.md` 에 넣었던 제안 절도 이 PR 에서 되돌렸다(BE 가 같은 파일에 「구현됨」 절을 넣으므로 이중 계약이 된다).
- #552 는 아직 머지 전이라 계약이 바뀔 수 있다. FE 는 `src/api/profile.ts` 한 곳만 맞추면 화면과 Mock 이 같이 따라간다.
- 실서버 모드에서는 `VITE_PROFILE_ENABLED=true` 가 되기 전까지 어떤 요청도 보내지 않는다(아래 "켜는 시점").

## 왜, 무엇을

- 팀 결정: 사용자가 학력·경력·어학·자격증을 등록한다. "처음 사이트 들어올 때 입력하게 하고 마이페이지에서 수정한다."
- 쓰임(#552): 공고 매칭 **1차 필터**(#532, 학력·경력 같은 값으로 거르기)와 **자소서 AI**(#484)가 서버에서 이 값을 읽는다(연결은 BE 의 다음 PR).
- 경험 카드(STAR) 문장은 이 정보로 만들지 않는다. 확정 카드만 근거라는 제품 원칙이다.
- **`/api/activities` 와 다른 것이다.** 합치지 않았고 건드리지 않았다.

| | 인적사항 (이 문서) | 활동 `/api/activities` ([경험 카드 계약](2026-10-28-EXPERIENCE_CARDS.md)) |
|---|---|---|
| 무엇 | 학교·회사·어학 시험·자격증 같은 **사실 기록** | 동아리·대외활동·인턴 같은 **레포 밖 경험**을 묶는 상자 |
| 단위 | 사용자당 문서 하나, 네 목록을 통째로 교체 | 여러 개, 각각 만들고 고치고 지움 |
| 카드와 | 연결 없음 | 안에 경험 카드(`QUALITATIVE`)가 쌓임 |
| 쓰임 | 매칭 1차 거르기, 자소서 AI 참고 | 카드 묶음·자소서 카드 고르기 |

## 화면

| 어디 | 무엇 |
|---|---|
| `/settings/profile` | 학력·경력·어학·자격증 네 영역. 줄 추가·삭제, 월 입력, [저장] 한 번에 네 목록을 통째로 보낸다. 고친 채로 나가면 확인 창 |
| 마이페이지 | "인적사항" 줄(저장한 개수 요약, 저장한 적 없음과 건너뜀을 구분) → 위 화면. 저장·보관 정보 목록에도 한 줄(쓰임: 공고 매칭의 지원 자격 비교, 자소서 AI 참고) |
| 홈 | 한 번도 저장하지 않았을 때(`savedAt` 이 null)만 안내 카드(입력하기 · 건너뛰기). 마법사로 강제하지 않고, 불러오지 못하면 아무것도 그리지 않는다 |

### 처음 들어올 때와 건너뛰기 (#531)

- **`savedAt === null`** 이면 홈에 입력 안내가 뜬다. [입력하기]는 입력 화면(비어 있음)으로 간다. **`savedAt` 이 있으면** 안내는 없고, 입력 화면은 저장된 값을 채워서 보여 준다. 로그인 직후 화면 전체를 가로채는 방식은 쓰지 않았다 — 주 흐름을 막지 않기 위해서다. 사용자가 모르고 지나쳐도 마이페이지 줄에서 들어올 수 있다.
- **[건너뛰기] = 빈 목록 네 개를 `PUT`** 한다. 그러면 `savedAt` 이 생겨 다른 브라우저·기기에서도 안내가 다시 뜨지 않는다. 브라우저에는 아무 표시도 남기지 않는다(이전 제안의 `localStorage` "나중에"는 없앴다). 저장에 실패하면 안내가 그대로 남고 다시 누를 수 있다.
- 건너뛰기 직전에 `GET` 으로 한 번 더 본다. `PUT` 이 네 목록을 통째로 바꾸므로, 그 사이 다른 탭에서 저장했다면 빈 목록으로 지우게 되기 때문이다. 이미 저장돼 있으면 `PUT` 하지 않고 그 값을 그대로 둔다.
- 입력 화면에서 모두 지우고 저장해도 같은 빈 네 목록이 저장된다(저장 전에 "저장하면 입력한 정보가 삭제돼요"를 보인다).

### 입력 화면 규칙

- 영역마다 줄을 더하고 지운다. 개수 상한(학력 5·경력 10·어학 10·자격증 20)에 닿으면 [추가]를 막고 이유를 적는다.
- 줄을 만들었으면 필수 칸을 채워야 저장된다. 필수가 아닌 칸은 이름 뒤에 "(선택)"을 붙여 비워도 된다고 보인다. 영역 전체를 비워 두는 것(줄을 만들지 않음)은 언제나 괜찮다.
- 오류는 [저장]을 한 번 눌러 본 뒤에야 칸 옆에 보이고(쓰는 도중에 먼저 빨갛게 되지 않게), 고치는 즉시 사라진다. 첫 오류 칸으로 초점을 보낸다.
- 칸 이름은 눈에 보이는 이름에서 만든다(`학력 1 학교`, `학력 1 전공 (선택)`). 눈에 보이는 이름이 접근 가능한 이름에 그대로 들어 있어야 음성 조작이 된다(WCAG 2.5.3).
- 자동 저장을 쓰지 않는다. 줄이 덜 채워진 문서는 서버가 받지 않아 중간 저장이 성립하지 않고, 개인정보를 입력이 멈출 때마다 보내지 않기 위해서다.
- 저장에 실패해도 입력은 그대로 두고 [다시 저장]을 보인다. 네 목록은 **항상 모두** 보낸다(하나라도 빠지면 400).

## 검증 — 서버와 같게, 사용자가 칸별로 고치게

서버의 400 은 `INVALID_REQUEST` 와 한국어 문장 하나뿐이라, 사용자가 어디를 고칠지 알려 주지 못한다. 그래서 화면이 **같은 규칙으로 먼저 검사해** 칸마다 안내한다(`api/profile.ts` 의 `ProfileInput`, Mock 도 같은 것을 쓴다).

- **BE 와 같은 것**: 목록 개수, 글 앞뒤 공백 제거 뒤 50자(점수 20자), 빈 글은 비어 있는 것, U+0000 거부, 열거값, 달은 `YYYY-MM`, 끝난 달이 시작한 달보다 앞서면 안 됨(같은 달은 허용), 학점은 만점과 함께 또는 둘 다 비움, 만점은 4개 중 하나, 시험 이름은 '기타'일 때만 필수.
- **FE 가 더한 것 둘** (BE 확인 요청 5·3번):
  - **경력 퇴사 월**: '재직 중'을 체크하거나 퇴사 월을 적어야 저장된다. 계약에서 `endMonth: null` 이 재직 중이라, 비운 칸을 그대로 보내면 **일을 그만둔 사람이 재직 중으로 저장**되기 때문이다.
  - **학점은 0 이상 만점 이하**: 계약의 "학점·만점이 맞지 않음"을 그렇게 읽었다.
- **FE 가 막지 않는 것**: 달의 범위. 처음 제안은 1950년 이전, 미래의 시작·취득 월, 졸업 예정 10년 초과, 끝난 상태의 종료 월 없음을 막았는데, BE 는 형식만 본다. FE 가 더 엄하면 BE 가 받는 값을 FE 가 막게 되고 규칙이 둘이 되므로 뺐다. 달 입력칸에도 `min`·`max` 를 두지 않는다. 2204-03 도 저장되는 문제는 BE 에 요청한다(요청 4번).

## 오류 처리 — 서버 문구는 보이지 않는다

- 서버 400 `INVALID_REQUEST` 의 `error.message`(예: "학력 1번째 학교 이름…")는 **화면에 보이지 않는다**(서버 문구 비노출 원칙). 입력은 그대로 두고 일반 안내("서버가 입력을 받지 못했어요 / 입력한 내용을 다시 확인한 뒤 저장해 주세요")와 [다시 저장]을 보인다. 개인정보가 섞일 수 있는 문장을 화면·로그에 옮기지 않기 위해서이기도 하다.
- **BE 가 `error.details.fields` 에 칸별 `{ path, code }` 를 주면** 그 칸 옆에 오류를 붙인다. 관대한 파서(`serverIssues`)가 모양이 맞는 항목만 읽는다. `details.errors` 도 같은 모양이면 읽고, 모양이 다른 항목·모르는 `code`(→ "목록에서 골라 주세요")·화면에 없는 목록·줄·칸을 가리키는 항목은 버리며, 없으면 무시한다. 이때도 `error.message` 는 읽지 않는다. 화면이 알아듣는 `code` 는 `REQUIRED · TOO_LONG · INVALID_FORMAT · INVALID_VALUE · INVALID_CHARACTER · OUT_OF_RANGE · END_BEFORE_START · TOO_MANY` 이고, `path` 는 `educations[0].school` 처럼 BE 목록 이름을 쓴다. **지금은 BE 가 주지 않으므로 이 경로는 단위 시험에서만 쓰인다.** 이것이 BE 에 요청하는 것이다(요청 1번).
- 401 은 로그인 화면으로, 5xx·연결 실패는 입력을 그대로 둔 채 [다시 저장]을 보인다.

## 개인정보 원칙 (이 기능의 전제)

학교·회사·점수는 개인정보다. 아래는 FE 가 지키고 시험으로 막아 둔 것이고, **BE 도 같이 지켜 주길 요청하는 것**이다.

1. **지표 이벤트에 값을 싣지 않는다.** `track()` 이벤트(`profile_prompt_accepted` · `profile_prompt_dismissed`(건너뛰기) · `profile_saved`)는 이름과 개수(`educationCount` …)만 보낸다. 문자열 값은 하나도 없다.
2. **로그에 남기지 않는다.** FE 는 인적사항을 `console` 에 쓰지 않는다. 서버도 `PUT /profile` 의 요청·응답 본문을 접근 로그·오류 로그·APM 에 남기지 않기를 요청한다(남긴다면 필드 마스킹).
3. **URL·쿼리스트링에 넣지 않는다.** 두 API 모두 쿼리가 없고, 화면 주소도 값을 담지 않는다. DOM id 도 값에서 만들지 않는다.
4. **AI 로 보낼 때는 가려서 싣고 사용자에게 알린다.** 카드 문장은 이 정보로 만들지 않지만, **자소서 AI(#484)는 이 값을 읽는다**(#552). 그래서 BE 에 요청한다: (a) AI 로 보내는 칸을 자소서 문항에 필요한 만큼으로 줄이기, (b) 모델 입력에 올릴 때 가리는 규칙(학교·회사 이름 등)과 프롬프트·로그에 값을 남기지 않기, (c) 사용자에게 알리는 문구 확정.
   - 이 문서의 이전 판은 "이 정보로 자소서 문장을 지어내지 않는다"고 썼는데, #552 가 자소서 AI 가 읽게 열어 둔다고 해서 어긋나 고쳤다. 화면도 "공고 매칭 비교에만"으로 읽히지 않게 했다.
   - **지금 화면이 말하는 것**: "공고 매칭에서 지원 자격 조건을 비교할 때 써요. 자소서를 AI 로 쓸 때도 이 정보를 읽을 수 있어요. 경험 카드 문장은 이 정보로 만들지 않아요." 마이페이지 저장·보관 정보에도 같은 두 쓰임을 적었다.
   - **아직 말하지 않는 것**: "가려서 전달해요". 가리는 규칙은 BE 가 정하고 구현해야 하는데 #552 에 없다. 하지 않은 약속을 화면에 쓰지 않는다. BE 가 가리는 규칙을 구현·확인하면 그 문구를 더한다.
   - **켜기 전 조건**: `VITE_PROFILE_ENABLED=true` 를 켜기 전에 (c)의 고지 문구가 화면에 반영돼야 한다.
5. **브라우저에 오래 남기지 않는다.** 값은 메모리(React Query 캐시)에만 있고, 인적사항 코드는 `localStorage` 를 쓰지 않는다(건너뛰기도 서버가 기억한다). 로그아웃하면 캐시를 모두 비운다. 데모 모드에서는 이 탭의 `sessionStorage` 에만 저장되고 서버로 가지 않는다.
6. **자동완성에 넣지 않는다.** 입력칸은 `autocomplete="off"` 다.

## BE 에 요청·확인할 것

계약이 #552 에서 이미 정해진 것은 따르고, 아래만 요청·확인한다. 번호는 중요한 순서에 가깝다.

1. **400 에 칸별 `{ path, code }`** — 지금은 한국어 문장 하나뿐이라 화면이 칸별로 짚으려면 클라이언트가 먼저 검사해야 한다(서버와 규칙이 갈라질 위험). `error.details.fields: [{ "path": "educations[0].school", "code": "REQUIRED" }]` 를 더해 주길 요청한다. `code` 는 위 8개 어휘를 제안한다. **받은 값은 담지 않는다**(`path`·`code` 만). 있으면 FE 는 그 칸에 붙이고, 없으면 일반 안내만 보이므로 BE 일정과 무관하게 먼저 머지할 수 있다. 문장은 사람이 읽는 용도로 남겨도 좋다.
2. **매칭 1차 필터(#532)가 필요로 하는 값이 이 칸으로 충분한가** — `level`(학사 이상) · `status`(졸업 예정 포함 여부) · 경력 연수(`type` 별로 인턴·파트타임을 세는지, 기간이 겹칠 때 합치는지) 외에 필요한 칸이 있으면 지금 정해야 화면이 한 번에 맞춘다. 특히 ① 직무(`role`)·전공·자격증 이름은 자유 글이라 정규화·사전이 없다. 사전을 서버가 줄 수 있으면 FE 가 입력 제안(자동 완성)으로 쓸 수 있다. ② 어학 `score` 는 글(20자)이라 "토익 800 이상"을 서버가 숫자로 견주려면 시험별 형식이나 숫자 칸이 필요하다. ③ 걸러진 결과가 목록에서 빠지는지·아래로 내려가는지·표시만 하는지는 매칭 쪽 결정이다. **입력하지 않은(건너뛴) 사용자는 거르지 않는다**고 제안한다 — 안 적었다고 공고가 사라지면 안 된다. 그리고 학력 `status` 가 졸업 예정이거나 달이 미래인 경우를 어떻게 읽을지.
3. **학점 만점 선택지와 학점 규칙** — 선택지를 4.0 · 4.3 · 4.5 · 100 으로 보인다. 5.0·9.0 같은 만점이나 P/F 처럼 점수가 없는 학교가 필요한지 확인하고, **학점의 범위(0 이상 만점 이하)와 소수 자릿수 규칙**을 계약에 적어 달라(FE 는 0 이상 만점 이하로 먼저 막는다).
4. **달의 범위** — 지금은 형식만 봐서 `2204-03` 이나 `1900-01` 도 저장된다. 경력 연수를 계산하는 쪽(#532)에서 어긋날 수 있다. BE 가 범위(예: 1950년 이후, 시작·취득 월은 이번 달까지, 졸업 예정은 N년 뒤까지)를 정하면 FE 도 같은 규칙으로 막고 문구를 맞춘다. "이번 달"은 `Asia/Seoul` 기준이길 제안한다.
5. **경력 `endMonth: null` = 재직 중** — 의도 확인. FE 는 퇴사 월을 비운 채 저장하지 못하게 한다(위 "검증"). 재직 중이 아닌데 `null` 로 오는 경로가 BE 에 없는지 봐 달라.
6. **`savedAt` 의 뜻** — 저장할 때마다 바뀌는지, 같은 내용을 다시 저장해도 바뀌는지. FE 는 값에 의존하지 않고 `null` 인지만 본다. 두 탭에서 고치면 마지막 저장이 이기는데(통째 교체), 막으려면 `savedAt` 을 `If-Match` 로 받는 낙관적 잠금이 필요하다. FE 는 지금 쓰지 않는다.
7. **AI 로 보내는 범위와 고지** — 개인정보 원칙 4번의 (a)(b)(c). 정해지면 입력 화면 안내와 마이페이지 '저장·보관 정보'를 맞춘다.
8. **보관·삭제·열람** — 사용자를 지우면 함께 지워진다는 것은 #552 에 있다. 탈퇴 기능은 아직 "준비 중"이다. 보관 기간, 백업에 남는 기간, 저장 시 암호화, 운영자 열람 권한, 제3자(공고 회사)에 넘기지 않음의 명시, `PUT /profile` 본문을 로그·APM 에 남기지 않음. 정해지면 마이페이지 '저장·보관' 표의 "보관"과 수집 목적 문구를 맞춘다.
9. **글자 수 단위** — FE 는 JS 글자 수(UTF-16)로 센다. BE 가 코드포인트로 세면 이모지에서 경계가 다르다.
10. **요약을 `MeView` 에 넣을지** — 홈 안내가 `GET /profile` 을 한 번 더 부른다. `MeView` 에 `profileSaved: boolean`(= `savedAt !== null`) 하나만 있으면 호출을 줄일 수 있다. 값 자체는 `MeView` 에 넣지 않기를 제안한다.
11. **지표 이벤트 이름** — 서버가 이벤트 이름을 허용 목록으로 받는다면 세 개(`profile_prompt_accepted` · `profile_prompt_dismissed` · `profile_saved`)를 더해야 한다.
12. **켜는 시점** — #552 가 머지·배포되고 위 1·7번이 정리된 뒤 `frontend/Dockerfile` 에 `ENV VITE_PROFILE_ENABLED=true` 를 더한다(`VITE_MATCH_ENABLED` 와 같은 방식). 지금은 더하지 않았다.
