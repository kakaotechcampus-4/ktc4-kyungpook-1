# 공고 조건 매칭 구현 계획

## 승인된 범위
#207 e829d13의 FE 계약과 예시를 사용한다. #199에 FE 동의를 남겼다. 인재상 태그가 아닌 공고 조건 목록·상세를 만들며 자소서는 이번 범위에 넣지 않는다. #116의 인재상 매칭 부분은 본 작업으로 대체하고 자소서 작업만 분리한다. API 서버 구현 완료 전 실제 모드는 VITE_MATCH_ENABLED로 제한한다.

## 화면 설계
목록: 제목 → 검색/경력/직무/정렬 → 결과 수 → 공고 카드. PC는 2열, 모바일은 1열이며 대표 행동은 공고 상세 보기다. 등급은 서버 값을 표시하고 합격 가능성으로 표현하지 않는다. null은 평가 전, D는 근거가 없는 상태로 구분한다.
상세: 회사·직무·마감/출처 → 필수·우대 조건 → 하게 될 일. 조건 아래 A/R 카드 문장을 연결하고 빈 근거도 보인다. text와 quote가 같으면 원문 중복을 숨긴다. ENTRY는 신입 가능, UNSPECIFIED는 경력 표시 없음이며 신입 필터에 넣지 않는다.

## 구현 순서
1. api/matching.ts: Zod 스키마, 목록/상세 API, 서버 준비 전 endpoint 차단, 캐시 키/조회 훅. 화면은 mock 파일을 직접 참조하지 않는다.
2. features/match/model.ts: 마감/등급 정렬, 검색/경력/직무 필터, 표시 문구. 요청 파라미터를 만들지 않는다.
3. mock/matching.ts: 계약 예시 기반 목록/상세, null 등급/빈 조건/미확인 경력. 예시 카드 id를 실제 데모 카드에 연결하고 현재 확정 버전/가리기 반영. 프론트 제품 코드에서 등급을 다시 계산하지 않는다.
4. 목록/상세와 공통 셸 탐색 추가. 기존 SearchField/Select/QueryFailure를 재사용하며 매칭 CSS만 별도 범위에 둔다.
5. 카드 변경 성공 후 매칭 캐시 무효화. 필터 변경·탭 복귀에 AI 검색을 재호출하지 않고 오류 자동 재시도도 하지 않는다.
6. 단위/RTL 및 320·390·768·1440px 브라우저 테스트, 정적 빌드, 실제 API 모드 기능 제한 확인. README·회귀 원인·검증 결과 기록.
7. 최신 develop과 차이를 확인해 PR 생성, Grow22·taehun0208·ganggang-0605 리뷰 요청. #116에 역할 분리 댓글. 개인 저장소에는 배포된 UX를 유지하며 매칭 변경만 적용하고 Vercel 빌드·검증·배포.

## 회귀 방지
브라우저 목은 정적 산출물에서도 돌아야 한다. 집계/카드 API 계약을 바꾸지 않는다. 활성 공고 계산에서 고정 예시 날짜가 지나 사라지는 테스트는 피하고 상대 날짜 목을 사용한다. 쿠키/인증 및 로그아웃의 전체 캐시 초기화는 기존 공통 처리를 쓴다. API 응답 미지원은 원인과 수동 재시도를 보여준다. 404 상세에는 목록 복귀, 확정 카드 없음에는 카드 목록을 연결한다.

## 검증·트러블슈팅
- 신규 계약·화면 테스트 15개: enum/null/정렬/필터, 기능 제한, 503 수동 재시도, 상세 404, 중복 원문 숨김, 가리기·확정·재열기 캐시 제거.
- 정적 빌드 매칭 브라우저 5개: 320/390/768/1440px, 목록 검색·경력 필터·상세·목록 복귀·카드 연결, 다크 모드와 가로 넘침.
- Mock을 끈 HTTP 계약 브라우저 5개: 기존 카드 계약 4개와 매칭 메뉴·직접 경로·endpoint 차단 1개. 실제 Spring/OAuth/AI 연동 검증은 아니다.
- 독립 리뷰 후 목록 수동 새로고침 시 상세 캐시 무효화, 실패 조회 재진입 자동 재요청 방지(retryOnMount false)를 추가했다. 카드 변경은 resetQueries로 이전 근거를 지워 재조회 실패 시 가리기 이전 문장을 남기지 않는다.
- Windows에서 forks worker 시작이 지연돼 local threads로 검증했다. 무거운 검사 병렬 실행 중 lazy 화면 로딩 제한에 걸린 2개는 코드 변경 없이 순차 실행해 통과했다. CI 정책·대기 제한을 완화하지 않았다.
- 데모는 가상 공고 예시이며 화면에 짧게 표시한다. 목록과 상세는 같은 데이터 생성기를 사용하고 근거 링크는 현재 확정 데모 카드의 가리기 적용 A/R로 연결한다. 데모 등급은 시나리오 값이며 실제 매칭 품질을 뜻하지 않는다.
