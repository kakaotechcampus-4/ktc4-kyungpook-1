# UX 개선 설계와 실행 기록

## 목적과 기준
최신 develop f6131ef에서 시작한다. 사용자가 승인한 10/18 UX 진단을 반영한다. 한 화면의 대표 행동을 명확히 하고, 입력을 보존하며 실제 제공 범위만 안내한다. PC 1440px, 모바일 390/320px에서 확인한다.

## 계약과 협업 경계
- API 경로, 요청/응답, Job enum·pollAfterMs·retryable, UUID 멱등키, null/400, STAR 저장·확정 규칙을 유지한다.
- #253의 진행 상태·재시도·사용된 후보 정리는 중복 구현하지 않는다. 필요한 경우 같은 파일의 다른 영역만 수정하고 결합 검증한다.
- #219 Docker 운영 스위치 및 #207/#116 기업 매칭은 변경하지 않는다.
- 역사 버전 본문을 조회하는 서버 계약이 없으면 본문을 지어내지 않는다. 서버 요약으로 복원 대상을 확인한 뒤 명시적 복원을 제공한다.
- 비밀정보·환경 파일을 커밋하지 않는다. 신규 의존성을 추가하지 않는다.

## 검증 기록
- 최종 단위/화면 테스트 40파일 295개 통과. 최초 동작 회귀를 실패로 확인한 뒤 구현했고, 실제 모드의 세션 만료 안내 유지도 별도 검증했다.
- 운영 빌드 Playwright 107개 통과: 핵심 생성→확정, 실패·재시도, 검색·키보드, 모바일 하단 가림, 두 테마 대비 포함.
- 15개 화면 × 1440/390/320px × light/dark = 90개 화면 확인. 가로 넘침·페이지 오류 0. 외부 연구 폴더에 캡처를 보관하며 사용자 데이터·trace는 커밋하지 않는다.
- #253 head f9b2b9d4와 자동 결합 시 충돌 없음. 결합 트리에서 타입 검사와 관련 테스트 33개 통과. #253 코드는 이 브랜치에 병합하지 않았다.
- 단위/HTTP 모드 최종 검증은 PR 본문에 실제 결과를 기록한다. HTTP 모드는 Mock off + 격리된 HTTP fixture이며 실제 운영 Spring의 데이터를 변경하지 않는다.
- 별도 코드 리뷰에서 마지막 회상 입력 손실·레포 상태 혼용·다른 카드에 이전 복원 선택 적용 가능성을 발견하여 키 분리, 이탈 확인, 늦은 응답 방지로 수정했다.

## 트러블슈팅과 보존한 동작
- 초기 저장 CTA를 옮긴 뒤 기존 테스트는 생성 전 종료/확정을 직접 누르고 있었다. 새 사용자 순서로 바꾸되 UUID 재사용·ACK ID·수정 중 입력·서버 원문/버전 검사는 삭제하지 않았다.
- 기존 세션 만료 테스트는 샘플 모드에서도 로그인 실패를 기대했다. 샘플에서는 숨김, 실제 로그인에서는 유지하는 별도 검증으로 나눴다.
- 회상은 브라우저 영구 저장을 추가하지 않는다. 제출된 답변은 기존 API로 서버에 저장하며, 아직 제출하지 않은 메모만 화면 생명주기 동안 보관한다.
- #253과 처음 결합할 때 버튼 주변 및 import에서 충돌했다. 후보 행동 로직은 원복하고 별도 스타일 파일로 시각적 위계를 조정했으며, 카드 import 경계를 유지해 자동 결합을 확인했다.

## 서버 협의가 필요한 한계
- 현재 버전 목록은 요약만 제공한다. 과거 STAR 본문을 상상해서 보여주거나 미구현 GET 경로를 호출하지 않는다. 상세 비교에는 소유권 검사를 포함하는 과거 버전 본문 조회 계약이 필요하다.
- 분석 진행 생존 표시·불가 재시도 숨김·사용된 후보 접기는 #253 담당 범위다. 중복 구현·임의 진행률 생성·서버 retryable 무시는 하지 않는다.
