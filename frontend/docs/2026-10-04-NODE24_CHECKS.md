# Node 24 GitHub Checks 호환성 수정

## 문제와 원인
팀 PR #61의 Node 22 검사와 개인 PR #1은 통과했지만 `verify (24)`에서 저장·이탈 검사 6개가 실패했다. Node 24.21.0으로 로컬 실행해 같은 오류를 재현했다.

`RequestInit: Expected signal ("AbortSignal {}") to be an instance of AbortSignal`은 라우터가 Request를 만들 때 발생한다. 기존 Vitest 2.1.9의 jsdom 환경은 브라우저 AbortController/AbortSignal과 Node의 Request를 함께 사용했다. Node 24의 Request는 이 조합을 거절해 화면 이동과 이어쓰기 검사가 연쇄 실패했다.

[Vitest 공식 이슈 #8374](https://github.com/vitest-dev/vitest/issues/8374)와 [공식 수정 #8390](https://github.com/vitest-dev/vitest/pull/8390)에서 동일 원인과 Fetch/DOM 호환성 수정을 확인했다.

## 수정 범위
- 공식 환경 호환성 수정이 포함된 Vitest 4.1.11로 버전을 고정하고 lockfile을 갱신한다. Vite·React·jsdom과 Node 22 팀 표준은 유지한다.
- 테스트는 tsconfig.test.json으로 타입 검사한다. 브라우저 앱 설정을 상속하며 테스트에만 Node 타입을 추가하고 빌드 references에 포함한다. 파일을 읽는 공유 계약 검사의 Node 타입을 테스트 도구의 암묵적 타입에 의존하지 않는다.
- 애플리케이션 코드와 API 규약을 변경하지 않는다. 테스트에서는 Request 취소와 DOM 이벤트 취소의 실제 동작을 함께 검사한다.
- 기존 저장·이탈·StrictMode 검사를 유지한다. Node 24 검사는 기존 CI matrix에서 계속 실행한다.
- 환경 파일·인증 키는 변경하거나 커밋하지 않는다.

## 재현과 검증 계획
1. 기존 버전의 Node 24에서 저장 검사 6개 실패와 새 Request 취소 검사 실패를 확인한다.
2. 도구 버전/lockfile만 바꾼 뒤 새 호환성 2개와 저장 검사 6개를 실행한다.
3. Node 22와 24 전체 단위 검사, 타입·프로덕션 빌드, 정적 E2E를 실행한다.
4. 문서·README와 두 PR을 갱신하고 실제 GitHub Checks 결과를 확인한다.

```powershell
npm ci
npm run typecheck
npm test
npx --yes --package=node@24 node node_modules/vitest/vitest.mjs run
$env:PLAYWRIGHT_PORT='5176'
npm run e2e:static
```

## 검증 기록
기존 Vitest 2.1.9 + Node 24에서 `save-navigation.test.tsx` 6개 실패와 unhandled rejection 3건, `web-abort-compat.test.ts`의 Request 취소 1개 실패를 확인했다.

Vitest 4.1.11에서 Node 22.17.0과 Node 24.21.0 각각 전체 단위 108개가 통과했다. 기본 npm 10.9.2의 깨끗한 `npm ci`도 통과했으며 npm audit 결과는 0건이다. 타입·프로덕션 빌드 및 정적 E2E 60개가 통과했다. 테스트와 앱의 별도 타입 환경도 읽기 전용 리뷰로 확인했다. GitHub Checks의 실행 결과는 PR 본문에 기록한다.

## 설치·타입 검사에서 함께 확인한 문제
기존 npm 10.9.2는 Vitest 버전 변경의 peer dependency 해석에서 `edgesOut` null 오류가 났다. lockfile 갱신에만 일회성 `npx --yes npm@11.21.0 install --save-dev --save-exact vitest@4.1.11`을 사용했다. 전역 npm이나 CI 설치 정책은 변경하지 않았다. 이후 기본 npm의 `npm ci`로 새 lockfile의 재현성을 검증했다.

Vitest 4로 업데이트한 뒤 `shared-contract.test.ts`의 node:fs/path/process 타입 오류가 빌드에서 드러났다. 테스트 전용 TypeScript 프로젝트를 분리하고 Node 타입을 명시했다. 앱은 기존 브라우저 타입으로 검사하고, 테스트는 별도 프로젝트에서 계속 전체 타입 검사한다. 테스트를 빌드 검사에서 누락하거나 오류를 무시하지 않는다.

로컬 5176 포트는 다른 프로세스에서 사용 중이라 정적 E2E 서버가 시작하지 못했다. 기존 프로세스를 종료하지 않고 빈 포트를 골라 PLAYWRIGHT_PORT로 실행한다.
