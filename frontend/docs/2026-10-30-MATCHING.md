# 매칭 개편 — 레포 분석 뒤 추천 기업 · 공고 페이지 추천 · 공고에서 자소서 (흐름 확정 · API 미정)

화면 흐름과 동작 규칙만 정한 문서다. 서버 API(경로·요청·응답 칸 이름)는 아직 없고, 맨 아래 'API' 절은 비어 있다. 남은 결정('정할 것')을 정하면 그 절을 채우는 PR 을 따로 올린다. 그 전까지 지금 매칭 계약([BACKEND_CONTRACT.md](BACKEND_CONTRACT.md) '기업·직무 매칭')과 지금 화면은 그대로 둔다.

화면 설계는 이 문서로 먼저 시작할 수 있다. 칸 이름이 필요한 목(mock)은 API 절이 채워진 뒤에 만든다.

## 왜 바꾸나

- 지금은 사용자가 매칭 메뉴에 들어가야 공고를 본다. 바꾼 뒤에는 **레포 분석이 끝나면 에이전트가 먼저 맞는 기업을 골라 보여 준다.**
- 지금 등급(A~D)은 카드 문장과 공고 조건 문장이 '비슷한 말을 썼나' 를 재서 부정확하다. 바꾼 뒤에는 **겹친 기술처럼 사용자가 바로 확인할 수 있는 이유**를 보여 준다.
- 지금은 공고를 보고 자소서로 넘어가는 길이 없다. 바꾼 뒤에는 **공고 상세에서 바로 자소서를 시작**한다.

## 한눈에 보기

```
레포 분석 끝
  └─ 서버가 추천을 계산해 저장 (확정 카드 전체 + 인적사항 → 공고 전체)
       ├─ 레포 화면: 추천 기업 3곳
       └─ 공고 페이지(/match) 맨 위: 같은 추천
            └─ 기업을 누름 → 공고 상세 → '이 공고로 자소서 쓰기' → 자소서 ① 입력
공고 페이지의 '내 조건으로 매칭하기' → 추천을 새로 계산해 바꿈
```

## 말뜻

| 말 | 뜻 |
|---|---|
| 추천 | 사용자에게 맞는 기업 몇 곳과 기업마다 대표 공고 하나, 맞은 이유. **사용자당 하나**만 저장한다 |
| 빠른 추천 | AI 없이 값만 견줘 고른 추천. 몇 초 안에 끝난다 |
| 정밀 추천 | 빠른 추천의 상위 후보만 AI 가 다시 읽고 순서를 다시 매긴 추천 |
| 관심 직무 | 사용자가 인적사항에서 고르는 직무 1~3개(백엔드·프론트엔드 등). 이 직무가 아닌 공고는 추천하지 않는다 |
| 맞은 이유 | 추천마다 붙는 한 줄. 예: 'Java, Spring, PostgreSQL 3개가 겹쳐요' |

## 화면

### ① 레포 화면 — 분석이 끝나면 넘어가는, 그 레포의 카드를 모아 보는 화면

카드 목록 옆이나 위에 **추천 칸**을 둔다. 자리(PC 오른쪽 칸, 모바일 카드 목록 위 등)는 FE 가 정한다.

```
이 레포 경험과 맞는 기업                      빠른 추천 · 10/30 14:20 계산
┌───────────────────────────────────────────────────────────────┐
│ [로고] 초록마켓   백엔드 개발자 · 마감 11/10                     │
│        Java, Spring, PostgreSQL 3개가 겹쳐요                    │
│        이 레포 카드 2장이 맞았어요                               │
├───────────────────────────────────────────────────────────────┤
│ [로고] 바다페이   서버 개발자(신입) · 상시 채용                  │
│        Java, Docker 2개가 겹쳐요                                │
├───────────────────────────────────────────────────────────────┤
│ [로고] 구름소프트  백엔드 엔지니어 · 마감 11/03                  │
│        Spring, SQL 2개가 겹쳐요                                 │
└───────────────────────────────────────────────────────────────┘
카드 1장이 확인을 기다려요. 확인하면 추천이 더 정확해져요.
추천 전체 보기 →  (공고 페이지로)
```
(회사·공고는 지어낸 예시다.)

- 기업 3곳을 보여 준다. 기업마다 로고·이름, 대표 공고의 직무명과 마감, 맞은 이유 한 줄.
- 추천은 **지금까지 쌓인 모든 레포의 확정 카드**로 계산한다. 그래서 이 레포 카드가 맞은 기업이면 '이 레포 카드 N장이 맞았어요' 를 덧붙여, 방금 분석한 레포가 추천에 어떻게 쓰였는지 보이게 한다.
- 기업을 누르면 그 기업의 대표 공고 상세(③)로 간다.
- '추천 전체 보기' 는 공고 페이지(②)로 간다.

**화면이 그려야 할 상태**

| 상태 | 언제 | 보여 줄 것 (문구는 예시) |
|---|---|---|
| 계산 중 | 레포 카드는 다 만들어졌고 추천을 계산하는 몇 초 | '맞는 기업을 고르는 중이에요' |
| 추천 있음 | 위 그림 | 기업 3곳 |
| 정밀 계산 중 | 빠른 추천은 나왔고 AI 가 다시 고르는 중 | 빠른 추천을 그대로 보여 주고 '더 정확히 고르는 중' 표시 |
| 맞는 공고 없음 | 관심 직무·인적사항에 맞는 공고가 없거나 겹친 기술이 하나도 없음 | '지금 맞는 공고가 없어요' + 공고 둘러보기 링크 |
| 확정 카드 없음 | 모든 카드가 확인을 기다림 | '카드를 확인하면 맞는 기업을 골라 드려요' |
| 계산 실패 | 서버 오류 | '추천을 불러오지 못했어요' + 다시 시도 |

- **확인을 기다리는 카드는 추천에 들어가지 않는다.** 문제 없는 카드는 분석 직후 자동으로 확정되므로([#568](https://github.com/kakaotechcampus-4/ktc4-kyungpook-1/issues/568)) 대부분 바로 쓰인다. 확인을 기다리는 카드가 있으면 '확인하면 추천이 더 정확해져요' 를 함께 보여 준다.

### ② 공고 페이지 — 매칭 메뉴 `/match`

위아래 두 칸이다.

**위: 내 추천**
```
내 추천                                 정밀 추천 · 마지막 계산 10/30 14:25, gitory 분석 뒤
[초록마켓] [바다페이] [구름소프트] [하늘게임] [별빛랩]      (기업 카드, 맞은 이유 한 줄씩)
                                                     [내 조건으로 매칭하기]
```
- 레포 화면과 **같은 추천**을 보여 준다. 기업 수는 레포 화면보다 많아도 된다('정할 것' 1).
- '마지막 계산' 에 언제, 무엇 뒤에 계산했는지 적는다(예: 'gitory 분석 뒤', '내 조건으로 매칭하기'). 버튼을 눌러 결과가 같거나 바뀌어도 사용자가 이유를 알 수 있게 하기 위해서다.
- 추천이 한 번도 계산되지 않았으면(레포 분석 전) '레포를 분석하면 맞는 기업을 골라 드려요' 와 레포 목록 링크.

**'내 조건으로 매칭하기' 버튼**
- 누르면 지금의 공고·확정 카드·인적사항(관심 직무 포함)으로 추천을 **새로 계산해 바꾼다.** 레포 화면의 추천도 같이 바뀐다.
- 그사이 바뀐 것이 없으면 **같은 결과가 나오는 것이 맞다.** 같은 조건에 다른 답이 나오면 어느 쪽을 믿을지 헷갈리기 때문이다. 화면은 '바뀐 것이 없어 같은 추천이에요' 처럼 알려 줄 수 있다.
- 결과가 달라지는 때: 새 공고가 들어오거나 마감됨, 카드를 고치거나 더함, 인적사항·관심 직무를 바꿈.
- 계산하는 동안은 버튼을 막고 진행 표시를 한다. 빠른 추천은 몇 초, 정밀 추천은 그보다 오래 걸린다(시간은 API 를 정할 때 잰다).

**아래: 공고 둘러보기**
- 공고 전체 목록. 마감이 가까운 순, 상시 채용은 뒤.
- 회사 로고·이름, 기업별 보기(#545), 경력·직무 필터, 글자 검색은 지금처럼 둔다.
- **등급(A~D)은 보이지 않는다.** 둘러보기는 '맞나' 를 판정하지 않고 공고를 보여 주기만 한다.
- 목록을 열거나 검색·필터를 바꿀 때 AI 를 부르지 않는다.

### ③ 공고 상세 — 지금 매칭 상세 화면

- 회사·직무·마감/출처, 필수·우대 조건, 하게 될 일은 지금 구조 그대로다.
- 추천에서 들어왔으면 맨 위에 그 추천의 **맞은 이유**를 보여 준다.
- 조건 아래 근거 카드 문장을 붙이는 방식은 바뀔 수 있다('정할 것' 8).
- **새 버튼 '이 공고로 자소서 쓰기'** → 자소서 ① 입력 화면([자소서 계약](2026-10-28-COVER_LETTER.md))을 회사·직무·공고 조건을 채운 채로 연다. 문항은 사용자가 넣는다. 지원 동기 문항에 회사 정보가 없던 문제도 이걸로 풀린다.
  - 지금 자소서 API(`POST /cover-letters`)에는 공고를 받는 칸이 없다. 공고를 어떻게 넘길지는 '정할 것' 7 이다. 그 전까지는 직무 칸(`jobRole`)만 공고 직무명으로 채워 열 수 있다.

### ④ 인적사항 화면 — 관심 직무 고르기

- 인적사항([#540](https://github.com/kakaotechcampus-4/ktc4-kyungpook-1/pull/540) 의 `/settings/profile`)에 **관심 직무 1~3개 고르기**를 더한다.
- 처음에는 **카드 분야 태그로 미리 골라 둔다.** 예: 백엔드 카드가 가장 많으면 '백엔드' 가 골라져 있고, 사용자는 확인만 하거나 바꾼다.
- 고르지 않으면 직무로 거르지 않는다.
- 직무 목록은 '정할 것' 3 이다. 지금 공고 직무 분류(`BACKEND · FRONTEND · MOBILE · DEVOPS · DATA · AI_ML · SECURITY · QA · ETC`)가 출발점이다.

## 추천을 고르는 방법

두 단계지만 **따로 만든 두 기능이 아니라 한 계산의 앞뒤**다.

**1단계 — 빠른 추천 (AI 없음)**
1. **관심 직무로 거르기** — 백엔드만 고른 사용자에게 프론트엔드·데이터 공고를 추천하지 않는다.
2. **인적사항 필수 조건으로 거르기** — 학력, 최소 경력 연수처럼 공고의 **필수** 조건에 맞지 않으면 뺀다. 공고에 그런 요구가 없거나 사용자가 인적사항을 적지 않았으면 거르지 않는다. 우대 조건은 거르지 않고 2단계 점수에만 쓴다.
3. **기술 겹침으로 점수 매기기** — 공고의 필수·우대 기술 목록과 내 확정 카드의 기술 태그가 몇 개 겹치는지 센다. 필수 기술이 겹치면 더 높게 친다. 겹친 기술이 그대로 '맞은 이유' 가 된다.
4. 공고 점수를 기업으로 묶어 상위 기업과 대표 공고를 고른다('정할 것' 1).

**2단계 — 정밀 추천 (AI)**
- 1단계 상위 후보만 AI 가 '이 경험이 공고가 요구하는 깊이를 채우나' 를 판단해 순서를 다시 매긴다.
- **1단계 후보 안에서 순서만 바뀐다.** 빠른 추천에서 본 기업이 정밀 추천에서 갑자기 전혀 다른 기업으로 바뀌지 않는다. 인적사항을 1단계에서 거르는 것도 같은 이유다 — 필수 조건에 안 맞는 기업을 빠른 추천에 띄웠다가 정밀 추천에서 빼면 '추천한 회사가 사라지는' 일이 생긴다.
- 맞은 이유는 AI 판단 한 줄과 근거 카드로 바뀐다. 예: '결제 대기열 장애를 직접 줄인 경험이 대용량 트래픽 처리 조건에 맞아요' + 근거 카드 제목.
- 정밀 추천이 있으면 레포 화면·공고 페이지 모두 정밀 추천을 보여 준다.

**예시 — 사용자 한 명의 흐름**
1. 관심 직무 '백엔드', 인적사항 '졸업 예정', 경력 없음.
2. gitory 레포 분석이 끝나 카드 5장 중 4장이 자동 확정된다. 확정 카드의 기술: Java · Spring · PostgreSQL · Docker.
3. 1단계: 공고 120개 → 백엔드 35개 → '경력 3년 이상' 이 필수인 12개를 빼고 23개 → 기술 겹침 순으로 기업을 묶어 상위 3곳.
4. 레포 화면에 '빠른 추천' 3곳이 뜨고, 1장 남은 카드에 대해 '확인하면 추천이 더 정확해져요' 가 붙는다.
5. 사용자가 남은 카드를 확인하고 공고 페이지에서 '내 조건으로 매칭하기' 를 누른다 → 카드 5장으로 다시 계산하고, 2단계가 상위 후보를 다시 골라 '정밀 추천' 으로 바뀐다.

## 다시 계산하는 때

| 때 | 계산 |
|---|---|
| 레포 분석이 끝나 그 레포의 카드가 다 만들어졌을 때 | 한다 |
| '내 조건으로 매칭하기' 를 누를 때 | 한다 |
| 레포 화면·공고 페이지를 열 때 | **하지 않는다** — 저장된 추천을 읽기만 한다 |
| 인적사항·관심 직무를 바꿀 때 | '정할 것' 4 |

화면을 열 때 계산하지 않아서 빠르고, AI 비용도 위 두 때로 묶인다.

## 지금 매칭과 달라지는 것

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 시작 | 사용자가 매칭 메뉴를 연다 | 레포 분석이 끝나면 추천이 먼저 뜬다 |
| 단위 | 공고 목록 | 기업 + 대표 공고 |
| 판정 | 등급 A~D(카드 문장과 조건 문장이 비슷한가) | 맞은 이유(겹친 기술, 정밀 추천은 AI 판단 한 줄) |
| 계산하는 때 | 목록을 열 때마다 | 레포 분석 끝, 버튼을 누를 때 |
| 직무 | 화면 필터 | 관심 직무로 서버가 거름 |
| 자소서 | 따로 시작 | 공고 상세에서 바로 시작 |

그대로 두는 것: 공고 상세의 조건·하게 될 일 구조, 기업별 보기와 로고(`companyId` · `logoUrl`), 자소서 화면.

## 정할 것 (API 를 정하면서 하나씩)

1. 추천 기업 수(레포 화면 3곳, 공고 페이지 몇 곳)와 공고 점수를 기업으로 묶는 법, 대표 공고를 고르는 법
2. 정밀 추천을 레포 분석 뒤 바로(배경에서) 돌릴지, 버튼을 누를 때만 돌릴지 — 바로 돌리면 사용자는 기다리지 않지만 레포마다 AI 비용이 든다
3. 관심 직무 목록과 기술 이름 목록 — 지금 카드 기술 태그는 16개라 Spring·PostgreSQL 같은 이름이 없다. 공고와 카드가 같은 목록을 쓰게 넓힌다
4. 인적사항·관심 직무를 바꿀 때도 자동으로 다시 계산할지
5. '내 조건으로 매칭하기' 가 공고 둘러보기의 필터(경력 등)도 계산에 넣을지 — 넣으면 레포 화면 추천도 그 필터 결과로 바뀐다
6. 레포 화면에 '이 레포 카드가 맞았어요' 말고 '이 레포로 새로 올라온 기업' 도 표시할지
7. 공고에서 자소서로 넘길 값 — 공고 id 를 넘겨 서버가 회사·조건을 붙일지, 화면이 채운 글을 넘길지
8. 추천에 없는 공고 상세에서 '맞은 조건' 을 무엇으로 채울지
