# 후보 선택·정렬·읽기 영역 개선

## 범위

develop `441b7fa`를 기준으로 후보 보드부터 홈·레포·카드 목록/상세·직접 작성·답변·GitHub 연결·마이페이지·회상·탈퇴·로그인 12개 화면을 점검했다. 1440·390·320px 및 두 테마에서 로딩이 끝난 본문을 확인한다. 색감·API·서버 데이터·저장·멱등키·폴링은 유지한다.

## 개선

| 문제 | 변경 |
|---|---|
| 체크 버튼 18px·제목과 중심 13px 차이 | 44px 조작 영역 안에 20px SVG 표시, 제목 첫 줄과 정렬 |
| 출처·제목·상태·제외 버튼이 한 줄에서 섞임 | 제목/행동과 출처/상태를 분리하고 명시적인 grid 사용 |
| 검색창이 PC에서도 좁음 | 검색 영역이 남는 폭을 사용하며 행동은 44px 유지 |
| 모바일 커밋의 고정 SHA 열로 본문이 좁음 | SHA/제외 상태를 본문으로 옮기고 체크·본문·외부 링크로 정렬 |
| 커밋을 읽으면 상위 후보가 선택됨 | 상세 영역 클릭을 후보 선택에서 제외; 커밋 포함/링크는 별도 조작 |
| 반복 문구·불명확한 ‘카드감 낮음’ | 출처 배지와 서버 추천 이유를 보여 주고 weak 표시를 ‘추천도 낮음’으로 정리 |
| 긴 제목 카드의 STAR가 26px 내려감 | 남는 공간을 STAR 위에 배치, 제목을 자르거나 고정하지 않고 기준선 유지 |
| 320px 레포의 마지막 단계 문구가 잘림 | 해당 페이지의 세 단계만 모바일 3등분, 모달 단계 레일 유지 |
| 근거 링크 32px·긴 문장 생략 | 44px 링크·전체 SHA/설명 자연 줄바꿈 |

선택 유지·검색 밖 선택·사용된 후보 비활성·추천 대상·제외 실패/복원·카드 생성 실패 복구는 기존 동작을 유지한다. 페이지 전용 클래스로 공통 wizard/카드 상태의 의미가 바뀌지 않도록 한다. 사용되지 않는 후보 스타일과 hover가 disabled 표시를 덮던 규칙을 정리한다.

## 검증과 재발 방지

- 클릭 크기·제목 정렬·커밋 읽기/포함·모바일 본문 폭·추천 대상·STAR 기준선·레포 단계 경계·근거 읽기를 브라우저에서 검사한다. 작은 조작 영역, 13px/26px 정렬 차이, 단계 잘림, 상위 선택 전파를 실패로 재현한 뒤 수정한다.
- 키보드 Space/Enter, ARIA checked·label, SVG 장식 숨김, disabled·이벤트 전파·강제 색상을 공통 Check에서 유지한다.
- 전체 화면 캡처는 Skeleton 숨김과 수집 이력 로드를 기다린다. 고정 하단바가 전체 캡처 중간에 보이는 현상을 실제 스크롤 불가로 오인하지 않는다. 긴 문장·내용을 자르거나 가로 overflow를 숨겨 문제를 감추지 않는다.
- 기존 카드 정렬 단위 검사가 날짜 변경 후 실패했다. 시드는 모듈 로드의 현재 날짜인데 테스트 시계가 10/12로 고정돼 새 수정이 시드보다 과거가 됐다. 시계만 시드 이후로 고정하고 Mock/서버 정렬 규칙은 유지한다.
- DOM iterable 환경을 넓히지 않고 브라우저 검사에서 `Array.from(HTMLCollection)`을 사용한다.

최종 타입·단위·개발/정적/HTTP 검사, 코드 리뷰, 배포·CI 결과와 실행 링크는 PR 본문에 기록한다. 운영은 기존 Mock 체험 모드이며 실제 Spring 통합 검증과 구분한다. 환경 파일과 키는 업로드하지 않는다.
