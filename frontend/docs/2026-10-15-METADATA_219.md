# 카드 기본 정보 계약 보완 (#219)

## 범위
운영 활성화 전에 #186 서버 계약과 프론트 요청을 맞춘다. STAR 저장·확정·버전 규칙은 바꾸지 않는다.

## 수정
- 생성/PATCH가 같은 제목·기간 검증 규칙을 사용한다.
- 삭제한 기간은 null, 생략한 기간은 유지한다. 의미 있는 문자열의 공백은 보존한다.
- Mock metadata 입력 오류는 400 INVALID_REQUEST이며 확정 카드 수정은 기존 409다.
- 다이얼로그에서 오류가 나면 입력을 유지하고 사용자 클릭으로만 재시도한다.

## 트러블슈팅
기존 스키마는 null을 거부하고 빈 문자열을 그대로 보냈다. 기존 Mock 테스트가 422와 빈 문자열을 기대하여 계약 차이를 가렸다. 먼저 회귀 테스트 5건 실패를 확인한 뒤 공통 스키마와 Mock을 수정했다.

## 검증
- 타입 검사 및 운영 빌드 통과.
- 전체 단위/화면 테스트 35파일 231개 통과.
- HTTP 본문 null/필드 생략 및 400 오류 보존, 다이얼로그 입력 유지·사용자 재시도 테스트 포함.
- 실제 Spring 운영 서버에 데이터를 쓰는 검증은 하지 않았다.
- 운영 빌드 브라우저 카드 워크플로 테스트 5개 통과: 생성 후 제목·기간 수정, 기간 삭제 및 새로고침 유지 포함.
