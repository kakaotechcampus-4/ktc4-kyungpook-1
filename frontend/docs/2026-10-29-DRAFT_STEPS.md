# 카드 상세 'AI 가 한 일' (#521)

멘토 피드백: "에이전트가 스스로 판단하고 움직이는 장면이 잘 드러나도록". 서버는 카드 상세 응답의 `draftSteps`(BE #489, 계약은 [BACKEND_CONTRACT](BACKEND_CONTRACT.md) 'AI 가 한 일')에 AI 초안이 거친 단계를 담아 주는데, 화면에는 아무것도 없었다. 카드 상세에 'AI 가 한 일' 구역을 더했다.

## 사용자가 보는 것

- 초안(작성 중)과 확정한 카드의 상세 둘 다, 카드 칸 아래에 **AI 가 한 일** 구역이 하나 생긴다. 단계는 서버가 준 순서 그대로 세로 목록이다.
- 바퀴(`round`)가 둘 이상이면 "첫 초안과 검사", "1번째 고쳐 쓰기"처럼 이름이 붙는다. 첫 초안만 있으면 이름 없이 목록만.
- AI 가 스스로 고른 행동(`OPEN`·`RETRY`·`KEEP`)의 `reason` 은 **"AI 의 판단"** 이름표와 따옴표, 왼쪽 선으로 카드 문장과 구분한다. 구역 머리말도 "AI 의 판단은 AI 가 쓴 글이고 카드에 들어가는 문장이 아니에요"라고 말한다.
- 초안을 만드는 동안(D1)에는 아무것도 보이지 않는다(실시간 표시는 범위 밖). 직접 쓴 카드·기록 전에 만든 카드(`[]`)와 이전 서버(키 없음)도 구역을 그리지 않는다.
- 수정·가리기 화면과 인쇄에는 넣지 않았다.

## 코드

| 파일 | 하는 일 |
|---|---|
| `src/api/schemas.ts` | `DraftStep`·`DraftSteps`. `Card.draftSteps` 는 선택(이전 서버·이전 스냅샷에는 키가 없다) |
| `src/lib/draftSteps.ts` | 값 → 문장, 바퀴 묶음, 건너뛰기 규칙(순수 함수) |
| `src/features/cards/DraftSteps.tsx`·`.css` | 화면. 새 파일이라 다른 PR 과 겹치지 않는다 |
| `src/features/cards/CardPage.tsx` | `<DraftSteps steps={card.draftSteps} />` 두 줄(읽기 화면·초안 화면)과 import 한 줄 |
| `src/mock/fixtures.ts`·`store.ts` | card_01(전 과정), card_03(첫 검사만)에 데모 단계. `cardView` 는 없으면 `[]`(실서버처럼) |

실서버 모드에서 새로 부르는 API 는 없다. 이미 오는 카드 상세 응답을 읽을 뿐이다.

## 느슨하게 읽는 규칙

- 모르는 `kind`, 고장 난 `round`(음수·소수·문자), 객체가 아닌 항목은 **그 단계만** 버린다. 무슨 일을 했는지 모르면 지어내지 않는다.
- 모르는 `actor`·`field`·`material` 과 비었거나 문자열이 아닌 `code`·`value`·`reason` 은 null 로 두고 그 부분만 뺀다.
- `draftSteps` 가 배열이 아니거나 null 이어도 카드 전체는 읽힌다(`[]`).
- 칸 단계(`FLAG`·`OPEN`·`RETRY`·`KEEP`·`REWRITE`·`PASS`)인데 칸을 모르면 무엇에 대한 말인지 알 수 없어 건너뛴다.
- `actor` 가 `CODE` 인 단계에 `reason` 이 붙어 오면 계약 위반이라 'AI 의 판단'으로 내세우지 않고 버린다.
- 글은 React 텍스트로만 그린다. 링크를 만들지 않는다(`value` 에 URL 이 와도 글자 그대로).

## 문장(계약 표를 해요체로 다듬음)

| kind | 문장 |
|---|---|
| `DRAFT` | GitHub 기록으로 초안을 썼어요 |
| `FLAG` | {칸} 칸: 근거 없는 숫자({value})를 찾았어요 / 근거 커밋이 없어요 / 원문과 뜻이 다를 수 있어요 / 비어 있어요 / (모르는 코드) 문제를 발견했어요 |
| `OPEN` | {칸} 칸: 이슈·리뷰·답글·자료를 열어 봤어요, 아래 줄에 `value`(연 자료 제목), 그 아래 AI 의 판단 |
| `RETRY` | {칸} 칸: 자료 없이 고쳐 쓰기로 했어요 |
| `KEEP` | {칸} 칸: 그대로 두기로 했어요 |
| `REWRITE` | {칸} 칸을 다시 썼어요 |
| `PASS` | {칸} 칸: 다시 검사해서 통과했어요 |

- `DRAFT` 는 계약 예시의 "커밋과 PR 본문으로"를 쓰지 않았다. 커밋 묶음·이슈 후보에는 PR 본문이 없어 사실이 아닐 수 있다. 계약이 "다듬어도 된다"고 했고, 무엇을 읽었는지 모르니 "GitHub 기록"으로만 말한다.
- `OPEN` 은 "{value} 을(를)" 대신 자료 종류를 문장에, 제목을 아래 줄에 따로 둔다. 제목이 영문·숫자로 끝나도 조사가 틀리지 않는다.

## 일부러 하지 않은 것

- 단계를 `round` 로 다시 정렬하지 않는다(서버 순서가 곧 순서).
- 실측 카드(card_05)와 경험 카드(직접 쓴 카드)에는 데모 단계를 지어 넣지 않았다.
- `README.md`·`labels.ts`·`guidance.css` 는 건드리지 않았다. 열린 PR(#459·#461·#465)이 같은 파일을 고친다. 문구는 `lib/draftSteps.ts` 에, 스타일은 `DraftSteps.css` 에 뒀고, 정리는 그 PR 들이 머지된 뒤에 해도 된다.
- 글자 크기는 11·12·13·14·16 단계, 색은 시맨틱 토큰만 썼다(#461 의 기준에 맞춤).
