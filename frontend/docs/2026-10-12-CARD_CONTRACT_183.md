# 카드 API 계약 반영 — #183

## 범위와 기준

담당 [이슈 #183](https://github.com/kakaotechcampus-4/ktc4-kyungpook-1/issues/183), develop `333c109`, 병합된 #162·#163·#172·#175의 controller/service를 기준으로 반영한다. 백엔드와 AI 구현은 변경하지 않는다. 기존 검색·메뉴·테마·반응형·이탈 보호는 유지한다.

## 요청과 화면

1. 직접 작성 화면에 진입할 때 UUID v4를 하나 생성한다. 첫 저장 응답이 유실되어 재시도하면 같은 `Idempotency-Key`를 보낸다. 다음 작성 화면에서는 새 키를 사용한다.
2. 같은 키의 응답은 서버에 있는 카드의 현재 상태다. 반환된 제목·기간·레포를 표시하며 재요청 메타데이터로 자동 덮어쓰지 않는다. 사용자가 편집한 STAR 칸은 유지하고, 건드리지 않은 칸은 서버 글을 사용한다. 이미 확정된 카드라면 PATCH를 막고 기존 카드 링크를 제공한다.
3. 본문 PATCH는 항상 `situation/task/action/result` 네 키를 보낸다. 공백만 있는 값은 null, 의미 있는 공백·줄바꿈은 원문 그대로다. 칸 1000자·제목 256자·기간 50자·마스킹 20개 및 각 100자는 공유 상수/스키마로 관리한다. Java의 공백 판정과 기간 정규화 순서를 맞춘다.
4. 쓰지 않는 `POST /cards`, `POST /cards/{id}/versions`와 관련 훅·Mock 라우트를 제거한다. `/regenerate`는 실제 API 모드에서 화면과 요청 모두 차단하며 Mock 체험에서만 유지한다.
5. Mock도 같은 USER_EDIT 덮어쓰기·동일 본문 no-op·확정 버전 분기·현재 버전 복원 no-op·최근 수정 순서를 따른다. 근거는 버전별로 보존한다.

## 저장 응답으로 알 수 있는 범위

임시 저장 ACK에는 글·버전 번호·savedAt만 있다. `source`, 근거, 목록 STAR 상태, 카드 updatedAt을 추정하지 않는다. 상세 캐시에는 ACK로 확인한 글을 즉시 반영해 재조회 실패에도 글이 보이도록 하되 메타데이터는 조회 대기로 표시한다. 버전이 달라지면 모든 미확인 근거를 숨기고, 같은 버전은 변경된 칸의 근거만 숨긴다. 새 버전 판단은 버전 번호가 우선이며 동일 버전에서만 시각을 비교한다.

## 검증 방식과 한계

단위 검사는 멱등키 재전송·재진입·canonical 응답·StrictMode·직렬 저장·입력 보존·근거·이력·입력 상한을 확인한다. 기존 개발/정적 Mock E2E와 별도로 `npm run e2e:real`은 `VITE_API_MOCK=false`에서 HTTP 요청을 가로채 병합된 응답 형식으로 검증한다. 이는 실제 Spring/OAuth/DB 통합 검증을 대체하지 않는다. 운영 Vercel은 기존 Mock 체험 모드를 유지한다.

## 실제 연동 대기

카드 확정·재개·인터뷰 생성/답변·기본정보 수정은 프론트 기대 경로와 현재 병합된 controller 구현을 [BACKEND_CONTRACT](BACKEND_CONTRACT.md)에서 구분한다. 지원되지 않는 경로를 완료된 실제 연동으로 표시하지 않는다. 기업 매칭·RAG 및 후보 랭킹은 이번 계약 수정 범위 밖이다.
