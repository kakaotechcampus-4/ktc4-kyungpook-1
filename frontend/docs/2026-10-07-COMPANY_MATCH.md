# 기업·직무 매칭 · 자소서 초안 (프로토타입)

## 범위

프론트 화면 두 개를 **목 서버 위에** 만들었다. 서버·AI 구현과 DB 는 건드리지 않는다.

1. **직무 적합성** — `/match`(목록) · `/match/:id`(상세). 확정한 카드 근거가 기업·직무의 인재상을 얼마나 뒷받침하는지 보여준다.
2. **자소서 초안 생성** — `/cover-letter`(지원 대상·문항·카드 선택) · `/cover-letter/:id`(초안 보기·고치기).

PRD 7단계(기업 매칭)는 팀이 V1 범위에서 뺀 항목이다(`backend/ARCHITECTURE.md`). 그래서 **제안**이다 — 계약은
[BACKEND_CONTRACT.md "기업·직무 매칭 · 자소서 초안"](BACKEND_CONTRACT.md)에 미확정으로 적었고, 실서버 모드에서는
`matchSupported()` 가 꺼져 메뉴와 화면이 "서버 연동 대기"로 막힌다. 배포는 기존 Mock 체험 모드이며 실제 연동이 끝난 것으로 표시하지 않는다.

## 지킨 제품 원칙

- 확정한 카드만 근거이고, 그 안에서도 **행동·결과 칸 문장만** 근거다(상황·과제는 역량의 증거가 아니다). 근거 없는 인재상은 숨기지 않고 빈 칸 + "직접 작성해서 채우기".
- 퍼센트·점수 없음. A~D 를 "근거 충분/보통/적음/부족"으로 읽히게 했고, "합격 가능성이 아니다"를 배지 툴팁과 안내에 적었다.
- 기업 정보는 공개 출처 URL·확인일 필수, 만료는 목록·상세에서 제외. 체험 모드의 기업은 전부 가상(예시)이라고 화면에 밝힌다.
- 자소서 초안은 카드 문장(마스킹 적용)과 AI 연결 문장을 구분해 표시하고, 새 사실·수치를 만들지 않는다. 카드 문장이 마침표 없이 저장돼 있으면 문장 사이에만 마침표를 보정한다. 밖으로 나가는 글이라 연결 문장에는 앱 용어("확정한")나 의견("맞닿아 있다")을 넣지 않는다.
- 초안은 만든 시점의 스냅샷이다 — 쓴 카드가 바뀌면(특히 마스킹을 새로 건 경우) `stale` 로 알리고 "다시 만들어 주세요"라고 안내한다.
- 빈 칸을 둘로 나눈다: 확정 카드 어디에도 근거가 없는 인재상(`gaps`)과, 근거 카드는 있는데 이번에 고르지 않은 인재상(`notUsed`). 문구가 달라야 거짓 안내가 없다.
- 인재상 `3/4 근거 확보`는 근거가 있는 인재상의 개수(검증 가능한 사실)이고, 퍼센트·점수는 화면과 응답 어디에도 없다.
- **카드 한 장은 인재상 하나의 근거로만 센다.** 같은 카드가 여러 인재상에 보여도 등급은 "서로 다른 카드 기준" 개수로 매기고(`independentTagCount`), 충분(A)은 서로 다른 카드 3장이 받쳐 줄 때만 준다.
- 목록의 인재상 칩은 근거 있음(채운 칩) / 없음(점선 칩 + 아이콘 + 스크린리더용 이름)으로 구분한다.
- 지원 동기는 AI 가 대신 쓰지 않고 직접 쓸 칸(`SLOT`)으로 남긴다. 문항별 글자 수 제한(공백 포함)을 정하고, `현재 / 제한` 과 초과 분량을 보여 준다.
- 서버가 준 출처 URL 은 `http(s)` 만 링크로 만든다.

## 기존 디자인 재사용

새 CSS 는 모바일 내비 열 수 한 줄뿐이다. 목록은 `record-list` + `repo-row`, 필터는 `SearchField`/`Select`(#106), 근거 행은 `star-read__row`·`star-row__*`,
배지·`Chip`·`Note`·`EmptyState`·`StickyFooter`·`Breadcrumb`·`PageTitle` 를 그대로 썼다. 초안 편집은 카드 편집과 같은 `useDraftAutosave` +
`SaveStatus` + `useUnsavedChanges`, 중복 제출은 `useActionGate` 를 쓴다. `applyMask` 는 목 서버도 써야 해서 `StarBlock` 에서 `lib/mask.ts` 로 옮기고 `StarBlock` 이 다시 내보낸다(기존 import 유지).

모바일 하단 내비는 4칸 고정이던 그리드를 `grid-auto-flow: column` 으로 바꿔 항목 수만큼 균등 분할하고, "매칭"을 더해 5칸이 됐다(320px 에서 이름 표시·가로 넘침 없음을 검사한다).
자소서 메뉴는 모바일에서 매칭 목록·상세의 버튼으로 이어진다.

## 리뷰 반영 (10/10, 팀장 리뷰)

| 지적 | 반영 |
|---|---|
| 인재상 근거로 '상황' 문장이 쓰인다 | 근거는 행동(A)·결과(R) 칸에서만. 같은 카드의 둘 다 근거면 카드별로 묶어 보여 준다 |
| 같은 문장이 여러 인재상으로 세어져 카드 1~2장으로 "충분"이 나온다 | 등급을 "서로 다른 카드 기준"(최대 매칭)으로 계산, A 는 3개 이상 필요. 블루오션페이는 "충분"→"보통". 같은 카드가 여러 인재상에 쓰이면 상세에서 알려 준다 |
| 자소서 초안에 글자 수와 문항 구조가 없다 | 문항별 글자 수 제한 선택, `현재 / 제한`·초과 안내(편집 중 실시간). 지원 동기 문항에는 직접 쓸 칸(`SLOT`)을 두고 AI 가 지어내지 않는다 |
| 목록 칩이 모두 같은 모양이라 빈 인재상을 모른다 | 근거 없는 인재상을 점선 칩으로(`gapTags`), 인재상 전부 표시 |
| "확인일"이 모호하다 | "기업 정보 확인일" |
| 목록 아래 "자소서 초안 만들기"가 어느 기업 기준인지 모호하다 | "일반 자소서 만들기"로 바꾸고 설명을 붙였다(기업 기준 생성은 상세의 버튼) |

충돌(`responsive.css`·`README.md`, #115 머지 후)은 팀장 안내대로 V1 범위 결정 뒤에 develop 을 합쳐 해결한다.

## 검증 (Node 22)

- 타입체크·프로덕션 빌드 통과.
- 단위: 규칙(등급·서로 다른 카드 기준 계산·행동/결과 칸만 근거·만료 제외·확정 카드만·마스킹·초안 구성·SLOT·글자 수 제한·gaps/notUsed·stale·오류·edited 플래그·정렬·스키마 거절) 28개, 화면 동작(검색·필터·빈 상태·에러 재시도·근거/빈 칸·점선 칩·중복 카드 안내·링크 안전성·자동 추천·중복 제출·고치기 자동 저장·글자 수·초과 안내·지원 동기 칸·저장 실패·stale 안내·실서버 모드 차단) 37개, 카드 변경 시 캐시 무효화 3개, 기능 게이트 1개. 새 테스트는 수정을 일부러 되돌려 실제로 실패하는지 확인했다.
- 독립 리뷰에서 나온 지적(캐시 무효화 누락, 초안 stale, 빈 칸 문구, 의미 없던 "점수 없음" 테스트, 엔드포인트 방어선, 언마운트 후 이동, 외부로 나가는 문장의 앱 용어, 접근성 이름, 스키마 느슨함)을 반영했다.
- E2E: 목록(등급·점선 칩)→상세→초안→고치기→새로고침 유지, 글자 수 제한 초과 안내와 지원 동기 칸 채우기, 확정 카드 없음 안내, 320/390/768/1440px 가로 넘침·모바일 메뉴 5칸, 다크 대비.
