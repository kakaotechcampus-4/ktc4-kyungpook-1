# 인적사항 — 학력·경력·어학·자격증 (제안 · 서버 없음)

계약은 **제안(미확정)** 이다. 서버에는 이 API 가 없고, 화면은 이 문서와 Mock 으로 먼저 만들었다. 백엔드가 고치거나 거절해도 FE 는 `src/api/profile.ts` 한 곳만 맞추면 된다. 실서버 모드에서는 `VITE_PROFILE_ENABLED=true` 가 되기 전까지 어떤 요청도 보내지 않는다.

## 왜, 무엇을

- 팀 결정: 사용자가 학력·경력·어학·자격증을 등록한다. "처음 사이트 들어올 때 입력하게 하고 마이페이지에서 수정한다."
- 쓰임: 공고 매칭에서 **1차로 학력·자격 같은 단어로 거르고, 2차로 카드로 거른다.** 이 정보는 공고의 지원 자격을 견주는 **필터**일 뿐이고, 경험 카드·자소서 문장을 만드는 재료가 아니다.
- 지금 서버에는 이 정보를 담을 곳이 없다. `GET /api/me`(`MeView`)에도 필드가 없다.
- **`/api/activities` 와 다른 것이다.** 합치지 않았고 건드리지 않았다.

| | 인적사항 (이 문서) | 활동 `/api/activities` ([경험 카드 계약](2026-10-28-EXPERIENCE_CARDS.md)) |
|---|---|---|
| 무엇 | 학교·회사·어학 시험·자격증 같은 **사실 기록** | 동아리·대외활동·인턴 같은 **레포 밖 경험**을 묶는 상자 |
| 단위 | 사용자당 문서 하나, 통째로 교체 | 여러 개, 각각 만들고 고치고 지움 |
| 카드와 | 연결 없음 | 안에 경험 카드(`QUALITATIVE`)가 쌓임 |
| 쓰임 | 매칭 1차 거르기 | 카드 묶음·자소서 카드 고르기 |

## 화면 (FE, 만들어 둠)

| 어디 | 무엇 |
|---|---|
| `/settings/profile` | 학력·경력·어학·자격증 네 영역. 줄 추가·삭제, 월 입력, [저장] 한 번에 통째로 보낸다. 고친 채로 나가면 확인 창 |
| 마이페이지 | "인적사항" 줄(저장된 개수 요약) → 위 화면. 저장·보관 정보 목록에도 한 줄 |
| 홈 | 인적사항이 **비어 있고** "나중에"를 누르지 않았을 때만 안내 카드(입력하기 · 나중에). 마법사로 강제하지 않고, 불러오지 못하면 아무것도 그리지 않는다 |

- 모든 칸은 선택이다. 입력하지 않아도 다른 기능은 막히지 않는다.
- 자동 저장을 쓰지 않는다. 줄이 덜 채워진 문서는 서버가 받지 않으므로 중간 저장이 성립하지 않고, 개인정보를 입력이 멈출 때마다 보내지 않기 위해서다.
- "나중에"는 브라우저 `localStorage` 의 `gitory.profile-prompt.dismissed.{userId}` 에 `1` 만 적는다(값은 없고 사용자 id 로 구분). 저장소를 못 써도 화면은 닫힌다.

## API

| | 요청 | 응답 `data` |
|---|---|---|
| `GET /profile` | | `Profile`. **저장한 적이 없어도 200** + 빈 목록 네 개 + `updatedAt: null` |
| `PUT /profile` | `{ education, career, languages, certificates }` — **네 목록을 모두** 보낸다 | 저장된 `Profile`. 문서를 통째로 바꾼다 |

- `PUT` 은 **멱등**이다. 같은 내용을 다시 보내도 상태는 같고, 바뀐 것이 없으면 `updatedAt` 도 그대로다(앞뒤 공백 차이만 있는 본문도 같은 내용이다).
- 네 목록 중 하나라도 빠지면 400 이다. "빠졌으니 안 바꿈"으로 오해해 지워지거나 남는 일이 없게 한다. 모르는 키는 무시한다.
- 네 목록을 모두 `[]` 로 보내면 입력한 정보를 전부 지우는 것이다(별도 `DELETE` 는 두지 않았다).
- 쿼리 파라미터는 없다. 값은 URL 에 들어가지 않는다.
- 호출 제한(`RATE_LIMITED`)은 필요 없다. LLM 을 부르지 않는다.

**Profile**
```jsonc
{ "education": [{
    "school": "경북대학교",             // 1~50자, 필수
    "major": "컴퓨터학부",               // 1~50자, 필수
    "status": "ENROLLED|GRADUATED|LEAVE|DROPOUT|COMPLETED",   // 재학|졸업|휴학|중퇴|수료
    "startMonth": "2018-03",            // YYYY-MM, 필수
    "endMonth": "2022-02" | null }],    // 졸업·중퇴·수료는 필수, 재학·휴학은 null 가능(졸업 예정 월을 적어도 된다)
  "career": [{
    "company": "카카오", "role": "백엔드 개발",   // 각 1~50자, 필수
    "startMonth": "2022-03",
    "endMonth": "2024-05" | null }],     // null = 재직 중
  "languages": [{
    "name": "TOEIC",                     // 1~30자, 자유 글(TOEIC·OPIc·JLPT …)
    "score": "900",                      // 1~30자, 점수나 등급을 시험에 나온 그대로(900 · IH · N1 · Level 7)
    "acquiredMonth": "2021-08" }],
  "certificates": [{
    "name": "정보처리기사",               // 1~50자
    "issuer": "한국산업인력공단" | null,   // 0~50자, 비우면 null
    "acquiredMonth": "2021-11" }],
  "updatedAt": "ISO" | null }            // 한 번도 저장하지 않았으면 null
```

### 필드 규칙

| 항목 | 규칙 |
|---|---|
| 줄 수 | 목록마다 **최대 10개** (초과 → `TOO_MANY`, 경로는 목록 이름) |
| 글 | 앞뒤 공백을 지운 뒤 길이를 센다. 공백뿐이면 비어 있는 것(필수 칸은 `REQUIRED`, 선택 칸은 `null`). 공백 판정은 카드 글과 같다(`CardText`) |
| 모든 글 | U+0000 은 400 (`INVALID_CHARACTER`) |
| 길이 상한 | 학교·전공·회사·직무·자격증 이름·발급 기관 50자, 어학 시험·점수 30자 (초과 → `TOO_LONG`) |
| 월 | `YYYY-MM`. 형식이 틀리면 `INVALID_FORMAT`, 비어 있으면 `REQUIRED`, **1950년 이전**이면 `OUT_OF_RANGE` |
| 시작·취득 월 | 이번 달 **이후일 수 없다**(`OUT_OF_RANGE`). 경력의 종료 월도 같다 |
| 학력 종료 월 | 졸업 예정을 받으므로 **오늘부터 10년 뒤까지** 허용 |
| 종료 월 ≥ 시작 월 | 같은 달은 허용, 앞서면 `END_BEFORE_START`(경로는 `endMonth`) |
| 학력 `status` | 5개 값 외에는 `INVALID_VALUE`, 비어 있으면 `REQUIRED`. `GRADUATED`·`DROPOUT`·`COMPLETED` 인데 `endMonth` 가 null 이면 `REQUIRED` |
| 순서·중복 | 보낸 순서를 그대로 보존한다. 같은 내용의 줄도 막지 않는다(TOEIC 을 두 번 본 경우) |

"이번 달"은 서버의 `Asia/Seoul` 기준으로 정하길 제안한다. FE 는 브라우저 시간으로 먼저 검사하므로 월이 바뀌는 시각 근처에서는 한 달 어긋날 수 있다 — 서버 판정이 이긴다.

### 오류

| 상태 | 코드 | 언제 |
|---|---|---|
| 401 | `UNAUTHENTICATED` | 세션 없음 |
| 400 | `INVALID_REQUEST` | 위 규칙을 어김. `details.fields` 에 칸마다 하나씩 |

```jsonc
{ "data": null, "error": { "code": "INVALID_REQUEST", "message": "입력 내용을 확인해 주세요",
    "details": { "fields": [
      { "path": "education[0].school", "code": "REQUIRED" },
      { "path": "career[0].endMonth", "code": "END_BEFORE_START" } ] } } }
```

- `path` 는 `list[index].field` (목록 자체의 오류는 `languages` 처럼 목록 이름). `code` 는 `REQUIRED · TOO_LONG · INVALID_FORMAT · INVALID_VALUE · INVALID_CHARACTER · OUT_OF_RANGE · END_BEFORE_START · TOO_MANY`. 문구는 서버가 만들지 않는다 — FE 가 코드로 안내를 만든다.
- **오류 응답에 받은 값을 담지 않는다.** `path` 와 `code` 만 준다. 서버 로그에도 같다.
- 한 칸에는 오류 하나만 보낸다. 같은 줄의 다른 칸 오류는 같이 보낸다(한 번에 다 고칠 수 있게).
- `details.fields` 가 없거나 모양이 다르면 FE 는 칸 안내 없이 "입력 내용을 확인해 주세요"만 보인다. 400 으로 거절된 요청은 아무것도 저장하지 않는다.
- 서버 오류·연결 실패는 입력을 화면에 그대로 둔 채 [다시 저장]을 보인다.

## 개인정보 원칙 (이 기능의 전제)

학교·회사·점수는 개인정보다. 아래는 FE 가 지키고 시험으로 막아 둔 것이고, **BE 도 같이 지켜 주길 요청하는 것**이다.

1. **지표 이벤트에 값을 싣지 않는다.** `track()` 이벤트(`profile_prompt_accepted` · `profile_prompt_dismissed` · `profile_saved`)는 이름과 개수(`educationCount` …)만 보낸다. 문자열 값은 하나도 없다.
2. **로그에 남기지 않는다.** FE 는 인적사항을 `console` 에 쓰지 않는다. 서버도 `PUT /profile` 의 요청·응답 본문을 접근 로그·오류 로그·APM 에 남기지 않기를 요청한다(남긴다면 필드 마스킹).
3. **URL·쿼리스트링에 넣지 않는다.** 두 API 모두 쿼리가 없고, 화면 주소도 값을 담지 않는다. DOM id 도 값에서 만들지 않는다.
4. **인적사항으로 카드·자소서 문장을 지어내지 않는다.** 매칭에서는 1차 거르기에 쓰고, 자소서 AI 요청에는 **가려서 싣는다(팀 결정 10/29, #516·#531)**. 그래서 BE 에 요청한다: (a) AI 로 보내는 칸을 자소서 문항에 필요한 만큼으로 줄이기, (b) 모델 입력에 올릴 때 가리는 규칙(학교·회사 이름 등)과 프롬프트·로그에 값을 남기지 않기, (c) 사용자에게 알리는 문구 확정(아래 BE 결정 7). 이 문구가 정해지기 전까지 화면은 "공고 매칭에 쓰여요"만 말하고, AI 전달을 약속하거나 부인하지 않는다.
5. **브라우저에 오래 남기지 않는다.** 값은 메모리(React Query 캐시)에만 있고 `localStorage` 에는 "나중에" 표시만 쓴다. 로그아웃하면 캐시를 모두 비운다. 데모 모드에서는 이 탭의 `sessionStorage` 에만 저장되고 서버로 가지 않는다.
6. **자동완성에 넣지 않는다.** 입력칸은 `autocomplete="off"` 다.

## 백엔드가 정해야 할 것

FE 가 가정한 값이 있으면 같이 적었다. 정해지면 이 문서와 `BACKEND_CONTRACT.md` 의 제안 표시를 지운다.

1. **저장 방식** — 사용자당 한 행에 JSON(`profile`) 으로 둘지, 네 목록을 별도 테이블로 나눌지. 매칭이 필드별로 검색한다면 후자가 낫다. `PUT` 은 한 트랜잭션에서 통째로 교체하는 것으로 가정했다.
2. **1차 거르기가 무엇을 뭐와 견주는가(가장 큰 결정)** — 공고 조건의 어떤 단어(학력 수준·전공·자격증·어학)를 인적사항의 어느 칸과 견주는지, 같은 뜻의 다른 글(`컴퓨터공학` / `컴퓨터공학과` / `컴공`, `정보처리기사` / `정보처리 기사`)을 어떻게 같게 보는지. 학교·전공·자격증 이름은 지금 **자유 글**이라 정규화·사전이 없다. 사전을 서버가 줄 수 있으면 FE 는 입력 제안(자동 완성)으로 쓸 수 있다.
3. **학위 수준이 필요한가** — 지금 계약에는 학사·석사·박사·전문학사 구분이 없다. "석사 이상" 같은 조건을 거르려면 `degree` 칸이 있어야 한다. 추가하면 FE 가 선택칸 하나를 더한다.
4. **어학 점수의 구조** — `score` 는 자유 글(`900`, `IH`, `N1`)이다. "TOEIC 800 이상"을 서버가 숫자로 견주려면 시험별로 형식을 정하거나 `scoreValue`(숫자) 를 따로 받아야 한다.
5. **걸러진 결과가 어떻게 보이는가** — 미충족 공고를 목록에서 **빼는지 · 아래로 내리는지 · 표시만 하는지**, 그리고 매칭 응답(`MatchTarget`)에 어떤 모양으로 싣는지(예: 조건별 충족·미충족·모름). FE 는 지금 아무것도 가정하지 않는다. **입력하지 않은 사용자는 거르지 않는다**(모두 통과)고 제안한다 — 안 적었다고 공고가 사라지면 안 된다.
6. **보관·삭제·열람** — 보관 기간, 탈퇴 시 즉시 삭제(탈퇴 기능은 아직 "준비 중"), 백업에 남는 기간, 저장 시 암호화(컬럼·애플리케이션), 운영자 열람 권한, 제3자(공고 회사)에 넘기지 않음의 명시. 정해지면 마이페이지 "저장·보관 정보" 표의 한 줄(지금은 "보관")과 수집 목적 문구를 맞춘다.
7. **AI 로 보내는 범위와 고지** — 팀이 자소서 AI 요청에 프로필을 가려서 싣기로 정했다(#516, #531). 남은 결정: 어떤 칸을 보낼지, 가리는 규칙, 외부 LLM 전송·위탁 고지 문구. 정해지면 입력 화면 안내와 마이페이지 '저장·보관 정보' 표에 반영한다(지금은 매칭 사용만 적혀 있다). 이 결정이 FE 제안("넣지 않는다")을 대체한다.
8. **검증 규칙 확정** — 위 표의 상한(10개·50자·30자), 1950년 하한, 졸업 예정 10년, 끝난 상태의 종료 월 필수, 길이 단위(FE 는 JS 글자 수 = UTF-16), "이번 달"의 시간대. 이름·직무 등을 필수로 한 것도 제안이다(예: 검정고시처럼 전공이 없는 학력을 위해 `major` 를 선택으로 풀지).
9. **동시 저장** — 두 탭에서 고치면 마지막 저장이 이긴다(`PUT` 통째 교체). 막으려면 `updatedAt` 을 `If-Match` 로 받는 낙관적 잠금이 필요하다. FE 는 지금 쓰지 않는다.
10. **빈 문서와 "저장한 적 없음"** — 빈 `PUT` 이 처음 오면 문서를 만들지 않고 `updatedAt: null` 로 두는 것으로 Mock 을 만들었다. 홈 안내는 "네 목록이 모두 비었는가"로만 판단하므로 둘의 구분이 필요하지는 않다.
11. **요약을 `MeView` 에 넣을지** — 홈 안내가 한 번 더 `GET /profile` 을 부른다. `MeView` 에 `profileFilled: boolean` 하나만 있으면 호출을 줄일 수 있다. 값 자체는 `MeView` 에 넣지 않기를 제안한다.
12. **지표 이벤트 이름** — 서버가 이벤트 이름을 허용 목록으로 받는다면 세 개를 더해야 한다.
13. **켜는 시점** — 서버 구현과 계약 확정 뒤 `frontend/Dockerfile` 에 `ENV VITE_PROFILE_ENABLED=true` 를 더한다(`VITE_MATCH_ENABLED` 와 같은 방식). 지금은 더하지 않았다.

## 검증

- 단위: `profile-contract`(스키마 · 상한 · 월 규칙 · 켜짐 판단) · `profile-mock`(저장·멱등·400·초기화·스냅샷·옛 DB) · `profile-form`(줄 추가·삭제·10개 상한·검증 문구·저장·실패 시 입력 유지와 재시도·서버 칸 오류·나가기 확인) · `profile-prompt`(비어 있음·있음·닫음·저장소 막힘·실서버) · `profile-gating`(실서버에서 요청 0건) · `profile-privacy`(`track` 에 값 없음 · 실제 전송 본문 · URL · 콘솔 · 저장소 · 소스 검사).
- e2e(정적 빌드): 홈 안내 → 입력 → 저장 → 새로고침 유지 → 안내 사라짐 → 마이페이지 링크, "나중에", 저장 실패 후 재시도, 검증 안내, 나가기 확인, 10개 상한, 390·320px 가로 넘침·터치 크기, 다크 대비.
- 결과(Node 22): `tsc -b` 오류 없음 · 단위 62개 파일 515개 통과(이 작업 전 56개 파일 409개) · 정적 빌드 e2e 182개 통과(신규 12개 포함) · 실서버 모드 e2e 15개 통과(신규 1개 포함: 홈 안내·마이페이지 줄 없음, 직접 경로는 "준비 중", `/profile` 요청 0건).
- 새 시험이 핵심 동작을 실제로 잡는지 확인했다: 켜짐 판단을 항상 참으로, 안내가 비어 있지 않아도 보이게, "나중에" 기억을 빼기, 서버 검증을 건너뛰기, 멱등 비교를 빼기, 옛 데모 DB의 빈 값 기본을 빼기, `track()` 에 학교 이름 싣기, 값을 URL 에 넣기, 저장 실패 때 입력 지우기, 나가기 확인 끄기, 종료 월 순서 검사 빼기, 검증 없이 저장하기 — 각각 해당 시험이 실패했고 되돌린 뒤 파일이 원본과 같음을 `cmp` 로 확인했다.
- **확인하지 못한 것**: 실제 Spring 서버와의 연동(서버가 없다) · Safari·Firefox 데스크톱의 `type="month"`(달력이 없는 일반 입력으로 동작하고 형식은 안내 문구로 잡는다. 확인은 Chromium 만) · 실제 스크린리더 · 실서버 모드에서 Docker 빌드 값을 켠 상태.
