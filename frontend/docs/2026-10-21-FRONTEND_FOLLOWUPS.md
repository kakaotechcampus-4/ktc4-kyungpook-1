# 프론트 이슈 #332–335 후속 작업

1. 작업 목록은 RUNNING 우선, QUEUED는 시작 시각 오름차순으로 보여 준다. 대기 분석 앞에 실행 중 분석이 있을 때만 대기 이유를 표시한다. 초안과 분석의 큐 순번은 추측하지 않는다.
2. 후보 생성 응답과 완료 Job 결과의 cardIds를 Router state로 전달한다. 홈·목록에서 들어온 기존 카드 정렬은 유지한다.
3. 낮은 추천은 같은 목록 하단에서 기본 접는다. 검색 시 일치 항목을 자동으로 펼치며, 수동 선택·접기 후 선택·제외 복원 동작을 보존한다. 자동 추천 선택은 낮은 추천을 제외한다.
4. 요청 제한 RATE_LIMITED(429)는 GitHub Job 제한과 구분한다. 안전한 대기 시간만 안내하며 사용자의 입력과 선택을 유지하고 자동 재전송하지 않는다.

## 회귀 방지

- 기존 troubleshooting에 따라 후보 DOM 목록을 둘로 나누지 않았다.
- 공통 모바일 푸터의 레이아웃·여백은 그대로 사용한다.
- 서버 상태와 작업 결과를 추정하거나 API 필드·요청 본문을 바꾸지 않는다.
- #339 태그는 BE #338 뒤에 머지할 별도 PR로 분리한다.
- #222·#223·#224는 develop에 이미 구현된 경과 시간·재시도·사용된 후보 동작을 기존 테스트로 확인한다.
