## 1. 목표

> 자소서를 써야 하는 개발자 취준생은, 저장소 하나만 고르면 AI 가 커밋·PR·리뷰를 대신 읽어 **근거 커밋이 붙은 경험 카드**를 만들고, 그 카드로 **나와 맞는 공고**를 고르고 **그 공고에 낼 자소서 초안**까지 받는다.

1. 근거 링크 0개인 카드 문장이 화면에 한 건도 뜨지 않는다
2. 기여를 부풀리지 않는다 — 내 커밋 3개 / 팀 180개 저장소에서 "주도·전담·리드" 0회
3. 자소서 초안에 재료(카드·사용자 답·공고)에 없는 사실을 쓰지 않는다 — 재료에 없는 해석은 '추론' 으로 표시
4. 저장소당 확정 카드 평균 2장 이상 (⚠️ 운영 지표로 아직 못 잼)

### 서비스 경계

**`ai` 는 바깥(GitHub·모델)을 상대하고, `backend` 는 안(DB·세션·Job·규칙·검증)을 지킵니다.**

```
[web · React SPA]  ── Caddy 가 같은 주소로 제공 (/ = 화면, /api = Spring)
        │  REST { data, error } · 세션 쿠키 · CSRF
        ▼
[backend · Spring Boot]   DB · 세션 · GitHub 토큰(암호화) · Job 전부 여기 (공개 API 경로 58개)
   consent      GitHub 로그인(권한 `read:user` 하나) · 동의 · 토큰
   ingest       AI 가 올린 원본 저장 · 본인 기여 판정
   recommend    후보 점수 · 경험 후보 보드                        (LLM 안 부름)
   job          분석·카드 초안 Job · 재시도 · 멈춘 Job 정리
   card         카드 · 버전 · 근거 sha 확인 · 되묻기 · 자동 확정 · 활동   ★ 근거 검사는 여기
   profile      인적사항(학력·경력·어학·자격증) · 관심 분야
   matching     공고 가져오기 · 조건 저장 · 1단계 거르기 · 판단 저장 · 추천 · 모자란 조건 찾기
   coverletter  자소서 · 문항 · 카드 고르기 · 질문 · 초안 · 첨삭 · 대화
   agent        AI 서버 호출 어댑터 (다른 업무 모듈을 참조하지 않음)
   usage · audit   화면 사용 지표 · 감사 기록
        │  내부 REST · 내부 키 · GitHub 토큰은 헤더로만
        ▼
[ai · FastAPI]   포트를 밖에 열지 않음 (내부 API 29개)
   /internal/collect (+stream) · /collect/candidate-details        GitHub 수집
   /internal/analysis/groups (+stream) · /diff-evidence · /star (+stream)   경험 묶기 · diff 요약 · STAR 초안
   /internal/interview-turns · -answer-evaluations · -measured-sentence · -polished-sentence   되묻기
   /internal/card-themes                                            카드 기술 이름표
   /internal/job-postings/extract · /image-text                     공고 조건 뽑기 · 이미지 공고 글 옮기기
   /internal/matching/judgements · /gap-fill (+stream)              조건별 카드 판단 · 모자란 조건 찾기
   /internal/cover-letter-assignments · -questions · -drafts (+stream) · -polish · -turns · -fill   자소서
        ▼
[PostgreSQL]  [Redis — 호출 제한]
```

**이 구조에서 얻은 것**
1. **근거 검사를 AI 가 우회할 수 없다.** AI 는 근거 sha 를 주장만 하고, DB 를 가진 Spring 이 확인합니다. `ModuleBoundaryTest` 가 근거 확인 코드가 LLM 을 부르지 못하게 막습니다.
2. **GitHub 클라이언트가 한 벌이다.** 페이지네이션·한도 버그를 한 곳에서만 잡습니다.
3. **저장 책임이 한 곳이다.** AI 가 무상태라 트랜잭션·감사 기록이 갈라지지 않습니다. AI 판단(매칭 판단·자소서 단계)도 Spring 이 받아 저장하고, 화면은 저장된 값만 읽습니다.

### 매칭 — 코드가 거르고 AI 가 판단

```
① 1단계(코드, AI 없음)  관심 분야·학력·경력으로 공고를 거르고, 카드 기술 이름표와 공고 기술이 겹친 만큼 회사 순위
② 2단계(AI)            상위 회사 대표 공고의 필수·우대 조건마다 "이 조건을 채우는 카드"를 AI 가 고름 → match_judgement 저장
③ 보여 주기(코드)       공고 상세 "필수 4개 중 3개", 조건마다 채운 카드 · 레포 폴더 추천 기업 3곳 · 전체 추천 5곳
④ 모자란 조건(AI)       ✕ 조건마다 찾아볼지 정하고, 후보·작성 중 카드 → 내 공개 커밋 순으로 찾아 "이 후보로 카드 만들기" 등을 제안
```

- 등급(A~D)은 뺐습니다. 조건 수가 적은 공고는 A 가 너무 쉽게 나왔고(멘토 실측: 필수 1개 공고의 61%가 A), "필수 4개 중 3개" 가 더 구체적이라 목록·상세 모두 개수로 보여 줍니다(10/31 멘토 리뷰).
- AI 판단은 **공고를 열 때가 아니라** 카드가 확정되거나 사용자가 "맞춰 보기" 를 누를 때만 돌고, 결과를 저장해 다시 읽습니다. 확정 카드나 인적사항이 바뀌면 `stale` 로 표시합니다.

### 자소서 — 단계마다 사람이 볼 수 있게

```
공고에서 시작(선택) → 문항·지원 이유(필수)·강점 칩
→ 카드 고르기(AI, 문항마다)  → 재료 질문(AI, 모자란 것만) → 초안 쓰기(AI, 실시간) + 코드 검사
→ 첨삭(진단·고쳐 쓰기) · 대화로 재료 채우기 → 그 문항만 다시 쓰기
```

- 문항 유형(지원 동기·협업·문제 해결·성장 등)마다 보여 줄 행동 증거를 정해 두고, 재료가 보여 줄 수 있는 만큼만 씁니다. 재료가 없으면 빈칸을 남깁니다.
- 재료에 없는 해석(배운 점·판단 이유·포부)은 **추론 표시**(노란색)를 달고, 사용자가 확인·고치기·빼기를 고릅니다. 숫자·역할·사건·기술은 추론하지 않습니다.
- 지원 이유가 쓸 수 없는 글(지시문·공고 베낌·무관)이면 AI 가 판정해 지원 동기 칸을 비우고 대화에서 다시 묻습니다.

| 후보 | `candidate` `candidate_commit` `candidate_grouping` |
| 카드 | `card` `card_version` `card_statement` `statement_evidence` `card_slot_note` `card_draft_step` `card_material_answer` `interview_turn` `interview_option` `activity` |
| 인적사항 | `user_profile` |
| 매칭 | `job_posting_source` `job_posting` `job_posting_criterion` `match_judgement` `match_gap_fill` `repo_recommendation` `overall_recommendation` |
| 자소서 | `cover_letter` `cover_letter_question` `cover_letter_turn` |
| 운영 | `analysis_job` `ai_call` `usage_event` `audit_event` |

**핵심 결정**
1. **카드는 칸이 아니라 문장 단위로 저장한다.** "A 칸 3문장 중 2문장만 근거 있음"을 표현하려면 문장 하나가 행 하나여야 합니다.
2. **근거는 커밋 또는 되묻기 답 중 하나를 반드시 갖는다.** 커밋만 인정하면 정성 경험이 통째로 지워집니다. 둘 다 없는 문장은 화면에 뜨지 않습니다.
3. **AI 가 거친 단계를 행으로 남긴다.** 카드 초안(`card_draft_step` — 쓰기·검사·고쳐 쓰기·되돌림)과 자소서 단계를 저장해 화면에 "AI 가 한 일" 로 보여 줍니다. 사용자가 결과를 믿을지 판단할 재료입니다.
4. **AI 원본과 사용자 글을 따로 둔다.** 자소서 문항은 AI 원본(`aiText`)과 지금 글을 따로 저장해, 대화·첨삭으로 다시 써도 원본이 남습니다.

**지키는 규칙** — AI 초안 버전은 덮어쓰지 않고 새 버전으로 쌓는다 · 사용자 답은 원문을 남긴다(다듬기는 미리 보기 뒤 사용자가 고름) · GitHub 권한이 `read:user` 뿐이라 비공개 저장소는 읽지 못한다.

## 5. 인터페이스 원칙

- **값은 영문 대문자 enum, 한국어는 화면에서만.** 문구를 다듬다가 로직이 깨지지 않게 합니다.
- **`COMMIT_CLUSTER` 를 화면에서 "PR" 로 부르지 않는다.** 없던 PR 이 있었던 것처럼 보이면 그게 막으려던 실패입니다.
- **빈 결과는 에러가 아니다.** 후보 0개는 `200` + `verdict: "EMPTY"`, 근거 없어 비운 칸은 `200` + `droppedFields`, Job 실패는 `200` + `state: "FAILED"` 와 오류 코드.
- **오류 코드는 다시 시도 여부를 함께 준다.** 예: `AI_UNAVAILABLE`(retryable), `GITHUB_UNAUTHORIZED`(다시 연결), `COLLECTION_CAPPED`(일부만 읽음), `429 RATE_LIMITED` + `retryAfterSec`.
- **화면은 모르는 값에 멈추지 않는다.** 서버가 새 오류 코드·상태를 보내도 zod `.catch` 로 기본 오류로 보여 줍니다(#534, 멘토 리뷰).
- **계약이 코드와 어긋나면 시험이 실패한다.** OpenAPI 스냅샷 시험(BE·AI), `contracts/` 예시를 양쪽 시험이 읽음, 화면 지표 이름은 FE `track.ts` 와 BE 허용 목록을 시험이 대조.

## 8. 트레이드오프

1. **코드를 언제 얼마나 읽나** → **2단 읽기.** 후보를 만들 때는 커밋 메시지·PR 같은 메타데이터만 보고, 사용자가 고른 후보만 diff 까지 읽습니다.
2. **후보 묶기를 규칙으로 할까 LLM 으로 할까** → 규칙으로 거른 뒤 LLM 이 묶고 설명. LLM 이 번호를 빠뜨리거나 지어내면 코드가 단독 경험으로 살립니다.
3. **확정을 사람만 하나** → 9/1 에는 사람만 확정했으나, 매칭·자소서가 확정 카드만 재료로 쓰게 되면서 분석 직후 바로 쓸 수 있도록 **'확인 필요' 없이 네 칸이 다 찬 카드는 자동 확정**하고 확정 카드도 바로 고치게 바꿨습니다(#584). 대신 '확인 필요' 칸이 하나라도 있으면 확정하지 않습니다.
4. **정성 경험을 어디서 만드나** → **사용자 답에서만.** 코드만 읽고 "팀원을 설득했다"가 나오면 창작입니다.
5. **매칭을 임베딩으로 할까 AI 판단으로 할까** → **코드로 좁히고 AI 가 판단.** 임베딩은 빠르지만 한국어 조건 판단 정밀도가 0.15~0.42 였습니다. AI 판단은 느리고 비싸서 1단계 코드가 상위 회사만 넘기고, 결과를 저장해 다시 묻지 않습니다.
6. **자소서 문장까지 만드나** → 9/1 에는 대필 논란을 피하려 카드까지만이었으나, 10/25 멘토 피드백으로 **확정 카드를 재료로 한 초안**을 만듭니다. 대신 재료에 없는 해석은 추론 표시를 달고, 재료가 없으면 빈칸을 남깁니다.
7. **AI 를 백엔드에서 분리하나** → **분리.** 근거 검사가 서비스 경계로 강제됩니다.
8. **LangChain 같은 프레임워크를 쓰나** → **SDK 직접 사용.** 도구 호출이 추상화 뒤에 숨으면 "모델이 실제로 읽었나"를 보이기 어렵습니다.
9. **기다리는 동안 무엇을 보여 주나** → **AI 가 실제로 한 일.** 분석은 읽은 PR·커밋과 판단을, 카드·자소서는 칸마다 쓰는 글을 스트리밍으로 흘립니다. 가짜 진행 막대보다 결과를 믿을 근거가 됩니다.
