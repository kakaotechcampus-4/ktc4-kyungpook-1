# Gitory 전체 프론트엔드 반응형·UX 개선안

## 목적
로그인부터 경험 정리, 인터뷰, 카드 관리, 설정까지 기존 기능을 유지하면서 화면 폭을 효율적으로 쓰고 320px 모바일에서도 조작 가능한 UI로 개선한다.

## 확인한 문제
- `.main`의 최대 폭 1180px 때문에 넓은 화면에 불필요한 빈 공간이 남는다.
- 뒤에 로드되는 `layout-tio.css`가 `shell.css`의 모바일 단일 열 규칙을 덮어쓴다.
- 랜딩 헤더와 본문의 최대 폭이 달라 정렬선이 어긋난다.
- 모바일 메뉴는 활성 메뉴 외의 글자를 숨겨 의미를 아이콘에만 의존한다.
- 첫 화면의 권한 설명이 핵심 CTA와 예시 카드의 흐름을 끊는다.

## 설계
- 데스크톱은 고정 사이드바와 가용 폭을 채우는 작업 영역을 사용하되 긴 폼과 글은 읽기 폭을 제한한다.
- 태블릿은 축소된 레이아웃과 화면 성격에 맞는 1~2열을 사용한다.
- 모바일은 상단 브랜드와 하단 주요 내비게이션으로 나누고 모든 화면을 단일 열로 만든다.
- 랜딩은 헤더와 본문의 정렬선을 통일하고 가치 제안, 만료 안내, CTA, 예시 카드 순으로 보여준다. 상세 권한 안내는 접을 수 있게 한다.
- 기존 라우트, 데모 로그인, API 계약, 상태 전이 및 저장 동작은 변경하지 않는다.
- `.env`, 키, 토큰을 추가하거나 커밋하지 않는다.

## 화면별 기준
- 로그인: 320px에서 가로 스크롤 없이 CTA와 만료 안내가 첫 화면에 보인다.
- 홈·저장소·후보·카드 목록: 필터와 버튼이 줄바꿈되고 카드가 단일 열로 바뀐다.
- 분석·인터뷰·카드 상세: 보조 패널이 본문 아래로 이동하며 sticky 요소가 내용을 가리지 않는다.
- 설정·직접 작성·모달: 입력과 버튼이 전체 폭을 쓰며 모달은 뷰포트 안에서 스크롤된다.
- 데스크톱 1440px 이상에서는 작업 영역이 남는 폭을 채운다.

## 검증
- 기존 단위 테스트, 타입 검사, 빌드, E2E를 실행한다.
- Playwright로 320, 390, 768, 1024, 1440, 1920px에서 주요 라우트의 가로 넘침과 내비게이션을 검사한다.
- 로그인부터 카드 생성까지의 핵심 흐름과 오류·빈 상태를 유지한다.
- 대표 화면을 브라우저에서 데스크톱과 모바일로 확인한다.
