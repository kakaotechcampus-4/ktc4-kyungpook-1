# 공고 매칭: 기업별 보기와 기업 마크

## 왜
- 팀 요청: 매칭 화면에서 기업마다 따로 볼 수 있게(기업별로 보기).
- 멘토 피드백: 공고 목록에서 회사가 잘 안 보인다. 기업 로고 정도만 옆에 있어도 화면이 풍부하고 알아보기 쉽겠다.
- 백엔드 #556: 매칭 목록·상세에 `companyId`(같은 회사를 묶는 id)와 `logoUrl`(https 주소 또는 null)이 생겼다. 기업별 묶기와 기업 페이지는 `companyId` 기준으로, 기업 마크는 `logoUrl` 이미지로 바꿨다.
- 리뷰(성준 님): 목록 카드의 '근거 등급' 배지와 '필수 n/n · 우대 n/n' 줄을 뺀다. 판정 기준이 느슨해 경력 10년 이상 공고도 A 로 나왔고, 서버가 곧 목록의 AI 검색을 꺼서 목록의 `fit`·`met` 이 비어서 온다. 근거와 함께 볼 수 있는 상세의 '조건·근거 보기'는 그대로 둔다.

## 무엇이 달라졌나
- **기업 마크(`CompanyMark`)**: 공고 카드·상세 머리말·기업 페이지·기업 카드에서 기업 이름 옆에 둔다.
  - `logoUrl` 이 https 이면 `<img>` 로 그린다. 이름은 옆에 글로 항상 있으니 이미지는 장식이다(`alt=""`·`aria-hidden`). `loading="lazy"`, `decoding="async"`, `referrerPolicy="no-referrer"`(방문한 쪽 주소를 로고 서버로 보내지 않는다), 고정 `width`·`height`(이미지가 오고 가도 레이아웃이 흔들리지 않는다).
  - 불러오지 못하면(`onError`) 이니셜로 되돌린다. 실패한 주소는 기억해 다시 그리지 않고, 다른 주소가 오면 새로 시도한다.
  - `logoUrl` 이 없거나(null) https 가 아니면 이니셜이다. 이름의 첫 글자(법인 표기 `(주)`·`㈜`·`주식회사`는 건너뜀, 영문은 대문자)를 이름에서 정해지는 색 위에 그린다. 색은 기존 토큰(`--matcha-*`·`--caution-*`·`--danger-*`·`--ink-*`)을 바탕색에 섞은 8가지이고, 글자는 항상 `--text-primary`다(라이트·다크 모두 대비 7.0:1 이상, 측정은 아래). 색만으로 구분하지 않는다: 이니셜 글자와 옆의 기업 이름이 함께 있다.
  - 로고는 흰 바탕을 가정하고 만들어지므로 다크 모드에서도 흰 칸(`--ink-0`) 위에 `object-fit: contain` 으로 올린다.
  - 이미지 주소는 화면에 그릴 때만 쓴다. 분석 이벤트(`track`)·주소창·로그에 넣지 않는다(시험이 막는다). CSP 는 없다(`frontend/vercel.json`, `deploy/Caddyfile` 에 CSP 헤더가 없다)라 외부 이미지가 불러와진다.
- **기업으로 묶기**: `companyId` 가 있으면 그것으로 묶는다(표기가 달라도 같은 회사). `companyId` 가 없는 응답(구서버·목)일 때만 이름 정규화(`companyKey`)로 묶는다. 두 기준은 접두어(`id:`·`name:`)로 나눠 우연히 같은 글자여도 부딪히지 않고, id 가 있는 공고와 없는 공고를 한 묶음에 섞지 않는다. 묶음의 이름은 이름이 있는 첫 공고의 표기, 로고는 로고가 있는 첫 공고의 주소다.
- **기업 페이지 `/match/company/:companyId`**: 조각은 `encodeURIComponent` 로 만든다(로켓펀치 출처 `rocketpunch:회사이름` 의 `:`·한글, `/ ? # %`, 공백 포함). 라우터가 한 번 풀어 준 값을 그대로 쓰고 다시 풀지 않는다("100%" 같은 값이 깨지지 않게). 그 기업의 공고 카드(목록과 같은 `PostingCard`), 공고 수, "← 공고 목록"(기업별에서 왔으면 "← 기업 목록") 링크를 보인다.
  - 이름으로 만들던 옛 주소(`/match/company/나래랩스`)로 들어와도 같은 기업을 찾는다: 먼저 `companyId` 로 찾고, 없으면 이름으로 찾는다(묶음 안의 어느 표기든, 공백·대소문자·전각 차이 무시). 이름이 서로 다른 두 기업에 걸리면 어느 쪽인지 알 수 없어 고르지 않는다. 못 찾으면 "찾지 못했어요" 안내와 전체 공고 링크를 보인다. "모두 보기" 같은 이 화면의 링크는 옛 주소여도 `companyId` 주소로 이어진다.
- **목록 카드에서 등급을 뺐다**: 공고 카드(`PostingCard`, 공고별 보기와 기업 페이지가 같이 쓴다)에서 '근거 등급' 배지와 '필수·우대 n/n' 줄을 지웠다. 기업별 보기의 기업 카드와 기업 페이지 머리말에서도 '최고 등급'을 지웠다. 이들도 목록 단계의 등급이라 같은 이유다. 상세 화면은 그대로다(등급 칩, 필수·우대 `met / total개 근거 연결`, 조건별 근거). 목록 카드는 `fit`·`required`·`preferred` 를 아예 읽지 않으므로 서버가 비워 보내도(null, 0) 화면이 같고 아무것도 지어 보이지 않는다.
- **기업 순서**: 공고 많은 순 → 이름(가나다) 순이고, 이름 없는 묶음은 맨 뒤다. 등급이 아니라 서버가 준 사실로만 정한다.
- **공고별 / 기업별 전환**: 목록 위의 토글. 값은 `?view=company`로 주소에 담긴다(없으면 공고별). 기업별 보기는 기업마다 카드 하나: 마크·이름·공고 수·대표 직무(최대 3개, 더 있으면 "외 N건"). 기존 검색·경력·직무 필터는 그대로 적용된다(필터를 통과한 공고만 묶는다).
- **기업 이름 링크**: 목록 카드와 상세 머리말의 기업 이름이 기업 페이지로 가는 링크다. 카드 전체는 여전히 공고 상세로 가고(제목 링크를 카드 크기로 펼친다), 기업 이름만 그 위에 얹은 별도 링크다. 링크 안에 링크를 두지 않으려고 카드를 `<a>`로 감싸지 않게 바꿨다.
- **쿼리 이어 가기**: 목록의 `q`·`category`·`experience`·`sort`·`view`는 상세·기업 페이지 링크에 그대로 붙고, 돌아오는 링크도 같은 쿼리로 간다. 기업 페이지는 목록과 같은 검색·필터를 받아 같은 기준으로 거른다(기업별 카드의 "공고 N건"과 기업 페이지의 N이 어긋나지 않게). 걸러져 숨은 공고가 있으면 "N건 중 M건만 보여요"와 필터만 푸는 링크("이 기업 공고 모두 보기")를 둔다. 정렬과 보기 방식은 푼 뒤에도 남는다.

## 설계 결정
- 공고 목록 API 응답 하나로 모두 그린다(`useMatches` 캐시 공유, 기업 페이지용 추가 요청 없음). AI 조회 비용 때문에 쓰는 기존 정책(자동 재조회 없음)도 그대로다. `GET /api/matches?companyId=` 는 아직 쓰지 않는다(이유는 아래 "백엔드에 요청할 것").
- 스키마(`MatchTarget`): `companyId`·`logoUrl` 은 구서버·목에 없어도, 값이 이상해도 목록 전체를 못 받게 하지 않는다. 없거나 이상하면 둘 다 null 이다. `companyId` 는 문자열이 아니거나 공백뿐이면 null(이름으로 묶는다), 아니면 서버 값 그대로(다듬지 않는다). `logoUrl` 은 https 만 받는다(`http:`·`javascript:`·`data:`·`//`·주소에 적힌 계정 정보는 null). 제품 원칙 "링크·이미지 주소는 https 만"이다. `CompanyMark` 도 같은 규칙(`isHttpsUrl`)으로 한 번 더 거른다.
- 접근성: 마크는 `aria-hidden`(기업 이름은 항상 글로 있다), 토글은 `aria-pressed` 버튼 그룹, 모바일 터치 대상 44px 이상(토글·카드 안 기업 링크), 색만으로 구분하지 않는다.
- 실서버 모드에서 매칭 API가 꺼져 있으면(`matchSupported()`가 false) 기업 페이지도 `MatchUnavailable`을 보이고 목록을 요청하지 않는다.
- 새 코드는 새 파일에 두고 `MatchListPage`는 연결만 바꿨다: `CompanyMark.tsx`, `PostingCard.tsx`(목록 카드 추출), `CompanyList.tsx`(토글·기업 카드), `CompanyPage.tsx`, `model.ts`의 기업별 도우미, `styles/match-company.css`.
- 목(데모): 예시 JSON 은 서버와 같은 모양을 지키는 문서라 건드리지 않고, `mock/matching.ts` 가 `companyId`(5곳)와 `logoUrl`(가온소프트만 https, 나머지 null)을 얹는다. 로고 주소는 지어낸 예시 호스트(`logo.example.com`)라 데모에서는 이미지 요청이 실패해 이니셜이 보인다. 이미지가 오는 화면은 브라우저 시험이 그 호스트를 가로채 확인한다. 같은 회사 다른 표기·로켓펀치 id 같은 경우는 시험용 목록(`src/test/match-company-fixtures.ts`)에 있다.

## 한계
- 같은 회사가 다른 표기로 오면(`companyId` 는 같고 `company` 가 다름) 이름은 묶음 안에서 처음 나온 표기를 쓴다. 공고 카드의 이니셜·색은 그 카드의 `company` 로 정해져서 로고가 없으면 같은 기업이어도 카드마다 다를 수 있다(로고가 있으면 같다).
- `companyId` 가 없는 응답에서는 예전처럼 이름으로 묶는다. 앞뒤·중복 공백, 대소문자, 전각/호환 문자 차이는 같은 기업으로 보지만 `(주)카카오`와 `카카오`는 다른 기업으로 남는다(다른 기업을 잘못 합치는 쪽이 더 나쁘다).
- 로켓펀치 출처의 `companyId`(`rocketpunch:회사이름`)는 회사 이름이 바뀌면 같이 바뀐다. 이전 이름으로 저장한 기업 페이지 주소는 이름이 옛 이름과 맞는 공고가 없으면 "찾지 못했어요"가 된다.
- 기업 페이지·기업별 보기는 이미 받은 목록 안에서만 묶는다. 서버가 목록을 나눠 주기(더 보기 등)로 바뀌면 기업 페이지는 받은 범위의 공고만 보인다. 그때는 `?companyId=` 로 한 기업만 받는 쪽이 맞다.
- 기업별 보기에서 "공고 정렬"은 기업 안의 공고 순서에만 쓰이고, 기업 순서는 항상 공고 많은 순 → 이름이다.
- 데모(목) 데이터는 기업마다 공고가 1건이라 기업 페이지가 한 장만 보인다. 여러 공고가 있는 경우는 단위 테스트로 확인했다.
- 이름·id 가 `.`·`..`뿐인 기업은 브라우저가 경로를 줄여 기업 페이지로 갈 수 없다(실제 기업명·id 에는 없다고 보고 처리하지 않았다).
- 이름·id 에 짝 잃은 서로게이트(이모지가 반쯤 잘려 온 글자)가 있으면 `encodeURIComponent` 가 던져 목록 전체가 그려지지 않으므로, 묶는 기준(`companyKey`·`groupKey`)과 주소(`companyPath`)에서만 대체 문자(U+FFFD)로 바꾼다. 화면에 보이는 이름은 서버 값 그대로다.
- 이니셜 마크의 색 배정(`companyTone`)은 해시를 바꾸면 기업마다 색이 바뀐다. 단위 테스트가 데모 기업 5곳의 색을 고정해 둔다.
- 남은 곳(이 PR 에서 건드리지 않은 `MatchListPage` 의 등급 관련 문구): 공고 정렬의 "근거 등급 순"과 기본 정렬(`sort=fit`), 소개 문구의 "등급은 조건마다 근거로 이어진 확정 카드가 많을수록 높아요(A가 가장 높음)", 모든 공고의 `fit` 이 null 일 때 뜨는 "확정한 카드가 없어요" 안내. 서버가 목록의 `fit` 을 비워 보내면 마지막 것은 확정 카드가 있는 사람에게도 항상 뜬다.

## 백엔드에 요청할 것
성준 님 질문("응답에 더 필요한 칸이 있으면 알려 주세요")에 대한 프론트 답이다. 지금 반영한 칸(`companyId`·`logoUrl`)만으로 화면은 돌아간다. 아래는 필요가 생기면 답을 달라는 것이다.

- **`GET /api/matches?companyId=` 는 지금은 쓰지 않는 쪽을 제안한다.** 프론트는 목록을 한 번 받아 기업별 보기·기업 페이지·상세 이동이 같은 캐시를 쓰고, 검색·필터·정렬은 화면에서 한다(바꿀 때마다 서버에 다시 물으면 매칭을 다시 계산하기 때문). 서버가 목록의 AI 검색을 끄면 목록 한 번 받는 비용이 작아져 기업 페이지만 따로 받을 이유가 줄어든다. 기업 페이지용으로 따로 받으면 기업별 보기의 "공고 N건"과 기업 페이지의 N 이 어긋나지 않게 캐시 키·필터를 따로 맞춰야 한다. 목록이 커져 나눠 주기(더 보기)로 바뀌거나, 기업 페이지만 열 때 목록 전체가 부담스러울 때 그때 `?companyId=` 로 바꾸겠다. 쿼리 자체는 계약에 남겨 둬도 좋다.
- **마감일**: 목록 카드가 등급을 빼면서 마감이 카드의 유일한 판단 값이 된다. ① `source.expiresAt` 이 null 일 때 "상시 채용"과 "마감일을 읽지 못함"이 구분되는지 알려 달라(지금 화면은 null 이면 "상시 채용"이라고 쓴다). 둘이 섞여 있으면 별도 칸이나 값이 필요하다. ② 서버가 목록을 마감 가까운 순(상시는 뒤)으로 정렬해 주는 규칙이 확정되면 계약서의 정렬 문장에 그대로 적어 달라. 프론트의 기본 정렬을 서버 순서와 맞추려고 한다.
- **목록의 `fit`·`met`**: 비어 올 때 칸을 없애지 말고 `fit: null`, `required.met`/`preferred.met` 0 으로 보내 달라. 프론트 스키마는 `required`·`preferred` 를 필수로 받아서, 칸이 빠지면 목록 전체가 계약 오류가 된다(목록 카드는 이 값을 읽지 않지만 스키마는 읽는다). 칸을 없앨 계획이면 알려 달라, 같이 고친다.
- **`companyId` 안정성**: 로켓펀치의 `rocketpunch:회사이름` 은 이름 표기가 바뀌면 id 가 바뀌어 저장해 둔 기업 페이지 주소가 깨진다. 안정적인 id 로 바꿀 수 있으면 좋고, 어렵다면 지금처럼 두자. 값에 `.`·`..` 만 있는 id 는 주소에서 줄어들어 쓸 수 없다.
- **대표 이름 칸(선택)**: 같은 `companyId` 인데 `company` 표기가 공고마다 다를 수 있다. 프론트는 이름이 있는 첫 공고의 표기를 쓴다. 대표 표기를 정해 주는 칸(예: `companyName`)이 있으면 화면마다 이름이 흔들리지 않는다. 지금 표기 차이가 실제로 생기는지부터 알려 주면 된다.
- **로고 파일**: 가로로 긴 로고도 정사각 칸 안에 비율을 지켜 넣는다(`contain`). 표시 크기가 최대 56px 이라 원본이 가로 112px 이상이면 선명하다. 로고 호스트가 Referer 로 막아도 되도록 프론트는 `no-referrer` 로 불러온다. 앞으로 CSP 를 넣게 되면 `img-src` 에 로고 호스트(Greenhouse·그리팅 CDN)가 필요하니 호스트 목록을 알려 달라.
