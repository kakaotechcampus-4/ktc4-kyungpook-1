# 카드 삭제 — #351

## 범위와 화면 결정

- 최신 develop 7f8cff3에서 시작했다. #261 UX 정리와 별도 PR이며 백엔드 삭제 API #369는 이미 병합됐다.
- 사용자가 불필요한 카드를 삭제하고 목록에서 검토를 이어가는 것이 핵심 과업이다.
- 목록·홈의 X는 항상 표시한다. hover에만 숨기면 터치·키보드 사용자가 발견하기 어렵다. 44px 영역과 카드 제목을 포함한 접근성 이름을 제공한다.
- X는 카드 링크의 형제다. 링크 안에 버튼을 넣지 않아 삭제 클릭이 상세 이동으로 이어지지 않는다. 삭제 자리만큼 출처 줄 공간을 확보한다.
- 상세는 카드 검토 영역 아래에서 같은 삭제 확인창을 사용한다. 제목·되돌릴 수 없음·확정 카드의 매칭 제외·후보 재사용 안내만 표시한다.
- 삭제 버튼에 강한 경고색을 쓰고 취소를 함께 제공한다. 요청 중 중복 제출·Escape·바깥 클릭으로 닫기를 막는다.

## API와 상태

`DELETE /api/cards/{id}` → 200 `{ data: { ok: true }, error: null }`이다. 공통 API 클라이언트의 세션·CSRF 처리를 재사용하고 재시도는 자동으로 하지 않는다.

- 404: 다른 탭에서 이미 삭제된 카드로 보고 목록·상세 캐시를 정리한다.
- 409 INVALID_STATE: 생성 중임을 안내하고 카드·확인창을 유지한다.
- 네트워크/서버 실패: 현재 카드를 유지하고 사용자 재시도만 허용한다.
- 성공 후 상세에서는 replace로 목록으로 돌아간다. 목록·홈에서는 해당 카드가 사라진다.
- 삭제 전 시작된 카드·저장소/후보·사용자·매칭 조회를 취소한 다음 카드 상세/버전 캐시 제거, 카드 목록 재조회, 저장소/후보/사용자 무효화, 매칭 캐시 초기화를 한다. 늦은 응답이 삭제 전 통계를 다시 저장하지 않게 한다.
- Mock도 활성 초안 Job 409, 후보 NEW 복구, 되묻기 기록 제거, 재조회 404를 재현한다. 화면에서 Mock을 직접 읽지 않는다.

## 트러블슈팅과 회귀 범위

독립 리뷰에서 카드 조회만 취소하면 비활성 저장소 조회가 늦게 완료되어 무효화 표시를 지우는 경쟁을 확인했다. 지연된 조회로 실패를 재현한 후 관련 조회 가족을 모두 취소하도록 수정했다.

기존 카드 링크·태그·이전/다음 이동·STAR/하단 정렬을 보존한다. 백엔드·AI·운영 설정은 변경하지 않는다. #261과 병합 가능 여부도 확인한다.

## 확인할 항목

- 단위: 삭제/후보 복구, 생성 중 거부, 캐시 정리·404 복구, 늦은 조회, 취소, 중복 클릭·Escape 보호.
- 정적 빌드: 320/390/768/1440px × light/dark, 목록 취소·키보드 삭제, 확정 상세 삭제·목록 이동, 기존 카드 정렬/내비게이션.
- Mock을 끈 HTTP 계약: 200/404/409/503, 실제 DELETE 경로, 요청 1회, 실패 시 내용 보존. 운영 Spring에 쓰는 검사가 아니다.
