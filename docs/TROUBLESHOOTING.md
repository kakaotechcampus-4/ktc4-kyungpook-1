# Frontend troubleshooting

## 2026-09-23 — 저장 실패·동시 요청과 화면 이탈

기존 `flush()`가 PATCH 오류를 삼키고 성공처럼 반환해 저장 버튼이 화면을 닫았다. 첫 직접 작성은 비동기 setCardId 직후 이전 렌더의 빈 ID로 PATCH할 수 있었다. 공통 직렬 저장 훅, 반환된 cardId ref, 성공 boolean을 이용한 이탈 조건으로 수정했다.

리뷰에서 뒤로가기 후 오래된 캐시가 다시 편집 폼에 들어가 저장 내용을 덮는 경로를 발견했다. 모든 성공 저장에서 exact card cache를 갱신하고, 배경 조회 실패가 작성 중 폼을 제거하지 않도록 초기 로드 실패와 분리했다. 전체 CardPage 회귀 테스트로 확인한다.

## 2026-09-23 — Job 오류가 성공 화면으로 이동

status 0을 제외한 모든 조회 오류를 후보 보드로 보내던 코드를 제거했다. 404/5xx/계약 오류는 조회 실패 화면으로 남고 분석 재실행과 조회 재시도를 구분한다. 비용이 발생하는 mutation은 자동 재시도하지 않는다.

## 2026-09-23 — Mock이 실제 실패를 가림

선택형 시나리오 모듈을 추가했다. 첫 저장 실패, 접수 후 응답 유실, 409 충돌, null/긴 제목, 빈 목록, 느린 응답을 같은 API 계약으로 재현한다. 자세한 방법은 [FRONTEND_RESILIENCE.md](../frontend/docs/FRONTEND_RESILIENCE.md)를 참고한다.
