# UI 조작·정렬 일관성 개선

## 적용 범위
사용자가 첨부한 검색 겹테두리, 과한 원형 필터, OS 기본 선택 메뉴, PC 홈 좌우 정렬, STAR 입력 들여쓰기와 제목 굵기를 공통 컴포넌트/토큰에서 수정한다. 모바일에서 보기만 좋은 상태가 아니라 검색 지우기, 키보드 선택, 긴 메뉴 스크롤, 한글 조합 취소와 작성 포커스까지 확인한다.

## 시작 상태와 재현
- 최신 develop 8125917에서 새 codex/ui-controls-consistency branch를 만들었다. #61은 이미 머지됐으므로 팀에는 새 PR을 만든다. 개인 저장소는 기존 #1에 동기화한다.
- 기존 Node 22 단위 108개가 통과했다. 신규 UI 브라우저 검사 7개를 변경 전 실행해 모두 실패를 확인했다.
- PC 홈 입력의 왼쪽은 이어쓰기에서 16px 어긋나고 최대 620px에 멈췄다. 홈/목록 제목은 800/700과 서로 다른 tracking이었다.
- 전역 포커스 shadow·outline·컨테이너 outline이 겹쳤다. 필터는 999px chip radius를 물려받고 native select 메뉴가 OS 스타일로 표시됐다.
- STAR textarea는 아이콘과 같은 행의 grow 안에 있어 아이콘 너비만큼 들여써졌다.

## 공통 규칙
- SearchField/Select/Button은 radius 10px, 최소 조작 높이 44px, control weight 500을 공유한다. 상태 배지·라디오·프로필의 모양은 역할에 맞게 유지한다.
- SearchField는 포커스 경계를 하나만 표시하며 지우기/Escape 뒤 입력 포커스를 유지한다. 한글 조합 중 Escape는 쿼리를 지우거나 기본 조합 취소를 막지 않는다.
- Radix Select 2.3.8을 얇은 controlled wrapper로 사용한다. 기존 enum/레포 빈 값은 콜백과 API에 그대로 전달한다. 전용 import로 필요한 페이지에서만 코드를 불러온다.
- STAR 제목과 본문을 공유 row/editor로 분리하고 textarea/문장/근거를 STAR 글자와 같은 시작선에 둔다. 원문·줄바꿈·ref·길이 제한·저장 콜백은 유지한다.
- Pretendard dynamic subset 1.3.9는 기존 폰트를 사용한다. body 400, control 500, heading 600과 -0.03em을 사용하며 코드/SHA/단일 STAR 글자는 tracking을 분리한다.
- 스크롤 기능은 유지하고 테마에 맞는 얇은 scrollbar를 사용한다. responsive.css는 마지막 화면별 배치 책임을 유지한다.

### 검사 준비 상태

Radix는 키보드 선택 포커스와 외부 pointer listener를 예약해서 설치한다. 메뉴가 보인다는 조건만으로 즉시 외부 클릭한 정적 검사는 반복 5회 실패했다. trigger/option 포커스를 확인하고 다음 animation frame에서 외부 클릭하도록 검사 준비 상태를 보완했고 같은 검사가 10회 연속 통과했다. 실제 외부 클릭 닫힘·선택 유지·포커스 복귀 assertion은 그대로 유지한다. 구현에 임의 대기를 추가하거나 테스트 재시도로 넘기지 않는다.

### 화면 재확인

1. 카드 목록에서 검색 입력·지우기·Escape를 누른다. 한글 조합 중 Escape는 입력을 보존한다.
2. 카드/저장소 정렬·필터를 키보드와 포인터로 선택한다. Escape/외부 클릭 뒤 trigger로 포커스가 돌아오는지 확인한다.
3. PC 홈의 이어쓰기와 새 경험 정리 좌우 경계를 비교한다. 모바일에서 자동완성을 조작한다.
4. 직접 작성·본문 편집·마스킹·인터뷰의 STAR 제목/본문 시작선을 확인한다. 원문과 줄바꿈을 저장 후 다시 연다.
5. 320px 긴 레포 메뉴에서 끝 항목까지 이동한다. 첫 임시 저장 뒤 레포 선택이 잠기는지 확인한다.
6. 두 테마에서 설정·목록·작성의 제목 굵기와 얇은 스크롤바를 확인한다.

## 범위 보호
