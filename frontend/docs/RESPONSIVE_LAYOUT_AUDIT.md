# 모바일·PC 배치 점검 (2026-09-26)

## 기준
320/390px 모바일, 768/1024px 태블릿, 1440/1920px PC를 검증한다. 기존 API·저장·선택 동작은 유지한다. 레이아웃 책임은 마지막에 로드되는 responsive.css에 모은다.

## 실화면에서 확인한 문제와 조치
| 화면 | 문제 | 수정 방향 |
|---|---|---|
| 직접 작성 | 기간/레포 필드 폭이 고정되어 모바일에서 들쭉날쭉. PC 저장 버튼은 본문 전체 폭. | 이름 있는 메타데이터 grid, 모바일 제목 1행 + 기간/레포 2열. 저장 상태·조건·버튼을 하나의 줄 그룹으로. |
| 홈 | 제목 안의 flex 때문에 문장 조각 사이가 벌어짐. 이어쓰기 제목이 모바일에서 STAR에 밀리고 PC에서는 과하게 긴 행. | 제목을 일반 문장으로, PC 이어쓰기 2열/모바일 제목 우선 2행 배치. |
| 설정 | 고정 폭 kv와 모바일 강제 전체 폭이 충돌하여 상태 배지가 새 줄에 떨어짐. | 정보·설명·상태를 명시적으로 묶고 모바일 grid로 배치. 중복 요금제 안내 제거. |
| 공통 안내 | 모바일 제목과 내용이 좁은 두 열로 분리됨. | 모바일 안내는 제목 위, 내용 아래. |
| 모달 | 짧은 높이 PC/가로 화면에서 하단 행동이 뷰포트를 벗어날 수 있음. | 모든 폭에서 뷰포트 최대 높이 제한, 본문만 스크롤, 제목·하단 행동 고정. |
| 상세·목록 | 긴 제목 옆 행동이 제목을 압축. 검색·선택 컨트롤 높이와 정렬선 불일치. | 헤더 그룹 분리, 줄바꿈 허용, 최소 터치 높이와 정렬 통일. |
| 하단 행동 | 모바일 메뉴와 sticky footer의 높이 값이 다르고 본문 읽기 영역을 크게 차지함. | 동일 메뉴 높이 토큰, 간격 축소, 마지막 입력/행 스크롤 접근 검증. |

## 확인 방법
반응형 E2E에 필드 정렬·버튼 폭·안내문 읽기 폭·가로 화면 모달·하단 입력 접근 검사를 추가한다. 단순 페이지 overflow 뿐 아니라 요소 경계와 중첩을 확인한다. 애니메이션 중간 프레임은 화면 오류로 오판하지 않도록 완전히 로드한 후 촬영한다.

## 검증 결과
- 11개 주요 화면의 390/1440px 스크린샷 22장 점검, 브라우저 런타임 오류 없음.
- 타입 검사와 단위 테스트 70개 통과.
- 프로덕션 빌드와 정적 E2E 40개 통과(신규 배치 검사 5개 포함).
- 320/390/768/1024/1440/1920px 주요 화면 및 844×390 모달 검증.
- 별도 읽기 전용 코드 리뷰에서 공통 footer 소비 화면, 모달 스크롤, 입력 접근성·DOM 읽기 순서를 확인했고 중요한 회귀 없음.
