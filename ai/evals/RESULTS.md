# AI 품질 평가 결과

AI 작업마다 무엇을 어떻게 쟀고, 결과를 보고 무엇을 바꿨는지 모은 표다. 자세한 방법은 각 줄의 문서에 있다.
새 평가를 하면 맨 아래에 한 줄을 더하고, 같은 평가를 다시 재면 그 줄의 날짜와 숫자를 고친다.

## 평가마다 덧붙임

### LLM 모델 선택 · 카드 비용
- 방법과 숫자는 [MODEL_SELECTION_REPORT.md](MODEL_SELECTION_REPORT.md), [REPOSITORY_COST_MEASUREMENT.md](REPOSITORY_COST_MEASUREMENT.md).
- Opus·Fable 은 구조화 출력 계약을 어겨 비용을 끝까지 재지 못했다.
- 운영 키는 `gpt-5.6-luna` 만 허용한다. 다른 모델을 견주려면 그 모델을 허용한 키가 필요하다.

### 매칭
- 거리 상한은 [JOB_MATCHING_EVALUATION.md](JOB_MATCHING_EVALUATION.md), 한국어 평가는 [JOB_MATCHING_KOREAN_EVALUATION.md](JOB_MATCHING_KOREAN_EVALUATION.md).
- 한국어 평가에서 지금 모델은 한국어 오답이 정답보다 더 가까워서(상위 10개 안 거리 중앙값 오답 0.16 · 정답 0.65) 거리 상한만 바꿔서는 나아지지 않는다.
- 가장 좋은 모델도 조건 정밀도가 0.42 라, 근거 화면은 공고 원문 인용을 함께 보여 준다.

### STAR 초안
- 표본은 우리 저장소의 PR 이고, 같은 PR 에 프롬프트만 바꿔 카드를 만든 뒤 어느 프롬프트인지 가린 채로 칸마다 채점했다. 채점 항목은 단정 · 확인 안 된 것 안 씀 · 바꿈과 만듦 구분 · R 동사 · R 이 A 를 되풀이하지 않음 · 근거 충실도 등이다.
- 10-20 에는 보강 규칙을 더 고친 판(A 결정 이유 1.13)도 견줬지만, R 이 A 를 되풀이하지 않은 칸이 첫 판보다 20%p 넘게 떨어져 미리 정한 기준을 넘지 못해 넣지 않았다.
- 쓰기 규칙을 넣은 뒤 카드 한 장 비용은 약 0.7원, STAR 지연은 약 1.2초 늘었다.
- 남은 것: 뜻이 뒤집힌 칸(고치기 전 상태를 반대로 옮김)이 아직 4칸 남았다.

### 지시 주입
- 방법과 작업별 표는 [docs/GUARDRAILS.md](../../docs/GUARDRAILS.md) 3절.
- 작업마다 사례가 3~4개뿐이라 '막아 낸다' 는 증거라기보다 지금 프롬프트와 모델의 기본 동작을 확인한 값이다. 프롬프트나 모델을 바꾸면 다시 잰다.

### 경험 그룹화 — PR 없는 저장소
- 개인 저장소는 PR 없이 커밋만 있는 경우가 많아, 이때 경험 그룹화가 같은 일을 한 커밋끼리 묶는지 쟀다. 정답은 실제 PR 묶음이다.
- '같이 묶은 것이 같은 PR 인 비율' 이 26% 로 낮은 것은 대부분 같은 기능의 PR 여러 개를 한 경험으로 묶었기 때문이다(예: 공고 가져오기 PR 4개, E2E PR 4개). 경험 기준으로는 맞는 묶음이라 PR 기준 점수가 실제보다 낮게 나온다.
- 남은 것: 한 경험이 커밋 16개 · PR 5개까지 커져 카드 한 장으로 넓은 경우가 있고, 같은 PR 이 여러 경험으로 쪼개진 경우가 5건이다. 우리 커밋 메시지는 `feat:`·`fix:` 형식이라, 짧은 메시지('fix', 'update')를 쓰는 저장소는 따로 재야 한다.
- LLM 은 `gpt-5.6-luna` 로 한 번 불렀다(묶기 단계만).

### STAR 초안 — 출력 상한
- 상한에는 모델이 생각하는 토큰도 들어가, 2,000 일 때 성공한 호출도 상위 5% 가 1,642 · 최대 1,948 토큰을 썼다. 상한을 넘은 입력도 다시 돌리면 됐다(생각 길이가 매번 다르다).
- 2,000 을 넘으면 응답을 스트리밍으로 받는다. 스트리밍 도중 끊긴 연결은 #553 에서 다시 시도할 수 있는 실패로 바꿨다.
- 측정 코드는 develop 기준(PR 본문 1,000자, 고쳐 쓰기 없음)이다. 쓴 토큰만 비용이 들어 상한을 올려도 카드당 비용은 그대로다.

### 되묻기 판단 이유
- 표본은 직접 쓴 가상 카드라 다른 사람의 글이 없다. 사용자 답은 Spring 이 근거 신뢰도 HIGH 로 보내므로, 신뢰도가 아니라 답 내용으로 다시 물을지 판단해야 맞는다.
- 처음 판은 이유 40개 중 8개가 칸을 S·T·A·R 글자로 부르고 1개가 '신뢰도' 같은 입력 속 말을 써서, 칸을 '상황, 맡은 일, 행동, 결과'로 부르고 쉼표로 잇게 고쳤다(화면은 가운뎃점을 쓰지 않는다).
- 모델은 5.6 Luna 를 유지한다. 같은 세트에서 6 Luna 는 다 찬 카드를 3번 더 물었고(끝냄 17/20), Haiku 5.5 는 다시 물음 14/20 · 끝냄 12/20 이었다.
