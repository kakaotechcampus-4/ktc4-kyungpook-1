# Gitory 조용한 목록형 UI 개선안

## 목적
기존 반응형 동작과 기능을 유지하면서 프로필, 경험 목록, STAR 상태, 배지와 컨테이너의 시각 규칙을 통일한다. 작은 네모와 중첩 카드의 반복을 줄이고 콘텐츠 사이 간격을 넉넉하게 만들어 빠르게 읽히는 화면을 만든다.

## 선택한 방향
시각 비교안 중 A안인 `조용한 목록`을 사용한다. 경험 여러 개를 하나의 표면에 묶고 각 경험은 테두리 카드 대신 충분한 여백과 얇은 구분선으로 나눈다. 사용자는 추가 확인 없이 이 방향으로 전체 화면 개선, 양쪽 PR 갱신, 재배포까지 진행하도록 요청했다.

## 공통 시각 규칙
- 페이지의 큰 섹션 간격은 32px, 관련 요소 묶음은 20–24px, 작은 메타데이터는 8–12px을 기본으로 한다.
- 표면은 섹션당 한 번만 사용한다. 표면 안의 행과 정보 블록에는 별도 그림자나 둥근 외곽선을 반복하지 않는다.
- 테두리는 입력, 선택 상태, 위험 상태, 모달처럼 경계를 알아야 하는 요소에만 사용한다.
- 상태 배지는 `작성 중`, `확정`, `확인 필요`처럼 판단에 필요한 것만 남긴다. 종류, 날짜, 근거 수는 일반 메타 텍스트로 표현한다.
- 아이콘을 다시 네모 상자에 넣는 패턴을 줄이고 의미가 필요한 경우 아이콘 자체와 텍스트를 함께 사용한다.
- 모바일과 데스크톱 모두 기존 breakpoint와 가로 넘침 방지 규칙을 유지한다.

## GitHub 프로필
- `UserAvatar` 공통 컴포넌트를 만들고 사이드바, 모바일 헤더, 마이페이지, GitHub 설정에서 사용한다.
- 데모 사용자는 저장소 내부의 로컬 SVG 프로필 샘플을 사용해 네트워크 없이 항상 이미지가 표시되게 한다.
- 실제 `avatarUrl`이 없거나 이미지 로딩에 실패하면 사용자 아이디의 첫 글자를 표시한다.
- 아바타 크기는 28, 36, 48, 64px 네 단계만 사용하고 원형, 테두리, 배경 처리 규칙을 통일한다.

## STAR 표시
- 목록용 STAR는 `S/T/A/R` 네 칸을 동일한 너비의 그리드로 배치한다.
- 각 칸은 알파벳과 `상황/과제/행동/결과` 라벨을 같은 기준선에 표시한다.
- 채움, 확인 필요, 비어 있음은 배경색과 테두리 차이로 구분하되 네 칸의 크기와 위치는 바뀌지 않는다.
- 카드 상세의 큰 STAR 섹션은 기존 내용과 근거 연결을 유지하되 키와 제목의 시작선을 통일한다.
- 스크린리더용 `STAR 채움` 설명과 각 필드 상태는 유지한다.

## 경험 목록
- 홈과 카드 목록은 `experience-list` 표면 하나 안에 경험 행을 배치한다.
- 데스크톱에서는 가용 폭에 따라 2열을 사용하되 각 열의 제목, 메타, STAR 시작선이 일치한다.
- 모바일에서는 한 열로 바꾸고 행 간 세로 간격을 20px 이상 유지한다.
- hover와 focus는 행 전체의 옅은 배경으로 표현하며 위치 이동 애니메이션과 큰 그림자는 제거한다.
- 목록 상단 필터는 작은 네모 배지 여러 개 대신 텍스트 탭과 하나의 활성 표시로 단순화한다.

## 다른 화면의 컨테이너 정리
- 저장소, 후보, 설정, 분석 단계는 바깥 섹션 표면과 내부 카드가 중첩된 곳부터 내부 테두리와 그림자를 제거한다.
- 입력과 CTA는 현재 형태를 유지해 조작 가능성을 보존한다.
- 오류, 경고, 선택 상태는 기존 신호색과 구분을 유지한다.
- 랜딩 예시 카드는 제품 설명에 필요한 한 장이므로 유지하되 내부 행의 중첩된 네모와 작은 배지를 줄인다.

## 데이터와 오류 처리
- API 및 스키마는 바꾸지 않는다. 프로필 표시만 `avatarUrl`, `login`을 받아 렌더링한다.
- 이미지 오류는 컴포넌트 내부 상태로 처리하고 동일 크기의 이니셜 fallback으로 교체한다.
- 데모 아바타는 앱의 public 자산으로 포함하며 `.env`나 외부 인증정보를 사용하지 않는다.

## 검증
- 아바타 URL 존재, 없음, 로딩 실패 시나리오를 컴포넌트 테스트로 확인한다.
- STAR 네 칸의 순서, 라벨, 상태 클래스, 접근성 문구를 단위 테스트로 확인한다.
- Playwright에서 홈과 카드 목록의 묶음 수, 행 구분, 불필요한 개별 그림자 제거를 확인한다.
- 320, 390, 768, 1024, 1440, 1920px 전체 라우트의 가로 넘침 검사를 유지한다.
- 타입 검사, Vitest, 빌드, 개발·정적 E2E를 실행하고 대표 모바일·PC 화면을 시각 확인한다.

## 배포와 PR
- 개인 저장소 `TaeHuiKKIM/gitory-web` PR #1과 팀 저장소 `kakaotechcampus-4/ktc4-kyungpook-1` PR #6에 동일한 UI 변경을 반영한다.
- 두 저장소에 `.env`, 토큰, API 키를 커밋하지 않는다.
- 검증된 개인 저장소 커밋으로 `gitory-prototypes` 프로덕션을 재배포하고 운영 도메인을 확인한다.

## 자체 검토
구현 범위, 간격 수치, 공통 컴포넌트, fallback, 상태 표현, 반응형 검증과 배포 대상을 명시했다. 미정 항목이나 기존 API 계약을 변경하는 요구는 없다.
