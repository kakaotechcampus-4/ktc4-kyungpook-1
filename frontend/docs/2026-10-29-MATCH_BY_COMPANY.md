# 공고 매칭: 기업별 보기와 기업 마크

## 왜
- 팀 요청: 매칭 화면에서 기업마다 따로 볼 수 있게(기업별로 보기).
- 멘토 피드백: 공고 목록에서 회사가 잘 안 보인다. 기업 로고 정도만 옆에 있어도 화면이 풍부하고 알아보기 쉽겠다.

## 무엇이 달라졌나
- **기업 마크(`CompanyMark`)**: 공고 카드와 공고 상세 머리말에서 기업 이름 옆에 이니셜 마크를 둔다. 이름의 첫 글자(법인 표기 `(주)`·`㈜`·`주식회사`는 건너뜀, 영문은 대문자)를 이름에서 정해지는 색 위에 그린다. 같은 기업은 언제나 같은 글자·색이다. 색은 기존 토큰(`--matcha-*`·`--caution-*`·`--danger-*`·`--ink-*`)을 바탕색에 섞은 8가지이고, 글자는 항상 `--text-primary`다(라이트·다크 모두 대비 7.0:1 이상, 측정은 아래).
- **공고별 / 기업별 전환**: 목록 위의 토글. 값은 `?view=company`로 주소에 담긴다(없으면 공고별). 기업별 보기는 기업마다 카드 하나: 마크·이름·공고 수·최고 등급·대표 직무(최대 3개, 더 있으면 "외 N건"). 기업은 최고 등급 → 이름 순이다. 기존 검색·경력·직무 필터는 그대로 적용된다(필터를 통과한 공고만 묶는다).
- **기업 페이지 `/match/company/:company`**: 이름은 URL 인코딩. 그 기업의 공고 카드(목록과 같은 `PostingCard`), 공고 수, 최고 등급, "← 공고 목록"(기업별에서 왔으면 "← 기업 목록") 링크. 목록에 없는 기업은 "찾지 못했어요" 안내와 전체 공고 링크를 보인다.
- **기업 이름 링크**: 목록 카드와 상세 머리말의 기업 이름이 기업 페이지로 가는 링크다. 카드 전체는 여전히 공고 상세로 가고(제목 링크를 카드 크기로 펼친다), 기업 이름만 그 위에 얹은 별도 링크다. 링크 안에 링크를 두지 않으려고 카드를 `<a>`로 감싸지 않게 바꿨다.
- **쿼리 이어 가기**: 목록의 `q`·`category`·`experience`·`sort`·`view`는 상세·기업 페이지 링크에 그대로 붙고, 돌아오는 링크도 같은 쿼리로 간다. 기업 페이지는 목록과 같은 검색·필터를 받아 같은 기준으로 거른다(기업별 카드의 "공고 N건"과 기업 페이지의 N이 어긋나지 않게). 걸러져 숨은 공고가 있으면 "N건 중 M건만 보여요"와 필터만 푸는 링크("이 기업 공고 모두 보기")를 둔다. 정렬과 보기 방식은 푼 뒤에도 남는다.

## 설계 결정
- 공고 목록 API 응답 하나로 모두 그린다(`useMatches` 캐시 공유, 기업 페이지용 추가 요청 없음). AI 조회 비용 때문에 쓰는 기존 정책(자동 재조회 없음)도 그대로다.
- **평가 전(null)은 D가 아니다.** 한 기업의 최고 등급은 null을 건너뛰고 구한다. 전부 null이면 최고 등급은 null이고 "카드를 확정하면 등급이 나와요"를 보인다. 기업 정렬에서도 평가 전 기업은 D보다 뒤다.
- 등급은 서버 값 그대로이고 비율·점수는 만들지 않는다.
- 접근성: 마크는 `aria-hidden`(기업 이름은 항상 글로 있다), 토글은 `aria-pressed` 버튼 그룹, 모바일 터치 대상 44px 이상(토글·카드 안 기업 링크), 색만으로 구분하지 않는다.
- 실서버 모드에서 매칭 API가 꺼져 있으면(`matchSupported()`가 false) 기업 페이지도 `MatchUnavailable`을 보이고 목록을 요청하지 않는다.
- 새 코드는 새 파일에 두고 `MatchListPage`는 연결만 바꿨다: `CompanyMark.tsx`, `PostingCard.tsx`(목록 카드 추출), `CompanyList.tsx`(토글·기업 카드), `CompanyPage.tsx`, `model.ts`의 기업별 도우미, `styles/match-company.css`.

## 한계
- **진짜 기업 로고는 아직 못 쓴다.** API(`MatchTargetResponse`)에 기업 id도 로고 필드도 없다. 그래서 이니셜 마크이고, 로고를 지어내거나 외부 주소를 끌어다 쓰지 않는다. 로고는 백엔드가 `companyId`와 로고 주소(예: `logoUrl`, https만)를 주면 `CompanyMark`가 이미지로 바꾸고 실패 시 이니셜로 되돌리면 된다.
- 기업은 `company` 문자열로 묶는다. 앞뒤·중복 공백, 대소문자, 전각/호환 문자 차이는 같은 기업으로 보지만 `(주)카카오`와 `카카오`는 다른 기업으로 남는다(다른 기업을 잘못 합치는 쪽이 더 나쁘다). 동명이인 기업이나 표기 흔들림은 기업 id가 있어야 정확해진다.
- 기업 페이지·기업별 보기는 이미 받은 목록 안에서만 묶는다. 서버가 목록을 나눠 주기(더 보기 등)로 바뀌면 기업 페이지는 받은 범위의 공고만 보인다. 기업 단위 조회는 서버가 해 줘야 한다.
- 기업별 보기에서 "공고 정렬"은 기업 안의 공고 순서에만 쓰이고, 기업 순서는 항상 최고 등급 → 이름이다.
- 데모(목) 데이터는 기업마다 공고가 1건이라 기업 페이지가 한 장만 보인다. 여러 공고가 있는 경우는 단위 테스트로 확인했다.
- 이름이 `.`·`..`뿐인 기업은 브라우저가 경로를 줄여 기업 페이지로 갈 수 없다(실제 기업명에는 없다고 보고 처리하지 않았다).
- 이니셜 마크의 색 배정(`companyTone`)은 해시를 바꾸면 기업마다 색이 바뀐다. 단위 테스트가 데모 기업 5곳의 색을 고정해 둔다.
