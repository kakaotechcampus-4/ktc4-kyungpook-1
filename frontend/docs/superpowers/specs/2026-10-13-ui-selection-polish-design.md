# 후보 선택과 화면 정렬 개선

기준 develop `441b7fa`, 별도 브랜치 `codex/ui-selection-polish`. #192 리뷰 2건 승인·병합을 확인하고 시작한다. 사용자 승인 없이 진행하라는 기존 요청과 정해진 색감·간격 원칙을 유지한다.

## 확인한 문제
- 후보/커밋 체크박스는 18×18px이며 제목 첫 줄과 세로 기준이 다르다.
- 후보 헤더에서 출처·제목·상태·제외 버튼이 같은 flex 줄에 섞여 길이에 따라 배치가 바뀐다.
- 모바일 커밋 목록은 고정 SHA 폭과 별도 메시지 열 때문에 읽는 폭이 좁다.
- 후보 검색창 폭과 도구 버튼·작은 링크의 조작 영역을 함께 점검한다. 홈/레포/카드/작성/답변/설정/회상/탈퇴/로그인을 1440·390·320px에서 확인한다.

## 설계
1. 공통 Check는 44×44px 조작 영역 안에 20px 표시를 두고 SVG 체크·hover·focus-visible·disabled·강제 색상 상태를 지원한다. 기존 role/aria-checked/label/한 번만 변경/키보드 동작을 유지한다.
2. 후보 행은 선택 열·본문 열로 정렬하고 제목/행동 헤더와 출처/상태 줄을 분리한다. 사용됨·낮은 추천도·선택·제외·복원 상태의 의미를 유지한다. 커밋 상세는 별도 전체 폭 영역으로 확장한다.
3. 커밋은 체크·본문·GitHub 링크 세 열을 사용하고 SHA/상태는 본문 안에 배치한다. 고정 SHA 열을 없애며 긴 경로는 끊어서 표시한다. 부모 후보 선택과 하위 버튼/링크의 조작을 분리한다.
4. 후보 검색과 도구 행은 여유 있는 폭·44px 조작 크기를 사용한다. 다른 화면에서 발견한 공통 문제만 근거와 함께 수정한다. 이미 정렬된 화면은 유지한다.

## 제약과 검증
API·enum·선택 집합·서버 저장·멱등키·폴링·읽기 복구 동작은 변경하지 않는다. 새 의존성 없음. 모바일/PC·라이트/다크·320px·긴 제목·긴 커밋·상태·키보드·이벤트 전파를 검증한다. 단위/브라우저 회귀에서 크기·정렬·조작과 실제 저장 동작을 확인한다. 문서/README·PR·리뷰어·개인 동기화·배포 결과를 남기며 민감 파일은 올리지 않는다.
