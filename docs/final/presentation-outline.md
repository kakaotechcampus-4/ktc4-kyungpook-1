## 1. 표지 — 0:15

**화면** — Gitory 로고 · "커밋과 PR을 자소서 경험으로" · 카카오테크 캠퍼스 4기 경북대 1팀 · 팀원 6명

**말** — "안녕하세요, 경북대 1팀입니다. 개발자의 GitHub 기록을 자소서 경험으로 바꾸는 Gitory 를 소개하겠습니다."

## 2. 문제 — 0:45

**화면**
- 밤 11시, "협업 중 갈등을 해결한 경험을 쓰시오" 앞에서 GitHub 과 옛 카톡방을 30분째 뒤지는 장면(그림 한 장)
- 구직자 67% "자기소개서 작성이 가장 어렵다"(잡코리아 1,011명)
- 인터뷰 6명 — 프로젝트당 30분~1시간을 **기억을 되짚는 데** 씀

**말** — "개발자 취준생은 자소서를 쓸 때마다 흩어진 커밋과 PR 에서 자기 경험을 처음부터 다시 찾습니다. 글쓰기 도우미는 이미 많습니다. 부족한 건 글이 아니라 **근거** 입니다."

## 3. 해결 한 장 — 0:40

**화면** — 흐름 한 줄
`저장소 고르기 → 경험 후보 → 근거가 붙은 STAR 카드 → 비어 있는 칸만 되묻기 → 나와 맞는 공고 → 그 공고의 자소서 초안`

**말** — "저장소 하나만 고르면 AI 가 내 커밋·PR·리뷰를 읽고 경험별로 묶어, 문장마다 근거 커밋이 붙은 카드를 만듭니다. 그 카드로 맞는 공고를 고르고 자소서 초안까지 이어집니다. 직접 보여 드리겠습니다."

## 4. 데모 — 4:00

[데모 시나리오](demo-scenario.md) 대로. 화면 전환만 하고 슬라이드는 띄우지 않습니다.

## 5. AI 는 어디까지 판단하나 — 0:50

**화면** — 세 줄 표

| AI 가 판단 | 코드가 막음 | 사람이 정함 |
| --- | --- | --- |
| 경험 묶기·추천 이유 · STAR 초안과 근거 주장 · 되묻기 다음 칸·끝내기 · 공고 조건마다 맞는 카드 · 모자란 조건 찾기 · 자소서 카드 고르기·쓰기·첨삭 | 내 기여만 남기기 · 근거 커밋 실제 확인 · 근거 없는 문장 지우기 · 출처 없는 숫자 '확인 필요' · 되묻기 상한 · 매칭 1단계 거르기 · 호출 제한 | 어떤 후보를 카드로 · 확인 필요 칸 · 자소서 지원 이유 · 추론 문장 확인 |

**말** — "AI 는 여러 도구를 엮어 스스로 다음 단계를 고릅니다. 되묻기에서는 어느 칸을 더 물을지, 언제 끝낼지를 AI 가 정하고, 매칭에서는 모자란 조건을 내 기록에서 다시 찾아 무엇을 할지 제안합니다. 대신 **틀리면 안 되는 것은 코드가** 막고, 내가 책임질 문장은 사람이 정합니다."

## 6. 그럴듯한 거짓말을 막는 법 — 0:50

**화면** — 장치 네 개
1. **근거 두 번 확인** — AI 는 "이 문장의 근거는 커밋 a3f21c" 라고 주장만, DB 를 가진 서버가 확인
2. **근거 없으면 비움** — "근거를 찾지 못해 비워 두었습니다" (데모 4번 장면)
3. **추론 표시** — 자소서에서 재료에 없는 해석은 노란색, 사람이 확인
4. **지시 주입** — 커밋·공고 속 "이전 지시를 무시하라" 84개 사례, 모델이 따른 것 **0**

**말** — "가장 겁나는 실패는 그럴듯한 거짓말입니다. 내 커밋 3개인 팀 프로젝트에서 '프로젝트를 주도했다' 가 나오면 면접에서 무너집니다. 그래서 근거 검사는 AI 가 아니라 코드가 하고, 모듈 경계 시험이 근거 코드가 LLM 을 부르지 못하게 막습니다."

## 7. 재 본 것 — 0:50

**화면** — 숫자 다섯 개 (큰 글씨)

| | |
| --- | --- |
| 카드 한 장 | **3.12원 · 12.8초** (실패 0/100) |
| 자소서 한 편 | **20.7원** · 재료 없는 문항은 빈칸 6/6 · 지어낸 숫자 0 |
| 매칭 조건 판단 | 정밀도 임베딩 0.15~0.42 → **AI 판단 0.87** |
| 레포 수집 | **174초 → 80초**, GitHub 요청 절반 |
| 평가 | 29가지 · 잘 될 유형이 아니라 **안 될 유형부터** |

**말** — "기능마다 무엇을 어떻게 쟀는지 결과표에 남겼습니다. 매칭은 처음 임베딩 검색으로 했는데 한국어 공고에서 정밀도가 0.15 밖에 안 나와, 코드로 좁히고 AI 가 조건마다 판단하게 바꿨습니다. 잰 결과를 보고 바꾼 것이 결과표 한 줄마다 있습니다."

## 8. 구조와 운영 — 0:40

**화면** — 시스템 구성도(`docs/images/architecture/system-architecture.svg`, 매칭·자소서 반영 필요) + 숫자 한 줄
- React · Spring Boot · FastAPI · PostgreSQL, EC2 한 대에 Docker Compose, develop 머지마다 자동 배포
- 시험 BE 3,575 · AI 1,253 · FE 1,467 · E2E 348 — 머지 전 CI 필수

**말** — "AI 서버는 DB 없이 바깥(GitHub·모델)만 상대하고, 저장과 검증은 Spring 이 맡습니다. 그래서 AI 가 근거 검사를 건너뛸 수 없습니다. 10월 5일부터 실제 서버에 올려 매 머지마다 배포했습니다."

## 9. 못 한 것과 다음 — 0:30

**화면**
- ⚠️ 실제 사용자 지표 — 운영 사용자가 팀·멘토 위주라 "시간이 줄었다" 를 숫자로 못 보임
- 🟡 자동 확정 — 문제 없는 카드는 자동 확정, 사용자 확인을 어디까지 둘지
- ⚠️ 서버 한 대 · 백업이 같은 서버 안

**말** — "아직 실제 사용자 수치로 시간을 줄였다고 말할 수는 없습니다. 다음은 캠퍼스 수강생들의 실제 저장소로 확정 카드 수와 걸린 시간을 재는 것입니다."

## 10. 마무리 — 0:15

**말** — "Gitory 는 채울 수 있어서가 아니라 근거가 있을 때만 씁니다. 감사합니다."

## 예상 질문

| 질문 | 답 초안 |
| --- | --- |
| ChatGPT 에 커밋을 붙여넣으면 되지 않나? | 1회성 질문이면 답은 나옵니다. 우리는 ① 수백 개 커밋에서 내 기여만 골라 묶기 ② 문장마다 근거 커밋과 서버 확인 ③ 코드 문장과 사용자 답을 나눠 저장 ④ 공고·자소서까지 잇기를 합니다 |
| 왜 Agentic 인가? | 무엇이 경험인지(묶기), 어느 칸을 더 물을지·언제 끝낼지(되묻기), 모자란 조건을 어디서 찾을지(매칭)를 AI 가 정하고, 수집·diff 분석·공고 판단 도구를 여러 단계로 엮습니다 |
| 자동 확정은 사람 확인을 건너뛰는 것 아닌가? | '확인 필요' 칸이 하나도 없고 네 칸이 다 찬 카드만 자동 확정하고, 확정 카드도 바로 고칠 수 있습니다. 자소서에서는 카드 고르기를 사용자가 바꾸고, 추론 문장은 사용자가 확인합니다 |
| 자소서 대필 아닌가? | 확정한 카드·사용자 답·공고만 재료로 쓰고, 재료가 없으면 빈칸을 남깁니다. 재료에 없는 해석은 추론 표시를 달아 사용자가 정합니다 |
| 비용은? | 카드 초안 한 장 3.12원, 자소서 한 편 20.7원(Luna). 매칭 판단은 저장해 다시 묻지 않고, 사용자별 1분·하루 호출 제한이 있습니다 ([확인 필요] 운영 서버에서 `RATE_LIMIT_ENABLED` 를 켰는지) |
| 비공개 저장소는? | 권한을 `read:user` 하나만 받아 공개 저장소만 읽습니다. 쓰기 권한도 받지 않습니다 |
| 평가를 팀이 직접 판정했는데 믿을 수 있나? | 정답을 AI 값을 가리고 만들고, 갈린 것은 누가 붙였는지 가리고 다시 판정했습니다. 판정자가 팀 밖 사람은 아니라는 한계는 있습니다 |
