## 한 줄 이야기

**"저장소 하나를 골랐더니, 근거가 붙은 경험 카드가 생기고, 나와 맞는 공고가 뜨고, 그 공고에 낼 자소서 초안까지 나온다."**

데모 내내 보여 줄 것은 하나입니다 — **AI 가 무엇을 읽고 무엇을 판단했는지 화면에 남는다.** 그래서 기다리는 장면도 버리지 않고 "AI 가 지금 읽는 것" 을 보여 줍니다.

## 왜 미리 해 두나

| 단계 | 실제 걸리는 시간 | 데모에서 |
| --- | --- | --- |
| 레포 분석(수집·묶기) | 팀 저장소 첫 수집 약 80초 + 묶기 | **작은 레포로 라이브 시작** → 진행 줄만 보여 주고, 결과는 미리 분석한 레포로 넘어감 |
| 카드 초안 | 카드 한 장 약 13초(여러 장이면 더) | 라이브로 1장 — 칸이 채워지는 장면 |
| 매칭 판단(전체 추천) | 회사 여러 곳 AI 판단 | **미리 계산** 해 둔 결과 |
| 자소서 카드 고르기·초안 | 문항마다 수십 초 | 라이브로 시작해 쓰는 장면만 → 미리 만든 자소서로 넘어감 |
| 첨삭 | 문항당 21~35초 | 미리 받아 둔 결과를 엶 |

## 장면 (4분)

시간 옆 ★ 는 꼭 보여 줄 장면, ☆ 는 시간이 모자라면 건너뛰는 장면입니다.

### 1. 홈 — 0:00~0:15 ☆

- 홈의 활동 잔디·공고 마감 캘린더·나에게 매칭된 공고를 한 번 훑습니다.
- **말:** "Gitory 는 내 GitHub 기록과 채용 공고를 한 화면에 모읍니다. 처음부터 보여 드리겠습니다."

### 2. 레포 고르기 → AI 가 읽는 장면 — 0:15~0:50 ★

1. 레포 목록에서 **레포 B** 를 고릅니다.
2. 분석 전 안내 — 읽는 것(내 커밋·PR·리뷰)과 안 읽는 것(남의 커밋·lockfile·비공개 저장소), 예상 시간.
3. 분석 시작 → 진행 화면에 **AI 가 지금 읽는 PR·커밋과 판단한 줄** 이 올라옵니다.
- **말:** "AI 가 남의 커밋은 내용을 받지도 않고, 내 커밋만 읽습니다. 지금 어떤 PR 을 읽고 무엇을 묶었는지가 그대로 보입니다."
- 진행 줄이 몇 개 올라오면 **레포 A 로 넘어갑니다**(레포 B 는 뒤에서 돌게 둡니다).

### 3. 경험 후보 → 카드 초안 — 0:50~1:35 ★

1. 레포 A 의 후보 보드 — 추천 5개가 먼저 보이고, 후보마다 **왜 추천했는지 한 줄** 과 묶인 커밋.
2. 후보 하나를 골라 카드 만들기 → **STAR 칸이 AI 가 쓰는 순서대로 채워지는** 화면.
3. 다 쓴 카드에서 칸 아래 **근거 커밋**(메시지·시각·diff 한 줄 요약)을 엽니다.
- **말:** "문장마다 근거 커밋이 붙습니다. AI 가 근거라고 주장한 커밋이 실제로 있는지는 DB 를 가진 서버가 다시 확인합니다."

### 4. 비어 있는 칸 → 되묻기 — 1:35~2:10 ★

1. 미리 준비한 **한 칸이 빈 카드** 를 엽니다 — "근거를 찾지 못해 비워 두었습니다".
2. 되묻기 시작 → AI 가 **고른 칸과 그 칸을 고른 이유** 를 보여 주며 질문합니다.
3. 짧게 한 번 답합니다(미리 정한 답: 아래 「미리 정한 답」).
4. 칸이 채워지고, 네 칸이 다 차면 카드가 확정됩니다.
- **말:** "비어 있는 칸이 이 서비스의 증거입니다. 채울 수 있는데 안 채운 게 아니라, 근거가 없으면 코드가 지웁니다. 비운 칸은 AI 가 스스로 골라 되묻습니다."

### 5. 레포 폴더 → 맞는 기업 — 2:10~2:25 ☆

- 레포 A 폴더 — 경험 카드 묶음과 **이 레포 카드로 고른 추천 기업 3곳**.
- **말:** "레포가 정리되는 순간, 이 레포 경험과 맞는 기업을 바로 보여 줍니다."

### 6. 공고 매칭 → 모자란 조건 찾기 — 2:25~3:10 ★

1. 공고 페이지 맨 위 **매칭 결과 상자** — 확인한 공고 수, 공고 타일마다 맞은·모자란 조건 이름.
2. 준비한 공고 상세 → **"필수 4개 중 3개"** 와 조건마다 채운 카드.
3. ✕ 조건에서 AI 찾기 → 후보·작성 중 카드·내 커밋 순으로 찾는 과정 → **"이 후보로 카드 만들기"** 같은 제안.
- **말:** "코드가 학력·관심 분야와 기술 겹침으로 먼저 좁히고, AI 는 조건마다 그 조건을 채우는 카드를 고릅니다. 모자란 조건은 AI 가 내 기록에서 다시 찾아 무엇을 하면 되는지 알려 줍니다."

### 7. 공고에서 자소서 — 3:10~3:55 ★

1. 공고 상세에서 자소서 시작 → 문항·지원 이유가 미리 채워진 입력 화면, 강점 칩.
2. 미리 만든 자소서를 엽니다 → 문항마다 고른 카드, 초안.
3. 초안 안 **노란 추론 표시** 문장 하나를 가리킵니다 → 확인·고치기·빼기.
4. 옆 패널 **첨삭** 탭(미리 받은 진단·고쳐 쓰기) 또는 **채우기** 탭(대화로 재료 받기)을 한 번 엽니다.
- **말:** "자소서는 확정한 카드와 공고 조건만 재료로 씁니다. 재료에 없는 해석은 노란색으로 표시해 사용자가 직접 정하게 하고, 재료가 없으면 빈칸을 남깁니다."

### 8. 마무리 — 3:55~4:00

- 레포 B 진행 화면으로 돌아가 후보가 나왔으면 한 번 보여 주고, 아니면 바로 발표로 돌아갑니다.
- **말:** "저장소 하나에서 시작해 지원서까지, 사람은 고르고 확인하고 비어 있는 칸만 답했습니다."
