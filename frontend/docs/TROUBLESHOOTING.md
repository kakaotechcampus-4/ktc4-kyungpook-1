# 프론트엔드 트러블슈팅

## 2026-10-29 — STAR 칸이 다 찬 카드에서 "작성 중"/"확정됨" 글자 배지를 걷어 낸다

카드 타일마다 상태 글자("작성 중"·"확정됨"), 확인 필요, 빈 칸 수, 근거 수가 겹쳐 무엇이 먼저 보여야 하는지 흐릿하다는 팀 의견(10/29)이 있었다. 네 칸이 다 찬 카드는 "더 할 일이 없다"가 기본 상태라 글자 배지가 필요 없고, 눈에 띄어야 할 것은 사람이 손봐야 하는 "확인 필요"다. 그래서 상태 표시를 `components/cards/CardStatusMark` 하나로 모았고, 카드 타일(홈·목록)과 카드 상세 머리글이 같은 규칙을 쓴다.

- 네 칸이 모두 FILLED 이고 확인 필요가 없다 → 글자 배지 없음. 확정 카드는 작은 체크 아이콘(읽어 주는 이름·툴팁 "확정됨", 아이콘 자체는 장식)이 남고, 작성 중 카드는 그 자리에 아무것도 두지 않는다.
- 빈 칸 없이 확인 필요 칸만 있는 작성 중 카드 → "확인 필요" 배지만("작성 중" 글자 없음).
- 빈 칸이 하나라도 있다 → 예전 그대로("작성 중"/"확정됨", 작성 중 타일은 확인 필요 함께, 빈 칸 수).
- 카드 상세는 칸별 상태 표를 받지 않으므로 요약의 `star` 와 같은 기준으로 현재 버전 글(공백뿐이면 EMPTY)과 `lowConfidenceFields` 에서 만든다(`cardStarStates`).
- 확인 필요는 원래 작성 중 카드의 신호다(목록의 "보완 필요" 탭, 홈 카드 모두 확정 카드는 제외). 시드의 확정 카드(card_05)처럼 확인 필요 표시가 남은 확정 카드는 "확인 필요"를 새로 띄우지 않고 체크 아이콘으로 둔다. 팀이 확정 카드에도 보이길 원하면 `CardStatusMark` 의 `review` 한 줄만 바꾸면 된다.

바꾸지 않은 것: 목록 필터 탭(전체/작성 중/확정됨/보완 필요)의 이름·개수·거르는 기준(`status`·`star` 로 센다), 확정 직후 배너의 "확정됨", 편집 중 머리글의 "편집 중", 사이드바 최근 카드의 점. **카드 상세의 "확정" 버튼과 하단 안내는 그대로 둔다.** 확정 여부는 공고 매칭에 쓰이는 카드(CONFIRMED)만 가르는 값이라, 글자 배지가 없어져도 작성 중 카드에서 확정으로 가는 길이 눈에 띄어야 한다. 칸이 다 찬 작성 중 카드는 타일에서 아무 표시가 없으므로 "확정만 남았다"는 단서가 약해지는 점은 열린 제품 질문이다. 배지가 없는 타일도 아래 줄 높이(24px)를 유지해 같은 줄 카드끼리 STAR 칸 위치가 어긋나지 않게 했다.

## 2026-10-20 — 모바일 공통 푸터가 마지막 콘텐츠를 8px 가림

모바일 `.main`은 `--main-pb: 24px`를 설정하는데 `.main--footer`는 실제 padding만 0으로 덮었다. StickyFooter가 같은 변수로 음수 하단 margin을 사용하므로 16px 본문 gap보다 8px 더 당겨졌다. #328의 카드 탐색 여백 보정은 해당 화면만 해결해 레포/후보/직접 작성/수정/가리기에는 문제가 남았다. 공통 `.main--footer`에서 변수도 0으로 맞추고 카드별 보정을 제거한다. PC 규칙은 유지하며 마지막 박스 전체와 행동 줄 사이 간격을 측정한다. 버튼 중심만 검사하면 테두리가 가리는 회귀를 놓칠 수 있다.

공통 푸터 수정과 함께 320px 레포 문맥의 행동 버튼이 축소되지 않게 하고, 가리기 프리셋은 단어를 쪼개지 않고 버튼 단위로 줄바꿈한다. [계획·검증 결과·이미지](2026-10-20-MOBILE_FOOTER.md)를 참고한다.

## 2026-10-18 — 멘토 리뷰의 사용성 지적 세 가지

분석이 오래 걸리면 화면에는 "진행 중"만 있어 멈춘 것인지 알 수 없었다. 멘토는 가짜로라도 진행률을 보여 주자고 했지만, 모르는 총량의 분모를 지어내지 않는다는 기존 원칙(단계별 done/total 은 서버 값 그대로)을 지켰다. 대신 늘 사실인 신호 둘을 보인다: 시작한 지 얼마나 됐는지, 서버에 마지막으로 확인한 지 얼마나 됐는지. 둘째 값은 서버가 적은 시각이 아니라 마지막으로 상태를 받아 온 시각(`dataUpdatedAt`)이라 서버·브라우저 시계가 어긋나도 맞는다. 진행 막대는 값(너비)은 그대로 두고 빛만 흘려 보내며(`prefers-reduced-motion` 에서는 끈다), 지금 읽는 단계에만 돌아가는 표시를 둔다. 매초 바뀌는 글이라 낭독 영역으로 만들지 않았다. 카드 초안 생성 화면도 같은 컴포넌트(`JobLiveness`)를 쓴다.

실패 화면에 서버가 다시 시도를 열지 않은 경우에도 "다시 시도 — 이 작업은 다시 시도할 수 없어요"와 비활성 버튼이 있어 눌러 볼 수 있는 것처럼 보였다. `retryable` 이 true 이거나 요청 한도로 기다리는 중일 때만 그 줄(과 부분 결과의 "이어 읽기")을 두고, 아니면 할 수 있는 일(다른 저장소, 직접 쓰기)만 남긴다. 이전 테스트가 "비활성 버튼이 있다"를 확인하고 있어 새 동작으로 바꿨다.

후보 보드의 "사용됨 숨기기/보이기"는 상태에 따라 글자가 뒤바뀌는 텍스트 버튼이라 무엇을 켜고 끄는지 알 수 없었다. 이미 카드로 만든 후보는 다시 고를 수 없으니 기본 목록에서 빼고, 목록 맨 아래에 "이미 카드로 만든 후보 N개 · 보기" 행을 두었다(0개면 행 자체가 없다). 처음에는 `details` 구역으로 따로 뺐다가 "후보는 하나의 묶음 목록"이라는 반응형 검사(`.record-list` 1개)에 걸려, 같은 목록의 마지막 행으로 바꿨다. 행 스타일이 `.record-list` 의 직접 자식에 의존하기 때문에 펼친 사용됨 행도 같은 목록의 자식으로 둔다.

## 2026-10-14 — 개수를 못 센 레포의 0 과 수집 상한

백엔드는 기여 개수를 아직 못 센 저장소를 개수 0 으로 내려주고 `countedAt` 을 null 로 둔다. 프론트 스키마에는 이 필드가 없어 버려졌고, 화면은 0 을 실제 값으로 읽어 "내 기여 0%" 경고와 "PR 0건" 배지를 띄웠다. `countedAt === null` 일 때만 "세는 중"을 보이고(`lib/repoCounts`), 레포 목록·읽기 전 안내·홈 제안·설정 수집 이력·분석 진행 문구와 PR 유무 필터에서 0 을 쓰지 않는다. 필드가 생략된 응답은 센 것으로 본다 — null 만이 못 셌다는 신호다.

수집 상한에 걸린 분석은 이유 없이 `partial: true` 만 와서 "일부 기록만 분석했어요"로 보였다. `GITHUB_RATE_LIMITED` 부분 결과와 같은 모양으로 `errorCode: COLLECTION_CAPPED` 를 받을 준비를 했다. 새 코드를 열거형에 넣자 문구 표(`Record<JobErrorCode, string>`)가 컴파일 단계에서 빠진 항목을 알려 줬다. 상한은 기다려도 풀리지 않는다고 보고 서버가 `retryable: true` 를 줄 때만 "이어 읽기"를 보인다.

## 2026-10-13 — 선택 조작·정렬·날짜 회귀

후보 헤더의 배지·제목·버튼을 하나의 flex 줄에서 처리해 체크 중심과 제목이 13px 어긋났다. 44px Check/제목 행과 별도 메타 줄을 사용한다. 펼친 커밋의 배경/문장을 누르면 부모 클릭 핸들러까지 올라가 후보가 선택됐다. 상세 영역을 선택 핸들러에서 제외하고 커밋 포함·추천·사용됨 상태를 브라우저 검사로 유지한다.

카드 footer의 auto margin은 STAR 아래에 빈 공간을 만들어 긴 제목 카드만 STAR가 26px 내려갔다. auto margin을 STAR 위로 옮기며 제목을 생략하지 않는다. 레포 단계의 인라인 gap/가로 스크롤은 320px에서 마지막 라벨을 잘랐다. 페이지에만 3열 grid를 적용하고 모달 레일은 유지한다. 근거 링크는 44px 조작과 긴 SHA/설명 줄바꿈을 사용한다.

기존 카드 정렬 검사에서 새 수정이 시드보다 과거가 됐다. 시드는 실제 날짜로 생성되는데 가짜 시계를 2026-10-12에 고정했기 때문이다. 모듈 로드 후 시계로 정렬 검사를 고정하며 생산 코드의 순서 규칙은 수정하지 않는다. TypeScript의 Node DOM 설정도 넓히지 않고 HTMLCollection은 Array.from으로 변환한다. [점검·검증 범위](2026-10-13-SELECTION_UI_POLISH.md)를 참고한다.

## 2026-10-12 — 직접 작성 재시도와 근거 캐시

첫 POST 응답이 유실되어 재전송하면 서버는 처음 만든 카드의 현재 상태를 돌려준다. 요청 제목으로 다시 PATCH하거나 현재 화면 전체를 서버 글로 덮으면 메타데이터 계약 위반 또는 입력 유실이 발생한다. 진입당 UUID 하나를 유지하고 서버 메타데이터·수정한 STAR·수정하지 않은 서버 STAR를 구분해 반영한다. autosave가 실제로 확인한 snapshot을 받아 후속 저장에서 이전 메타데이터를 재전송하지 않게 한다. 확정 replay는 입력을 남기며 저장을 막는다.

임시 저장 ACK에는 출처/근거가 없다. 글이 같아도 새 버전에서는 출처가 달라질 수 있으므로 모든 미확인 근거를 숨기고 상세 GET으로 복구한다. 같은 버전에서는 바뀐 칸만 숨긴다. 오래된 Mock 스냅샷의 과거 글이 현재 글과 같다고 현재 인터뷰 근거를 복사하지 않는다. 서버가 내려준 목록 STAR 상태와 카드 수정 시각도 ACK로 추정하지 않는다.

요청 경계에서 네 키와 입력 길이를 검증한다. 렌더 도중 스키마 검증으로 기존 긴 글을 자르거나 화면을 깨뜨리지 않는다. 의미 있는 공백은 보존하고 공백만 있는 글은 null로 정규화한다. 기존 테스트의 부분 PATCH·요청과 다른 ACK·첫 응답 임의 메타데이터는 실제 계약에 맞는 fixture로 갱신하며 저장 실패/취소/이탈 검사는 유지한다.

편집 후 취소·뒤로가기·이탈 확인으로 돌아오면 CardPage의 상세 observer가 유지된다. ACK 캐시를 stale로 만드는 것만으로는 GET이 발생하지 않아 근거가 계속 숨겨졌다. 같은 카드의 edit→읽기 전환에서 metadata-pending일 때 한 번 비동기 갱신하고, 기존 저장 후 닫기 GET은 cancelRefetch:false로 합류한다. 실패해도 글과 이동을 유지하며 변경 없는 취소에는 조회·저장을 추가하지 않는다. 화면 전환 성공/실패 8개와 확정 안내의 현재 버전 일치 검사를 추가했다.

여러 Node/브라우저 검사를 동시에 실행한 로컬 재검증에서 시간 초과와 실행 지연이 발생했다. 시간 초과를 통과로 기록하지 않고 검사 작업 수를 제한하고 환경별 검사를 순서대로 다시 수행한다. 애플리케이션의 타임아웃·재시도 정책을 느슨하게 바꾸지 않는다.

## 2026-10-07 — 접힌 메뉴의 가로 스크롤과 대기 단계가 흐림

64px rail에서 좌우 padding 12px/경계를 빼면 39px만 남는데 펼치기 버튼은 44px이었다. scrollWidth 66px/clientWidth 63px를 재현했다. 데스크톱 rail padding을 4px로 줄이고 44px 조작 영역을 유지한다. 사이드바는 세로로만 스크롤하며 넘친 버튼을 잘라 숨기는 방식으로 처리하지 않는다. 짧은 창에서 휠과 키보드로 메뉴에 도달하는 검사와 실제 포커스 경계 검사를 유지한다.

768–820px에서는 초기 CSS의 row 방향이 남아 태블릿에서 scrollWidth 306px/clientWidth 76px가 됐다. 최종 tablet 계층에서 sidebar/menu-group을 column으로 명시한다. 가로 숨김과 함께 적용하지 않으면 메뉴가 잘린다. 768/800/820/1024px의 모든 메뉴 경계와 실제 설정 이동을 검사한다.

표준 scrollbar-width/color의 non-auto 값은 Chromium의 WebKit 부품 스타일보다 우선했다. 두 방식을 feature gate로 분리해 투명 트랙·6px 둥근 손잡이·hover·화살표 제거를 적용한다. Firefox는 표준 thin 표현을, 고대비 모드는 native 색을 유지한다. 대기 단계는 강한 경계와 채움 색을 사용하며 완료 단계의 추가 테두리는 투명으로 유지한다. [검증과 브라우저 문서](2026-10-07-SCROLLBAR_STEP_CONTRAST.md)를 참고한다.

## 2026-10-07 — 왼쪽 메뉴와 최근 카드 글자가 연하게 보임

메뉴/그룹 제목/최근 카드가 서로 다른 보조 녹색을 참조해 라이트에서 로고보다 약하게 보였다. 사이드바 전용 `--sidebar-text`를 정의하고 해당 요소의 기존 CSS 규칙을 함께 변경한다. 라이트는 `--ink-900`, 다크는 `--text-primary`를 사용한다. 선택 아이콘은 기존 `--nav-active-text`로 명시해 글자색 변경이 아이콘의 강조색까지 바꾸지 않도록 한다. 본문·모바일 메뉴·굵기·간격을 유지한다. 두 테마의 실제 대비 최소 13.52:1, hover/접힘/모바일과 기존 정적 브라우저 검사 6개를 확인했다.

## 2026-10-06 — 검색 겹테두리·선택 메뉴·STAR 들여쓰기

검색 wrapper와 입력의 outline·shadow가 함께 적용돼 포커스 테두리가 겹쳤다. SearchField 하나가 focus-within 경계를 담당하고 내부 input의 중복 경계를 없앴다. 지우기와 Escape는 입력 포커스를 유지하며, 한글 조합 중 Escape는 원문을 지우거나 조합 취소를 막지 않는다. 실패를 재현한 IME 검사와 실제 지우기·포커스 검사를 유지한다.

정렬/필터는 chip의 999px 곡률과 OS 기본 select 메뉴를 사용했다. Radix Select의 controlled wrapper로 통일하고 기존 enum·레포 ID·빈 문자열을 호출자에 그대로 전달한다. 키보드·문자 탐색·닫힌 뒤 포커스 복귀·모바일 긴 목록 스크롤을 검사한다. 정적 빌드의 외부 클릭 검사는 메뉴가 보이는 즉시 클릭해 Radix가 예약한 document listener보다 앞서 실행됐다. 닫힘·trigger/option 포커스를 확인하고 다음 animation frame에서 외부 클릭한다. 같은 정적 검사가 반복 10회 통과했으며 임의 시간 대기·assert 제거·검사 재시도로 숨기지 않는다.

PC 홈의 prompt에는 이어쓰기와 다른 16px padding·620px 최대 폭이 남아 있었다. 동일한 부모 경계를 사용한다. STAR 본문은 아이콘 옆 grow 안에 있어 입력·문장·근거가 모두 들여써졌다. StarRow/StarEditorField가 제목 행과 전체 폭 본문을 분리한다. 원문·줄바꿈·ref·저장 대기열·이탈 보호는 유지한다.

body 자간만 바꾸면 브라우저 기본 input/button 자간은 normal로 남는다. 공통 control에도 tracking을 명시하고 실제 computed style로 -0.03em을 확인한다. 설정·오류·모바일 안내 제목에 남은 700/800 예외도 공통 600으로 맞췄다. 자세한 화면 점검과 회귀 범위는 [UI 검증 기록](2026-10-06-UI_CONSISTENCY.md)을 참고한다.

배포 전 새 설치에서는 source-map-js 1.2.1의 보안 공지가 audit에 반영됐다. 개발 전이 패키지 하나만 1.2.2로 패치하고 나머지 설치 버전은 유지한다. npm 명령은 package.json이 있는 frontend 폴더에서 수행하며 프로젝트 경로를 확인한다. 실제 설치·타입·단위·정적 빌드를 재검증한다.

## 2026-10-04 — Node 24 Checks와 테스트 타입 환경

기존 Vitest/jsdom의 AbortSignal과 Node 24의 Request 타입이 달라 라우터 이동 검사 6개가 실패했다. 공식 호환성 수정이 포함된 Vitest 4.1.11과 실제 요청/DOM 취소 회귀 검사를 적용한다. Node 22·24 전체 단위 108개가 각각 통과했다. 애플리케이션에 임의 Request 구현을 추가하지 않는다.

도구 업데이트 뒤 파일을 읽는 공유 계약 검사의 Node 타입이 암묵적으로 포함되지 않아 빌드가 실패했다. 테스트 전용 tsconfig가 앱 설정을 재사용하며 테스트에 Node 타입을 명시하고, tsc 빌드 references에서 테스트도 검사한다. 브라우저 앱에 Node 타입을 넓히지 않는다. 설치 중 npm 10 peer 해석 오류와 포트 충돌 재현·처리도 [상세 기록](2026-10-04-NODE24_CHECKS.md)에 남겼다.

## 2026-10-04 — 개발 StrictMode에서 저장 캐시가 옛 값으로 남음

개인 CI의 개발 E2E는 제목·기간 수정 후 이전 기간을 표시했고, 팀의 정적 E2E는 통과했다. NewCardPage의 mountedRef는 효과 cleanup에서 false로 바뀌지만 setup에서 true로 복원되지 않았다. 개발 StrictMode의 setup→cleanup→setup 뒤에는 저장 요청이 성공해도 캐시 갱신과 무효화를 건너뛰었다. 서버 저장 성공 표시와 상세의 옛 캐시가 어긋나는 문제였다.

CardModes의 본문 저장도 같은 패턴이라 함께 수정했다. 실제 화면을 떠난 뒤 늦은 저장 응답을 막는 기존 보호는 유지하고, setup마다 true를 복원한다. 임의 대기나 테스트 재시도로 숨기지 않는다. 기존 저장·이탈 검사 6개를 실제 앱처럼 StrictMode로 감싸 3개 실패를 재현했고 수정 후 모두 통과했다. 개발 신규 E2E 5개도 같은 실패를 재현한 뒤 전부 통과했다.

## 2026-10-03 — 카드 부가 정보·기간·복사 실패 복구

목록 스키마의 MANUAL/0 기본값이 API에서 생략한 출처와 근거 수를 사실처럼 표시했다. 부가 필드를 nullish로 보존하고 제공된 정보만 표시한다. 현재 버전의 서버 STAR 상태는 유지하며, 필수 응답만 주는 minimal-summary 시나리오로 검증한다.

기간은 자유 문자열인데 목록의 ym()이 날짜 변환 실패 시 빈 문자열을 반환했다. `2024년 상반기`와 `2024.04 ~ 2024.06`을 실패 검사로 재현한 뒤 ISO 형태만 날짜로 표시하고 나머지는 원문을 유지한다.

clipboard 실패 뒤 execCommand fallback까지 예외가 발생하면 복사 창이 잠기고 임시 textarea가 남았다. fallback은 false를 반환하며 finally에서 textarea를 제거한다. 공통 useActionGate가 finally에서 잠금을 풀고 즉시 중복 실행을 막는다. 창의 미리보기·재시도·ESC 닫기까지 단위 검사한다.

새 단위 검사의 getByRole에 Playwright 전용 exact 옵션을 넣으면 TypeScript 빌드가 실패한다. Testing Library에서는 문자열 name 자체가 정확히 일치하므로 옵션을 제거했다. toHaveValue는 부분 문자열 matcher를 받지 않아 textarea.value로 원문 유지 여부를 검사한다.

메타데이터 저장은 기존 STAR 직렬 저장과 분리하되 첫 저장 후 같은 저장 대기열에서 처리한다. 미지의 기간을 제목 수정으로 지우지 않고, 성공한 메타데이터만 상세·목록 캐시에 반영한다. 실제 미구현 API는 기본 비활성 기능 설정으로 차단한다.

## 2026-10-03 — 확정 응답 이후 조회 실패와 모달 재열기

확정 POST가 성공해도 뒤따르는 상세 GET이 실패하면 `invalidateQueries`가 오류를 삼켜 mutation은 성공하고 캐시에는 DRAFT가 남을 수 있다. 성공 응답의 status/versionNo를 상세·목록 캐시에 먼저 반영한 뒤 메타데이터를 재조회한다. 이전 상세 요청은 취소해 늦은 DRAFT 응답이 확정 상태를 덮지 않게 한다. 확인되지 않은 날짜나 내용을 만들지 않는다.

요청 중 모달을 닫고 다시 열면 새 mutation 인스턴스로 확정을 한 번 더 누를 수 있었다. 요청 중 취소·ESC·배경 닫기를 막는다. 두 문제를 실패하는 단위 검사로 재현한 뒤 수정했다.

## 2026-10-03 — 조회 실패·배치·버튼 이름의 혼동

카드 목록의 `?? 0`은 읽기 실패도 카드 0건처럼 표시했다. 미확인 숫자는 `—`, 실제 빈 응답은 0으로 구분한다. 기존 데이터가 있으면 마지막 확인된 숫자를 유지한다. 읽기 오류에서는 입력 보존 문구를 쓰지 않고 재조회를 안내한다.

모바일 예시의 결과 카드와 설정의 테마가 긴 부가 내용 뒤로 밀렸다. 예시는 요약/전체 보기, 설정 보관 정보는 native details로 분리한다. 이어쓰기 우선 홈과 실제 동작을 나타내는 버튼 이름을 검증한다. 기존 테스트의 이전 홈 제목·시작 버튼 기대값은 새 구성으로 갱신했다.

## 2026-10-01 — 배경의 노란 기운과 공유 토큰의 다크 영향

넓은 크림 배경과 노란 기가 있는 선택 영역이 화면 전체를 누렇게 보이게 했다. 옅은 세이지 배경·흰 카드·한 단계 진한 선택 표면·짙은 행동색으로 색 배치를 조정했다. 텍스트/경계/근거의 보조 색도 같은 녹색 계열로 맞춘다.

이번 변경에서는 2026-09-10 기준으로 타입 검사와 프로덕션 빌드가 완료됐고, Vitest 12개와 개발·정적 빌드 Playwright E2E 각각 18개가 통과했다. PC 랜딩에서는 헤더와 본문의 좌우 경계, 로고와 상단 CTA 높이의 차이를 각각 1px 이하로 검사한다.

## 백엔드·AI 계약 연동에서 걸린 것들 (2026-09)

### 목이 `fetch` 를 가로채서 Playwright 의 `waitForResponse` 가 안 잡힌다
데모 모드는 `window.fetch` 자체를 갈아 끼우므로 네트워크 요청이 아예 발생하지 않는다.
"서버에 저장됐는지"를 네트워크 이벤트로 확인하려던 테스트가 15초 타임아웃으로 죽었다.
→ 화면을 떠났다 돌아와도 값이 남아 있는지로 확인한다. 브라우저 저장이면 통과할 수 없는 조건이라 증명력은 같다.

### E2E 헬퍼가 매 페이지 로드마다 목 DB 를 지워 "새로고침 복구"를 검증할 수 없었다
`addInitScript` 가 로드마다 도는 탓에, 새로고침하면 복구할 상태 자체가 사라졌다.
→ `gitory.e2e.seeded` 표시를 두고 **테스트당 첫 로드에서만** 시드로 되돌린다.
브라우저 컨텍스트가 테스트마다 새로 뜨므로 표시도 같이 사라져, 테스트 간 격리는 그대로다.

### 목이 Job 을 메모리에만 들고 있었다
`snapshot()` 이 `Map(jobs)` 을 뺐기 때문에 새로고침하면 진행 중이던 분석이 통째로 사라졌다.
실서버에서는 Job 이 서버에 있으니 이건 목이 실제와 다르게 구는 자리였다.
→ 스냅샷에 `jobs` 와 `idem` 을 같이 담는다. 복구 화면을 데모에서도 그대로 확인할 수 있다.

### `CardSummary` 에 프론트 전용 필드가 남아 있었다
백엔드가 확정한 카드 목록 응답에는 `evidenceCount` 같은 필드가 없다. 필수로 두면 붙이는 날 첫 호출에서 `ContractError` 가 난다.
→ 당시에는 부가 필드를 zod `default()`로 내렸다. 2026-10-03에는 이 기본값이 출처/0건을 만들어내는 문제를 발견해 `nullish()`로 변경하고 모름과 실제 0을 구분한다.


### 2026-10-13 공용 커밋 행 변경의 모달 영향

.commit-row는 펼친 커밋뿐 아니라 직접 추가 검색 결과 버튼에서도 쓰였다. 모든 행을 체크/본문/링크 3열로 바꾸면 검색 결과의 배지가 잘린다. --cluster/--picker modifier로 배치를 명시한다. 검색 목록의 max-height와 flex-shrink 조합도 행을 내용보다 작게 만들므로 picker 행은 수축하지 않고 세로 스크롤을 사용한다. 공용 스타일 변경 때 grep으로 모든 소비자를 확인하고 화면·모달 상태를 함께 검증한다.
