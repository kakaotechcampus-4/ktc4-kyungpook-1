# 카드 작업·활용 흐름 개선 (2026-10-03)

## 승인된 범위
1. 카드 목록의 부가 정보가 생략/null이면 출처·근거 개수를 만들지 않는다. 실제 0과 모름을 구분한다.
2. 서버 active Job을 홈에서 확인하고 전용 작업 상태 화면으로 이동한다. 유형·대상 연결은 응답으로 판단하고 브라우저에 Job ID를 저장하지 않는다.
3. 현재 버전의 서버 STAR 상태를 이용해 빈칸/확인 필요 필터를 제공한다.
4. 본문만/STAR 형식/근거 포함 복사를 제공한다. 마스킹을 적용하고 사용자 문장을 윤문하지 않는다.
5. DRAFT의 제목·기간 수정 UI를 제공한다. 기존 STAR 저장·버전과 분리하며 레포 재지정은 포함하지 않는다.

## 최신 코드와 서버 확인
develop d6d07a6은 현재 브랜치에 포함돼 있다. #61·#76의 저장/확정/조회 보호를 유지한다. Backend ActiveJobResponse는 type을 이미 반환한다. 제목·기간을 수정하는 API는 현재 프론트 계약/백엔드 코드에서 확인되지 않아 아래 제안이 팀 확인 대상이다.

## 메타데이터 API 제안 (미확정)
`PATCH /api/cards/{cardId}/metadata`, body `{ title?: string, period?: string }`, response `{ data: { cardId, title, period: string | null, updatedAt }, error: null }`.
전달한 필드만 수정한다. 제목은 공백만 있는 값을 거절하고 period의 빈 문자열은 기간 삭제를 뜻한다. 소유권을 검사하고 DRAFT에서만 변경한다. STAR 본문·출처·버전은 변경하지 않는다. 실제 저장값을 반환한다. 상세 GET에도 실제 period 반환을 요청한다. 기존 기간을 모르는 채 제목만 수정할 때 기간을 지우지 않게 한다.

Mock에는 제안 API를 구현해 전체 화면을 검증한다. 실제 API 모드에서는 백엔드 계약·구현 확인 후 `VITE_CARD_METADATA_ENABLED=true`로 연결한다. 기본값에서는 미지원 경로를 호출하지 않는다. 이 값은 기능 설정이며 환경 파일이나 인증 정보를 커밋하지 않는다.

## 구현·검증 순서
1. 부가 정보 스키마·표시 헬퍼·minimal-summary Mock 시나리오를 추가하고 최소 응답/명시적 0 검사를 먼저 실패시킨다.
2. 홈 active Job 목록과 작업 상태 라우트를 추가한다. 기존 쿼리 키/폴링·완료 토스트를 공유하고 알 수 없는 유형을 ANALYZE로 추정하지 않는다.
3. 카드 보완 필터와 복사 형식을 추가한다. 필터 상태와 API enum, 사용자 문장·마스킹을 유지한다.
4. 메타데이터 endpoint/응답 스키마/캐시 헬퍼와 UI를 분리한다. 저장 실패 시 입력 유지, 확정 카드 차단, 첫 저장 후 수정·새로고침 복구를 검증한다.
5. 타입·단위·정적 E2E·두 테마 모바일/PC 시각 확인·별도 코드 리뷰를 마친 뒤 문서·README·두 PR·배포를 갱신한다.

## 협업 전달
백엔드 확인 요청을 [#61 댓글](https://github.com/kakaotechcampus-4/ktc4-kyungpook-1/pull/61#issuecomment-5969111285)에 남겼다. DRAFT 제목·기간 부분 수정, 상세 period, 부가 정보의 누락/0 처리 기준을 요청한다. 사용자에게 댓글 링크와 톡방 전달 문구를 제공한다. 계약 승인 전 실제 메타데이터 API 지원을 완료한 것으로 표시하지 않는다.

## 구현 결과
- AppShell이 활성 Job 폴링을 공유한다. 홈과 전용 상태 페이지는 응답의 type·steps·현재 state를 사용하고, 완료 결과·부분 완료·취소·실패의 대상 링크를 구분한다. 화면이 Job을 재실행하지 않는다.
- 보완 필터는 서버 현재 버전의 EMPTY/NEEDS_REVIEW를 검색·작성 상태와 조합한다. 필터 결과 0건과 실제 목록 0건을 구분하고 필터 초기화를 제공한다.
- 복사 미리보기는 본문/STAR/근거를 선택하며 사용자 원문·줄바꿈·마스킹을 유지한다. 복사 실패해도 미리보기·재시도·닫기가 동작한다.
- 제목·기간 부분 수정은 별도 endpoint/schema/cache helper로 분리했다. 모르는 기간을 제목 수정으로 지우지 않으며 확정 카드 수정과 실제 미지원 호출을 차단한다. 첫 저장 후에도 제목·기간 수정은 기존 저장 대기열에서 직렬 처리된다.
- 기간 자유 문자열이 목록에서 사라지는 리뷰 지적을 수정했다. 날짜 형태 외에는 원문으로 표시한다. 이전 확정 캐시·이탈 보호·후보 보존 로직을 유지한다.

## 검증
Node 22.17.0에서 타입·프로덕션 빌드, 단위 106개, 정적 E2E 60개가 통과했다. 신규 흐름 E2E 5개는 구현 전 실패를 확인했고 구현 후 통과했다. 최소/null 응답, 명시적 0, 자유 기간, 원문·마스킹, clipboard 실패 복구, 메타데이터 부분 저장/확정 차단/기간 삭제 및 실제 기능 게이트를 검사했다. 저장·확정·인터뷰·멱등키의 기존 회귀 검사도 통과했다.

라이트/다크 × 320/390/1440px에서 홈 활성 작업·작업 상태·전체/보완/최소 응답 목록·복사·제목/기간 창을 42장 촬영했다. pageerror 0건, 가로 넘침과 모달 하단 행동 잘림 0건이며 주요 화면을 직접 확인했다. 시각 확인 후 작업 단계 간격도 공통 간격 토큰으로 넓혔다. 별도 코드 리뷰에서 기간 표시·복사 실패 두 지적을 수정하고 재검토에서 차단 사항이 없음을 확인했다.

개인 CI의 개발 E2E에서 59/60이 통과하고 제목·기간 검사만 실패했다. StrictMode 효과 재실행으로 mountedRef가 false에 남아 성공 응답의 캐시를 갱신하지 못하는 원인을 로컬 개발 E2E와 StrictMode 단위 검사 3건으로 재현했다. 직접 작성·본문 편집 두 경로를 최소 수정해 저장 검사 6개·개발 신규 E2E 5개가 모두 통과했다. 이 수정은 서버 계약이나 실제 이탈 후 응답 보호를 바꾸지 않는다.

당시 선택 Node 24의 기존 AbortSignal realm 문제는 이 기능 범위에서 전역 polyfill로 바꾸지 않았다. 2026-10-04 후속 작업에서 공식 테스트 도구 호환성 수정으로 해결했으며 [Checks 수정 기록](2026-10-04-NODE24_CHECKS.md)을 참고한다. 팀 표준은 기존 Node 22다. 실제 백엔드 API 연결·소유권 서버 검사는 서버 구현과 계약 합의 이후 별도 확인 대상이다. 배포 체험 모드는 Mock이며 실제 계정 데이터를 변경하지 않는다.
