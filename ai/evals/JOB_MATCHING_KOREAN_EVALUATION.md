# 기업·직무 매칭 임베딩 한국어 평가

## 목적

매칭은 확정 카드의 한국어 문장과 공고 조건 문장의 임베딩 거리로 근거를 찾는다.
기존 평가(`JOB_MATCHING_EVALUATION.md`)는 질의에 영어 기술어가 섞여 있어, 영어 기술어가 없는
한국어 문장과 영어로만 쓴 공고(한국 근무 공고에도 있다)에서 어떻게 되는지 알 수 없었다.
이 평가는 작은 ONNX 모델 3개를 같은 데이터로 견주고, 모델마다 맞는 거리 상한을 찾는다.

## 평가 데이터 (`job_matching_korean_cases.json`)

- 공고 49건 · 조건 문장 712개. Greenhouse 공개 API 에서 2026-10-18 에 받은 공고의 담당업무·자격요건·우대사항
  목록 항목만 썼다. 팀 소개·전형 안내·같은 공고의 상위 직급 반복은 손으로 뺐다.
  - **공고 원문은 저장소에 넣지 않았다.** fixture 에는 공고 식별 정보(회사·공고 번호·제목·직무 분류·언어),
    조건 순서(`index`)·종류(`criterion_type`)와 조건 문장의 SHA-256(`text_sha256`)만 있다.
    해시는 문장을 유니코드 NFC 로 바꾸고 공백 연속을 한 칸으로 줄여 앞뒤를 자른 뒤 UTF-8 로 낸다.
  - 평가 스크립트가 실행할 때 위 공개 API 에서 공고를 받아(회사당 요청 1번, 요청 사이 1초, `User-Agent: Gitory/1.0`)
    조건 문장을 다시 뽑고 해시가 같은 문장만 쓴다. 받은 응답은 `GITORY_EVAL_CACHE_DIR`(기본 `.chroma/postings`,
    git 이 무시하는 폴더)에만 두고, `--cache-only` 를 주면 네트워크 없이 그 파일만 읽는다.
  - 공고는 시간이 지나면 바뀌거나 내려간다. 해시가 맞지 않는 조건은 빼고 그 조건을 가리키는 정답도 뺀다.
    제외한 수는 결과 JSON 의 `hydration` 에 적히고 실행 때 화면에도 나온다(아래 숫자는 2026-10-18 에 받은 공고로 쟀고 제외 0개).
  - 한국어 공고 29건(당근 27 · 퓨리오사AI 2) · 조건 412개
  - 영어 공고 20건(몰로코 10 · 퓨리오사AI 10) · 조건 300개. 한국 근무 16건, 미국 근무 4건(몰로코)
  - 받기 전에 robots.txt 를 확인했다. `boards-api.greenhouse.io` 는 `/embed/` 만 막고, Greenhouse 문서는
    "Job Board data is publicly available" 라고 적는다. 쿠팡(채용 집계 봇을 공고 경로에서 막음)·
    크래프톤(robots.txt 를 읽지 못함)·센드버드(`ai-train=no`)는 넣지 않았다.
- 카드 문장 질의 46개. 한글만 31 · 기술 이름을 한글로 적음(도커·쿠버네티스 등) 5 ·
  영어 기술어 섞임 10. 어느 공고에도 맞지 않아야 하는 질의 2개(게임 레벨 편집기, 동아리 회계)를 넣었다.
- 정답 573쌍(AI 도구로 만든 정답 초안이며 팀원 검토 전이다. 표본 60쌍을 팀원이 검토할 예정이다). 판정 기준은 fixture 의 `relevance_rule` 에 있다.
  세 모델이 언어별로 가깝다고 한 상위 12개와 질의 낱말이 든 조건을 모아(3,456쌍) 판정했고,
  모으지 않은 조건은 오답으로 본다.

## 재는 방법

- 운영처럼 문장 하나마다 가까운 조건 10개(`top_k=10`)를 받고 거리 상한 이하만 남긴다.
- 한국어 공고만 색인(한→한) · 영어 공고만 색인(한→영) · 둘을 함께 색인(운영과 같음) 세 가지를 따로 센다.
- 정밀도 = 남긴 조건 중 정답 비율. 재현율 = 남긴 정답 수 ÷ min(정답 수, 10).
- 거리는 cosine 거리(1 − 코사인 유사도)이고, 모든 조건과 정확히 계산했다(운영 Chroma 는 근사 검색).
- 모델: Chroma 기본 `all-MiniLM-L6-v2`(지금 운영), `paraphrase-multilingual-MiniLM-L12-v2`,
  `multilingual-e5-small`(질의 `query: `, 조건 `passage: ` 접두어). 두 다국어 모델은 허깅페이스의 ONNX 파일을
  커밋 해시로 고정해 쓴다(torch 없음).

paraphrase 와 e5 는 한→한에서 차이가 없고(+0.03 [−0.04, +0.10]), 한→영은 paraphrase 가 높다(+0.11 [+0.01, +0.21]).

### 정답·오답 거리 분포 (함께 색인, 분위수 10/50/90%)

| 모델 | 정답 | 상위 10개 안 오답 | 전체 오답 |
|---|---|---|---|
| all-MiniLM-L6-v2 (지금) | 0.19 / 0.65 / 0.97 | 0.10 / 0.16 / 0.48 | 0.25 / 0.79 / 1.00 |
| paraphrase-multilingual-MiniLM-L12-v2 | 0.37 / 0.62 / 0.84 | 0.38 / 0.49 / 0.62 | 0.60 / 0.77 / 0.93 |
| multilingual-e5-small | 0.13 / 0.17 / 0.22 | 0.12 / 0.14 / 0.16 | 0.15 / 0.19 / 0.24 |

- 지금 모델은 한국어 오답이 정답보다 더 가깝다. 한글 낱말을 거의 모르는 영어 모델이라 한국어 문장끼리는
  뜻과 관계없이 가깝게 나온다. 거리 상한을 어떻게 바꿔도 정답과 오답을 가를 수 없다.
- e5 는 모든 거리가 0.1~0.26 에 몰려 있고, 한→영 정답 거리(중앙값 0.205)가 한→한 상위 10개 안 오답(중앙값 0.136)보다 멀다.
  함께 색인하면 상한 하나로 두 언어를 다 맞출 수 없다(한→한 최적 0.155, 한→영 최적 0.185).
- paraphrase 는 0.35 아래에서 정답이 상위 10개 안 오답보다 많고(40 대 20), 0.35~0.55 에서는 두 쪽이 섞인다(176 대 233).

## 추천

- 모델: `paraphrase-multilingual-MiniLM-L12-v2`. 한→한·한→영 모두 지금 모델보다 순위가 좋고, e5 보다 한→영이
  좋으며, 질의 접두어가 없어 지금 `TextEmbedder` 하나로 바꿀 수 있다.
- 거리 상한: `0.48`(함께 색인 F1 최대 0.33, 홀짝 교차 검증 F1 0.31). 오답을 더 줄이려면 0.45
  (정밀도 0.46 · 재현율 0.23). 지금 값 0.4 는 이 모델에서 너무 좁다(재현율 0.16).
- 메모리: 모델을 올리면 약 0.7GB, 묶음 계산 최대 약 0.83GB 를 쓴다. 지금 모델도 묶음 계산 때 약 0.58GB 까지
  오르므로 실제 차이는 0.25~0.6GB 다. 서버 남은 메모리 2.4GB 안에 들어간다.
- 가장 좋은 모델도 조건 단위 정밀도가 0.42 다. 근거 화면에 오답이 섞일 수 있으므로, 원문 인용을 함께 보여 주는
  지금 설계를 유지한다.

## 한계

- 표본이 작다(질의 46 · 공고 49 · 회사 3, 한국어 공고는 거의 당근). 위 구간처럼 차이의 오차가 크다.
- 질의와 정답을 AI 도구로 만든 초안이고 팀원 검토 전이다. 세 모델의 상위 12개와 낱말 검색으로 모은 후보만 판정해,
  모으지 않은 정답은 빠져 있다. 팀원이 표본 60쌍을 검토한 뒤 아래 표에 일치율을 적는다.
- 조건 문장은 공고 목록 항목을 그대로 썼다. 운영은 Luna 가 뽑은 `text` 를 색인하므로 문장이 조금 다를 수 있다.
- 거리 상한을 같은 데이터에서 골랐다(교차 검증 F1 로 차이를 보였다).
- 문장 하나씩 셌다. 운영은 카드 문장 여러 개로 공고를 찾고 근거 수로 순위를 매긴다.

## 재현

```bash
cd ai
export GITORY_EVAL_MODEL_DIR=.chroma/models   # 다국어 모델을 받는 곳(기본값)
export GITORY_EVAL_CACHE_DIR=.chroma/postings # 받은 공고 응답을 두는 곳(기본값). 처음 실행할 때 3번 받는다
for provider in chroma-default paraphrase-multilingual-MiniLM-L12-v2 multilingual-e5-small; do
  python -m scripts.evaluate_job_matching_korean --provider "$provider" --threads 2 \
    --output "evals/results/job_matching_korean-$provider.json"
done
python -m scripts.evaluate_job_matching --provider paraphrase-multilingual-MiniLM-L12-v2 \
  --maximum-distance 0.48 --top-k 5 --output evals/results/job_matching-paraphrase-0.48.json
```

같은 공고로 다시 재려면 두 번째부터 `--cache-only` 를 붙인다.
결과 JSON 에는 거리 상한 0.05~0.80(0.005 간격)별 정밀도·재현율과 0.01 간격 거리 분포가 들어 있다.
속도·메모리는 모델마다 새 프로세스에서 같은 ONNX 코드로 따로 쟀다(평가 스크립트의 시간은 참고용).
